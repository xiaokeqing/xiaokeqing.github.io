## 一、现状诊断（核实结论）

### 1.1 视觉底子保留，不推倒重来

暖灰玻璃拟态 + 冷白文字 + 青色终端点缀（`tokens.css` 全站唯一令牌源）；
字体零外部依赖（雅黑正文 + 等宽数字）；CRT + 桐莉栖是品牌资产。
**优化对象是"数据呈现"和"信息密度"，不是换皮。**

### 1.2 四个真问题

| # | 问题 | 证据 |
|---|---|---|
| 1 | 图表视觉语言不统一：donut 两版（conic-gradient / SVG path）、地图两种画法、热力条形各写各的 | `xk-viz.js:59-62` vs `xk-bind.js` donutSvg；`xk-geo.js:231-267` vs `xk-bind.js:906-1024` |
| 2 | 密度失控：数据统计 tab 一屏 10 张卡；/ip/ 结果区 3 计数卡+5 表+时间线 | `shell-views.html:159-313`、`ip/list.html` |
| 3 | 文案工程师腔：接口细节糊在标题区；口径声明比数据抢戏 | `shell-views.html:56` |
| 4 | 排版卡下限：说明文字 13px 贴下限；标题阶缺一档；大数字无 tabular-nums | `tokens.css:54` |

### 1.3 数据约束（决定什么图能画）

| 数据 | 有什么 | 能画什么 |
|---|---|---|
| `alerts.js` 5 分钟窗口 `list` | 来源 × 类型 × 严重度 × 条数的**真实联合分布** | **桑基图**（全站唯一能画链路的数据） |

### 升级后长什么样

在作战室「数据统计」tab，7×24 访问柱状卡下方、来源 TOP5 上方，出现一张新卡：

```
┌──────────────────────────────────────────────────────────────┐
│ ● 告警链路 · 来源 → 类型 → 严重度   [/alerts · 5 分钟原始窗口] │
│                                                              │
│  Wazuh 告警 ═══════════════╗                    ┌── 低危(绿) │
│  (147 条)   ║ 青色粗带      ╠══ 其他(145) ══════╪══ 中危(紫) │
│             ║              ║                    └── 高危(黄) │
│             ╠══ 暴力破解(49) ════════════════════ 严重(红)   │
│             ╚══ 扫描(2) / SQL 注入(4)                        │
│  Suricata   ═══ 各类型 ════════════════ 各严重度             │
│  (53 条)     紫色系彩带                                       │
│                                                              │
│  近 5 分钟窗口 200 条告警（服务端聚合为 19 组）；              │
│  线宽 = 该条链路的真实条数                                     │
└──────────────────────────────────────────────────────────────┘
```

- **三列节点**：左=告警来源（Wazuh / Suricata），中=攻击类型（服务端 typeLabel 原值），右=严重度。
- **配色**：来源/类型节点青色 `#7FD4D8`；严重度节点按状态色——严重红 `#E8837B`、高危黄 `#E8B45A`、中危紫 `#B0A0E8`、低危绿 `#6FD3A0`、信息灰。彩带用起止节点渐变、28% 透明度，悬停某条链路时其余变淡（adjacency 高亮）。
- **交互**：悬停彩带出 tooltip「Wazuh 告警 → 暴力破解：49 条」；悬停节点高亮它的全部上下游。
- **下方口径行**：如实写「近 5 分钟窗口 N 条告警（服务端聚合为 M 组）；线宽 = 真实条数」。
- **空态**：窗口 0 条 →「本窗口 0 条告警，链路图为空（真实的 0）」；取不到 → 照抄 XK_FEED_NOTE 原因，不画样例图。
- **慢网态**：不自动加载 1 MB ECharts，显示「慢网模式：图表库约 1 MB，不自动加载。[仍然加载图表]」按钮。

```
└──────────────────────────────────────────────────────────────┘
```

- **布局**：7 行（周一~周日）× N 列（每周一列），GitHub 贡献图样式。方格 12px、间距 3px、圆角 2px。
- **颜色**：5 级青色梯度（沿用现有 `vz-c` 热力色的 l1~l5 分级思路，分位数归一，不是线性）；**没数据的日子是虚线空格**，不是 0 级色——"未生成"和"0 条"是两回事。
- **交互**：hover 出 tooltip（日期、24h 告警、严重/高危、Top 来源）；点击跳到对应日报页。
- **位置**：插在「一句话说明卡」和「逐日明细表」之间。明细表保留——日历给直觉，表格给精确值，互不替代。
- **数据**：`data/rollup/*.json` 构建期 SSR 直出，零运行时请求、零新增端点。
- **窄屏**：日历横向滚动，表格维持现有卡片式降级。

## 四、24h 时序升级（中风险，先核实字段）

- 现在：`#spark24` 是 canvas 单线 + 峰值点（`xk-shell.js:164-218`）。
- 升级后：若 stats24h.trend 含分严重度序列 → **堆叠面积图**，四色（红/黄/紫/绿）从下往上堆，hover 十字线显示该小时各严重度数值；**若只有总数 → 保持单线不动**（拆不出就不编）。
