### 2.4 代码侧参数链（`qwen-plus` 这个字符串从哪来）

`/api/public/ask` 的生成路径：`PublicAskService.ask()` → `OrchestrationService.run(question, List.of(), deadlineMs)` → `MultiAgentCoordinatorImpl`（公开身份走 `runAnalystPublic`）→ `LlmProviderSelector`（`@Primary`）→ `DashScopeLlmProvider.generate()` → Spring AI Alibaba `DashScopeChatModel`。

```java

@Value("${app.llm.cooldown-ms:60000}") private long  cooldownMs;
...

    return DashScopeChatModel.builder()
        .defaultOptions(DashScopeChatOptions.builder()
```

`DEFAULT_MODEL_NAME` 的取值核对：类里只存字段名，字面量 `"qwen-plus"` 出现在依赖 jar
`BOOT-INF/lib/spring-ai-alibaba-dashscope-1.1.0.0-RC2.jar` → `com/alibaba/cloud/ai/dashscope/spec/DashScopeModel$ChatModel.class`；
而启动自检里 `dashscope{model=qwen-plus}` 这一项就是 `LlmSelfCheck` 用 `selector.primary().modelName()` 打印的
（`LlmSelfCheck.java:114`），因此**运行期自检已经把 `DEFAULT_MODEL_NAME → qwen-plus` 钉死**。
默认接入域名（依赖 jar 内常量）：`https://dashscope.aliyuncs.com`。

**两个"模型名"配置项，只有一个管公开问答（很容易踩的坑）：**

```java
// RagService.java:59  —— 这是另一条链路（流式 queryStream，供 /api/chat 等使用）
@Value("${rag.model:qwen3-30b-a3b-thinking-2507}") private String model;
```

- `rag.model`（yml 里被显式设为 `qwen-plus`）**只被 `RagService` 读**；
  `RagService` 走的是 `generation.streamCall(param)` 流式链路。
- **`/api/public/ask` 不经过 `RagService` 的生成**：它的检索在 `MultiAgentCoordinatorImpl.runAnalystPublic()`
  里调 `publicKbService.search()`（`MultiAgentCoordinatorImpl.java:422-426`），
  生成调 `llmProvider.generate()`（`MultiAgentCoordinatorImpl.java:456 / 700`）。
- 所以公开问答的**对话模型由代码常量 `DashScopeChatModel.DEFAULT_MODEL_NAME` 决定**，
  改 `rag.model` **不会**改公开问答的模型（这一点对"升级模型"很关键，见
  [状态-K-模型取证.md](状态-K-模型取证.md) 的升级路线 A）。

重试与并发（三个层次，别混为一谈）：

| 层次 | 值 | 含义 |
|---|---|---|
| Spring AI DashScope SDK retry | `max-attempts=3`，退避 `2000ms ×2`（上限 `10000ms`） | SDK 侧重试 |
| 应用层编排重试 | ANALYST 结论 **最多 2 次尝试**（第 2 次附加"只输出合法 JSON"提示） | schema 校验重试（`MultiAgentCoordinatorImpl.java:698`） |
| 应用层硬超时/熔断 | `app.llm.timeout-ms=15000` + `cooldown-ms=60000` | `Future.get(15s)` 超时即 fail-closed 终止并冷却 60 s |
| 出站并发闸 | `app.outbound.max-inflight-per-dependency=2` | 单依赖最多 2 个在飞 |
| 公开端点闸 | 6 次/分/IP、**同 IP 并发 1**、`deadline-ms=20000` | 匿名成本闸 |

- 无 GPU、无推理进程、无权重文件 ⇒ 当前**没有**任何本地推理。

  都装不下，0.5B 级（约 0.4–0.6 GB）理论上塞得进去，但会与 JVM/隧道抢内存并触发 swap（swap 已用 673 MB），
  质量上也完全不能承担安全研判与 JSON schema 约束。
- 若真要走本地推理，需要：**换机型（≥16 GB 内存或带 GPU）**，或**把推理下沉到另一台机器**
  （本地 vLLM/Ollama 只作为 `base-url` 指向的内网服务）。
