### 1.2 卡点 ①：`python -m http.server` 把 `.mjs` 判成 `text/plain` ⇒ 模块脚本被浏览器拒 ✗

`[已实测]` 按任务要求先起了 `python -m http.server 8010 --bind 127.0.0.1`（在 `_emote-trial\` 下），
首次测量**直接超时 180 s**（界面状态栏**始终为空**、`window.demo` **从未被赋值**），
控制台唯一一条报错就是根因：

```
kind=log text="Failed to load module script: Expected a JavaScript-or-Wasm module script but the server
responded with a MIME type of \"text/plain\". Strict MIME type checking is enforced for module scripts per HTML spec."
url=http://127.0.0.1:8010/demo/app.mjs?v=7     ← 界面一直停在空状态，window.demo 从未被赋值（超时 180 s）
```

`[已实测]` 直接查原因：`python -c "import mimetypes;print(mimetypes.guess_type('a.mjs'))"` ⇒ `(None, None)`
（本机 Python 3.9.13 的 `mimetypes` 不认 `.mjs`，`SimpleHTTPRequestHandler` 回落到 `text/plain`）。

`[已实测]` 解决：`tools/serve.py` = **与 `python -m http.server` 同款** `SimpleHTTPRequestHandler`，
只在 `start` 前补 `mimetypes.add_type("text/javascript", ".mjs")`（另补 `.bin`→`application/octet-stream`），
起在 **8011**。改后同一个 URL 的响应头：

```
HTTP/1.0 200 OK     Server: SimpleHTTP/0.6 Python/3.9.13
Content-type: text/javascript      Content-Length: 7696        ← app.mjs?v=7
Content-type: application/json     Content-Length: 779509      ← c.psb.m.resx.json（穿过 junction ✓）
```

⇒ **这是一条通用经验**：本站若哪天要跑 ES module 页面，`python -m http.server` 在本机 Python 3.9 下会假故障，
症状是"页面全空 + 只有一条 MIME 报错"，不是代码问题 ✓。

### 3.1 视线跟随鼠标/触摸 ★ 值得追

**它做了什么** `[源码]` `app.mjs` L111-125：

```js
canvas.onpointermove = (event) => {
  if (!$("follow").checked) return;
  const rect = canvas.getBoundingClientRect();
  const eyeX = (canvas.width / 2 + player.coord[0]) / canvas.width;                       // 眼睛在画布上的位置
  const eyeY = (canvas.height / 2 + player.coord[1] + metadata.charaProfile.pixelMarker.eye * player.scale) / canvas.height;
  const clamp = (v) => Math.max(-100, Math.min(100, v));
  const x = clamp(((event.clientX - rect.left) / rect.width - eyeX) * 200);               // 指针相对眼睛的偏移 → -100..100
  const y = clamp(((event.clientY - rect.top) / rect.height - eyeY) * 200);
  player.setVariableDiff("gaze", "face_eye_LR", x, 120);     // 120 ms 平滑；★ 走"独立差分通道"
  player.setVariableDiff("gaze", "face_eye_UD", y, 120);
};
```

要点三条：① 基准点是**模型数据里的眼睛锚点**（`charaProfile.pixelMarker.eye = 2.5`），不是画布中心；
② `±200` 的增益 + `clamp ±100` 就是"手感"；③ 用 `setVariableDiff(通道名, 变量, 值, 平滑ms)`
把视线与表情时间线**解耦**（`app.mjs` L118 注释原文："独立差分通道，避免表情时间轴把鼠标视线覆盖回 0"）。

`[数据]` 模型侧还自带一条名为 **`視線追従`** 的时间线（c 模型第 60 条）+ `差分_目線左/右`（第 74/75 条）
⇒ 原游戏甚至做了"视线追随便用动作"。

**我们能不能做**：**能，而且我们有更省的路**。我们的 `kurisu-player.js` 已经有一层
"**逐帧锚点 + 小补丁**"的嘴部层（L1842：`static/kurisu/mouth/<label>.json` 逐帧锚点 + `<label>.patch.webp`；
L1923/1927 用锚点 `drawImage` 把小补丁贴到脸上）⇒ 眼睛就是**同构问题**：把"眼部区域"整块替换/平移。

**成本** `[推断]`：**2~4 人日**（1 人日 = 8h）——
`+` 每段剪辑抽 1 张"眼部区域"小图 + 1 组锚点（可复用现成的锚点提取工装）= **最省的一半**
`−` 难点在**眼球平移的合法范围**：位图眼睛被"挖"出来后，眼眶里的底色/高光会露馅
⇒ 现实做法是**眼睛微动（±几像素）+ 瞳孔层单独抠一层**，做不到 E-mote 那种"整只眼球自由转"
`−` 成本随覆盖剪辑数线性增长：先做 1~2 段（idle/thinking）验证，全 38 段要另算

**值不值得**：**值得**（见 §5）。它是 7 条里**性价比最高**的：素材增量是**几十 KB 级**（对照我们嘴部 48 个条目才 110 KB），
但它把"死图"变成"会看你"的角色，交互感差异最大 ✓。

### 3.4 表情过渡（时间线 / 插值）☆ 部分值得（借语义，不借实现）

**它做了什么** `[数据]` 每条"表情/动作"= 若干变量的关键帧轨道。统计（c 模型 759 条轨道 / ab 966 条）：

```
形态：单键+END 515（c, 68%）/ 659（ab, 68%）｜多内容键 3/4/5/2/6 键 = 81/59/52/34/12（c）
缓动取值：0 为主（1294），另有 0.5 / −0.5 / −1 / 1 / 101 / 102 / 105 / 106 / 107；**ab 里 103 出现 174 次**
END 帧时间（1/60 s）：11（336 条）、21（143 条）、61、121、30 …
样例（表情_平常 / head_slant）：[{t=0, value 0, easing 0}, {t=21, content:null}]
另有三张表：transitionControl 40 条、immediateControl 2 条、instantVariableList 23 条
```

`[源码+数据]` 三条关键语义（都被上一份实现笔记实证过，本次在数据里**复现了统计口径** ✓）：

1. **`content: null`（END 帧）不是"保持末值"，是"该轨道停止写入 = 交还下层"** ✗ 当保持末值会卡死叠加；
2. **"单键 + END" = 设值 + 过渡规格**（用该键的 `easing`，在 END 帧长内从"进入该轨道那一刻的值"过渡到目标值）
   ⇒ 朴素实现会求成常数、一帧跳到位，症状就是用户说的"表情是切换不是变化"；
3. **`easing 103` = 余弦缓入缓出**（运行时只实现这一种，其余按线性）；`instantVariableList`（23 个：眼开合、
   眉、嘴、眼泪、各 `_type` 选择器）**必须立即切换、不能插值**（插值会选到不存在的档 ⇒ 部件整个消失）。

`[源码]` 我们这套在**引擎层**不需要这些：我们的"表情"是换剪辑（38 节点/88 边），
**插值在语义上不成立**（两段位图之间没有可插的参数）。

**我们能不能做**：**部分能**。真正能借的是**三条语义**，不是那套关键帧引擎：

- 我们已有 88 条边、且边**带 `prob`**（88/88；`kurisu-player.js` L1519-1523 加权随机抽取，`prob===0` = 只允许宿主触发）
  ⇒ 边就是天然的"过渡规格"位置：**给边加一个 `transition: {kind, ms}` 字段**，就能既表达"硬切"又表达"淡入淡出/交叉溶解" ✓
- "`content:null` = 交还控制权"对应我们的 **`once_then_hold` vs `loop`**（现有 27 loop / 13 once_then_hold ✓）
  ⇒ 借它的严谨性：**每段剪辑的结束语义要显式**（保持？交还？回落默认？）而不是"播完停住"。
- "不可插值变量必须立即切换"对应我们**不要**对"服装/姿态这类离散维度"做淡入淡出 ✓

**成本** `[推断]`：**0.5~1 人日**（给边加过渡字段 + 播放器支持 alpha 交叉溶解；若已支持溶解则只补字段与文档），
**另 0.5 人日**把"结束语义/离散维度"写进状态机约定并加断言。

**值不值得**：**部分值得**（借语义、不借实现）✓。不要为"关键帧曲线引擎"买单 ✗——需要逐帧参数的只有
嘴部/眼部这两个补丁层，而它们已经有自己的逐帧锚点机制了。

### 3.7 网格变形（贝塞尔） ✗ 不追

**它做了什么** `[数据]` 每个 cel 可带 `mesh: {bp: 32 个 float, cc: null}` = **4×4 控制点场**（归一化坐标，交错的 x,y）：

```

  0.01976, 0.00518 | 0.33981, 0.00518 | 0.65987, 0.00518 | 0.97994, 0.00518 |   ← 第 1 行：x = 0, 1/3, 2/3, 1
```

`[外部声明/已实测]` 语义 = 把这 16 个点当**贝塞尔（Bernstein）补片**的控制点，对整个子树顶点做变形。
上一份实现笔记用"游戏实测结果反推基函数"给出误差表：**贝塞尔 0.72 ＜ 帐篷 6.83 ＜ Catmull-Rom 9.20**
（`E-mote动作复现-实现说明.md` §7.2），并记了两个坑：端点幽灵控制点必须**镜像反射**（用重复端点会让
恒等网格不恒等，头发被压平 154 px → 20.2 px）、以及**变形域的真实坐标系至今未解**（§7.4）。

**我们能不能做**：**不能，且不该**。网格变形要求素材是"图层 + 顶点"，我们是位图。
用 canvas/WebGL 对**整幅图**做网格扭曲（呼吸/摇摆）技术上可行，但① 我们的剪辑里动作已经是烧好的，

## 5. 一句话：现在最值得用它启发去做的一条

> **把我们已经跑通的"逐帧锚点 + 小补丁"机制（`static/kurisu/mouth/`，48 个条目仅 110 KB）从嘴部复制到眼睛，

> ±100 钳制 + 平滑"）。**

理由（三条，都对着证据）：

1. **它俩是同一层、同一套素材工装** ⇒ 一次投入两收益，不需要碰头部朝向/网格变形（那要换资产体系 ✗）；

3. **E-mote 把答案写在数据里了**：眨眼六档预设（含时长与随机间隔）+ 眼控表（`varL/varR` 镜像）+ 独立差分通道
   ⇒ 我们不用重新发明"手感"，**照抄参数**即可 ✓（这正是本次试跑最直接的产出）。

**明确不做的三件**：头部朝向（素材 ×3 ✗）、网格变形（要换素材表示 ✗）、表情关键帧引擎（对位图无意义 ✗）。
