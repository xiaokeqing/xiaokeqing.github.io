## 三、为什么"感觉不到那种牛逼"（诚实诊断）

1. **只有"流"，没有"势"。** 页面是一条实时滚动的告警行，看不到"今天比昨天多/少"、"这三周在涨"。人对"每秒 3 条"没感觉，对"7 天涨了 4 倍"有感觉。
2. **只有"数"，没有"战果"。** 拦截 98 次、封禁 18 个 IP 是实打实的战果，但页面上它们是 `blockTotal: 18` 这样的字段，不是"我替你挡了 98 次"。
3. **没有基线可比。** 单看 200 条无感；给"同类蜜罐平均每天 30 次"或"上周同一时刻 12 条"才有冲击。
4. **没有故事线。** 一次真实入侵（谁 → 用什么口径 → 试了几次 → 我多久发现 → 怎么处置 → 后来还来不来）比十个图表有说服力，而这套数据**完全支持**讲这种故事，现在只是没讲。
5. **点不开。** 一条告警点进去看不到完整链路（原始日志 → 关联蜜罐登录 → 处置动作 → 复盘结论），因此读者只能"看"，不能"查"。

一句话：现在是**监控台**，别人想看的是**作战记录**。

## 四、升级方案（按性价比排序）

### A 档 · 1–2 天，不加新数据源，把现有数据讲成"战报"

| 编号 | 做什么 | 依据（已有端点） | 验收口径 |
|---|---|---|---|
| A1 | 首页/监测中心顶部三个**英雄数字**：今日拦截、被封 IP、蜜罐被尝试次数（大字号 + 一句话解释） | audit.summary、honeypot.total | 首屏 3 秒内看懂"这站在挡攻击" |
| A2 | **今日战报**卡片：自动生成一句话（"今天挡了 98 次爆破，其中 195.178.110.218 一个人试了 228 次"） | topSources + summary | 文案由数据生成，不是手写 |
| A3 | 告警行可**展开**：规则 → 原文 → 关联蜜罐登录 → 处置结果（同一 IP 串起来） | alerts.list + honeypot.timeline + audit.blocks | 点一条能走完"检测→处置" |
| A4 | **24h 趋势条**（已有 `stats24h`）+ 来源国家/ASN 聚合（已有 geoip） | alerts.stats24h | 能看出"什么时候最凶" |
| A5 | 蜜罐"口令墙"：把 topCredentials 做成可视化（结构脱敏，不显示真口令） | honeypot.topCredentials | 视觉冲击 + 不泄露 |

### B 档 · 3–5 天，后端补聚合

- **B1 攻击者画像**：单 IP 时间线（扫端口 → 试口令 → 登录成功 → 执行命令），一条链一个页面。
- **B2 处置效果看板**：拦截成功率、封禁后复发率、误封申诉入口 —— 证明"处置有效"而不是"处置了"。
- **B3 每周自动战报**：生成 Markdown 直接进笔记区（用现成的 `note-publish.ps1` 管线），形成持续内容。

### C 档 · 1 周+，作品集级

- 公开靶场 + 对抗实录（见下节），形成"攻 → 检测 → 处置 → 复盘"的闭环展示。

**建议先做 A1+A2+A3**：纯前端 + 现有端点聚合，不改后端契约、不动发布链，一天能上线，且直接回答"这东西有什么用"。

## 五、Pikachu 靶场：可行，但要按"被监控的内部靶场"来做

### 5.1 资源够不够

srv2：4 vCPU / 3.7 GB（已用 2.0 GB）/ 40 GB（剩 15 GB）。Pikachu 是 PHP+MySQL 单镜像，常驻约 300–500 MB 内存，够跑。**srv1 只有 1.9 GB 且已用一半，不要放 srv1。**

### 5.2 三种暴露挡位（这是关键决策，不是技术问题）

| 挡位 | 谁能访问 | 风险 | 适合 |
|---|---|---|---|
| **R1 只本机/白名单** | 你自己 + 指定 IP | 几乎为零 | 录屏、截图、写文章素材 |
| **R2 子域 + 访问码 + 时间窗**（推荐） | 知道口令的人，且只在演示时段开 | 可控（口令 + 限时 + 隔离） | 给别人试、面试演示 |
| **R3 全公开** | 任何人 | 高：被当跳板打别人、被扫描器收录、Cloudflare 风控、法律连带 | 不建议 |

R3 的真实风险不是"被打穿"（靶场本来就该被打穿），而是**被打穿之后拿它当跳板**：一台公开的漏洞机器会在几小时内被自动化工具接管，然后用来扫别人 —— 那时候 IP 是你的。

### 5.3 推荐做法：R2 + "靶场即被监控对象"

```
Internet ──Cloudflare 隧道──> nginx (lab.xiaokeqing.cn, 口令页)
                                   │
                                   └─> docker: pikachu (仅内网, 禁止出网)
                                          │
                                          ├─ Suricata 镜像流量 → Wazuh 告警
                                          └─ 所有请求进 /api/public/alerts
```

要点：
1. **单独 docker network + `--network-internal`（禁止出网）**：被打穿也出不去，没法当跳板。
2. **`--read-only` + `--cap-drop ALL` + 每天定时重建**：状态脏了就重置，攻击者拿不到持久化。
3. **访问码页**（nginx `auth_basic` 或一个 6 位口令 cookie）：不让人随便撞。
4. **只在演示时间窗开放**（例如 20:00–23:00），其余时间 nginx 返回 403。
5. **页面顶部写明"仅供学习，禁止攻击他人"** —— 这句是法律意义上的"用途声明"。
6. **联动监控**：靶场流量镜像到 Suricata，Wazuh 出告警 → 面板实时可见 = **最强演示**（"你在打靶场，我这边的告警已经亮了"）。

### 5.4 工作量

- 靶场跑起来 + 隔离 + 口令页 + 定时重建：**半天**
- 流量镜像到 Suricata + Wazuh 规则 + 面板联动：**再加半天**
- 写一篇「靶场搭在公网上的 5 个坑」笔记：**1 小时**（顺手就是内容）
