### 2.1 交付物

```
脚本：/opt/secagent/scripts/srv2-site-config-backup.sh（7425 B，755，root:root）
单元：secagent-site-config-backup.service（oneshot）+ secagent-site-config-backup.timer
      OnCalendar=*-*-* 03:50:00，RandomizedDelaySec=300，Persistent=true
      （避开 srv1 数据备份 03:30 与 certbot 约 09:08）
输出：/var/backups/secagent-site-config/<host>-site-config-<stamp>.tar.gz（**chmod 600**，含私钥 ⇒ 包本身敏感）
      + 同名 .sha256（备份包自身指纹）
```

运维同学不用学第二套心智；同时**不修改**现有脚本与 cron（只加自己的）✓。

## 3. 换机/灾难恢复 SOP（本次演练覆盖的是"包能不能用"，这里是"怎么用"）

```
前置：新机装好 nginx 1.18+ / certbot 与相同的目录结构；注意 srv2 的坑（127.0.0.1:443 被 wazuh.dashboard 的
      docker-proxy 占用 ⇒ nginx 只能监听 10.0.0.10:443 与 127.0.0.1:18080 ✗ 不能绑 0.0.0.0:443）
1. 取包：/var/backups/secagent-site-config/<最新>.tar.gz + 同名 .sha256（或从演练目录取）
2. 校验包本身：sha256sum -c <包>.sha256
3. 解包到临时目录：TMP=$(mktemp -d); tar -xzf <包> -C $TMP
4. 先跑演练：srv2-site-config-backup.sh --drill <包>   → 期望 PASS
5. 还原（**这一步才碰线上**，且要先备份现场）：
     cp -a /etc/nginx /etc/nginx.pre-restore.<stamp>
     rsync -a $TMP/<stamp>/payload/etc/nginx/ /etc/nginx/
     rsync -a $TMP/<stamp>/payload/etc/systemd/system/ /etc/systemd/system/    # 只放回需要的单元
     rsync -a $TMP/<stamp>/payload/etc/letsencrypt/ /etc/letsencrypt/          # 保持 root:root 700 / live 目录符号链接
     rsync -a $TMP/<stamp>/payload/opt/secagent/scripts/ /opt/secagent/scripts/
6. 权限/属主修复（照本轮实测值；口径同 `docs/服务器配置-详细版-给外部AI.md` §5）：/etc/ssl/secagent/site-privkey.pem → root:xksite 640；site-fullchain.pem → root:xksite 644；
     /etc/letsencrypt 700 root:root；脚本 755；单元 644
7. systemctl daemon-reload
8. 语法与证书：sudo certbot renew --cert-name xk-site --dry-run（验证续期链路可走通）
9. 拉起：systemctl start secagent-static；回环自检 curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18080/ → 期望 200
10. 对外核验：从 srv1 curl https://xiaokeqing.cn/ → 期望 200（本机直连会被未备案阻断，不能用本机核验 ✗）
回滚：把第 5 步的 .pre-restore.<stamp> 拷回去 + daemon-reload + reload（本次演练**没有**执行第 5 步以后的动作）
```
