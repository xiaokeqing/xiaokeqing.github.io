## 3. 两个脚本干了什么（你要的"能力"核心 = 对齐 + 筛）

### 3.1 [tools/asset-align.py](tools/asset-align.py) —— 任意生成结果 → 既有规格

```
用法示例：
  python tools/asset-align.py --in <帧目录|单图|glob> --name <新剪辑名> \
         --target-clip idle            # 或 --interval 17 --loop-mode loop --canvas 764x1028
         --anchor-from clip:idle       # clip:<剪辑> | family:front|side|emotion|closed | anchors
         --fit canvas|head|h|w|area    # canvas(默认)=源整幅矩形→画布矩形
         --sheet --tier medium --webm  # 出图集 / 出透明 VP9+alpha WebM
         --edge-guard 16 --margin-px 0 # 上游同名的两个保护开关
         --dry-run                     # 只看会怎么对齐，不写文件
```

**三条不许省的纪律（来自上游 invariant，不是我们自己定的）：**

1. **一段素材只用一套变换**。上游原文："A clip's first frame is registered to its start still once.
   Every frame uses the same crop, scale, rotation and translation, preserving the source motion."
   ⇒ 逐帧各自缩放会看到"呼吸式忽大忽小" ✗。本脚本先算唯一一套 `(scale, dx, dy)`，再套到全段。
2. **零填充编号**。上游："Filenames are sorted lexicographically, so zero-pad numeric filenames."
   ⇒ 输出一律 `0000.png`…，输入位宽不齐会**告警但不擅自改名** ✓
3. **逐帧时长取自目标剪辑规格（8/17/21/5 ms），不拿容器 fps 当间隔** ✗
   （现有 WebM 容器是 60 fps、`durationMs = frames/60*1000`，那**不是**播放语义；
   渲染器按 `frameIndex` 逐帧画 ⇒ 真实时长写进 `frames-durations.json` 的 `durationsMs[]`）

**输出（默认落仓库外 `E:\DeepSeek1\work\_asset-out\<name>`，不往仓库塞大文件 ✓）：**

| 产物 | 内容 |
|---|---|
| `frames/0000.png…` | 画布规格 RGBA 帧序（可直接进图集/视频管线） |
| `frames-durations.json` | `frameIntervalMs` + 逐帧 `durationsMs[]` + 总时长 |
| `atlas/<clip>.atlas.webp`（可选） | 图集，页描述字段（`tile_w/tile_h/cols/rows/first_frame/last_frame/pixels/bytes`）**与 statemachine 的 `medium.pages[]` 同构** ⇒ 能直接喂入库脚本；多页按现有命名 `X.atlas.p01.webp` |
| `video/<clip>.webm`（可选） | 透明 `yuva420p` VP9，容器沿用 60 fps（与既有 video 管线一致） |
| `align-report.json` | 唯一变换、源/目标锚点、逐帧 QA（锚点偏差 / 面积比 / 贴边 / 断帧 / 跨帧漂移） |

**实测（两轮，`[已实测]`）：**

```
① 4 帧 268×360 已发布视频首帧（idle / speaking_med / angry_speaking / shy_speaking1）→ 764×1028
   scale 2.85556 ｜ dx 0.210 ｜ dy 0.011（平移量近乎 0 ⇒ 说明"视频首帧→画布"本来就该这么映射 ✓）
   逐帧：|ΔheadTopY| ≤1.0 px、|ΔheadCenterX| ≤1.25 px、面积比 1.0002~1.0144（容差 15%）
   贴边检查全过（只有底边）｜ 跨帧漂移 headTop 2.0 px、headCenter 0.54 px（容差 3 px）
② 180 帧真实剪辑（angry_speaking medium 图集）→ 同规格输出
   锚点跨帧漂移 headTop 0.0 px、headCenter 0.23 px ｜ QA 180/180 通过
   总耗时 126.2 s = 0.70 s/帧（含图集 WebP + 透明 WebM 编码 + 逐帧 QA）
```

### 3.2 [tools/asset-consistency.py](tools/asset-consistency.py) —— 与定妆集比、自动筛

```
三个指标（都会算、都会报）：
  ① 相似度    rgbNcc              可见区（两边剪影并集）内灰度的归一化互相关
  ② 边缘 NCC  edgeNcc             Sobel 边缘幅度图，在**膨胀后**的剪影掩码内做 NCC（最锐）
  ③ 关键点    kpMeanDistPx         Harris 角点在 alpha>128 内检测（numpy 自实现，无 cv2），
                                  互相最近邻 + 距离门限（画布对角线 8% = 102.5 px）匹配，
                                  再换算成**画布像素**报平均/最大距离
  附：alphaIoU（剪影重叠）、areaRatio、headTopDeltaPx / headCenterDeltaPx（上游同定义，容差 3 px）、
      下脸 L* 差（上游 QA 的 ROI：headTopY 往下 24%~30%、头心左右各 5% 画布宽）

⚠ 关于"关键点距离"的口径（必须写清，否则是吹）：
   这是**坐标级匹配**（无描述子），能测"整体对位与五官间距漂移"，
   **不能**替代特征描述子匹配，也**不能**判定"是不是同一个人物设定"。
   要更强需要 ORB/SIFT（上游用 ORB + RANSAC 做刚体注册）—— 那要 cv2，本轮没引 `[限制]`
```

**命令：** `calibrate`（互测标定）｜ `check --in DIR --clip NAME [--family X] [--out report.json]`｜ `refs-matrix`

## 4. 一致性阈值：**用现有素材互测标定出来的**（不是拍脑袋 ✓）

标定数据：[tools/refs/consistency-calibration.json](tools/refs/consistency-calibration.json)（31,495 B）
命令：`python tools/asset-consistency.py calibrate` ｜ 耗时 **60 s** `[已实测]`

方法：现有 38 个已剪辑的 medium 图集各取 6 帧（共 **210 帧查询**），逐帧与定妆集比，
**留一剪辑出**（排除同剪辑的参考帧 —— 否则会跟"同一帧自己"比，虚高 ✗）。
764 宽之外的 3 个剪辑（`idle2` / `trans_smile` / `idle_closed_eye`）**排除并记名**，不硬凑。

### 4.1 "像"的分布（210 帧 / 35 剪辑）

| 指标 | min | p05 | p10 | 中位 | p95 | max |
|---|---|---|---|---|---|---|
| `edgeNcc` | **0.1769** | 0.2611 | 0.2907 | 0.8442 | 0.9493 | 0.9615 |
| `rgbNcc` | 0.4987 | 0.6503 | 0.6659 | 0.9815 | 0.9954 | 0.9974 |
| `alphaIoU` | 0.8248 | 0.8723 | 0.8782 | 0.9879 | 0.9969 | 0.9981 |
| `kpMeanDistPx` | 3.208 | 3.697 | 3.942 | 5.611 | **18.242** | **19.500** |
| `areaRatio` | 0.9412 | — | — | 1.0030 | — | 1.0812 |
| `\|ΔheadTopY\|` px | 0 | 0 | 0 | 1.0 | 5.0 | 16.0 |
| `\|ΔheadCenterX\|` px | 0.001 | 0.019 | 0.044 | 0.523 | 4.875 | 26.554 |

**为什么 `edgeNcc` 最低只有 0.1769？** 逐剪辑看，最低的几个是
`trans_standby` 0.1769、`closed_eye_trans` 0.1874、`speaking_loop1/2` 0.2345/0.2627、`speaking_trans` 0.2490 ——
全是**转场/残影（ghost trail）剪辑**与**大幅度侧身**。这不是 bug，是"边缘指标天生对姿态敏感"。
⇒ **结论：`edgeNcc` 必须按姿态族用，不能当全局判据**（见 4.3）。

### 4.2 "不像"的负样本（7 个，来源都标了）

| 负样本 | edgeNcc | rgbNcc | alphaIoU | kpMeanDistPx |
|---|---|---|---|---|

| `synthetic:disk-flat`（圆盘+平色） | −0.0409 | −0.1003 | 0.4830 | 16.73 |
| `synthetic:stripes-rect`（竖条矩形） | 0.0651 | 0.0108 | 0.6046 | 16.49 |
| **`synthetic:idle-rgb-inverted`（轮廓=idle、颜色反相）** | **0.8311** | **−0.9999** | **1.0000** | **3.69** |
| **`synthetic:idle-silhouette-flat`（轮廓=idle、颜色拍平）** | **0.3999** | −0.0251 | 0.9922 | 11.85 |

后两个是**专门用来打指标盲区**的（用已发布 idle 首帧改造，可复现）——它们如实暴露了问题：

```
✗ 盲区 1：edgeNcc 测不出"轮廓对、内容错"。反相假素材 edgeNcc 0.8311，落在"像"分布的中位区间里
           （会**通过**只卡边缘的门禁），但 rgbNcc −0.9999 一票否决 ⇒ 判定必须**两个指标同时达标**
✗ 盲区 2：alphaIoU 同样被骗（反相样本 alphaIoU = 1.0000，因为 alpha 完全一致）
✗ 盲区 3：kpMeanDistPx 也骗过了（3.69 px，是最"像"的一档）
⇒ 所以：alphaIoU / edgeNcc / kpMean **都只看几何**；**只有 rgbNcc（与 L\*）看内容** ✓
```

### 4.3 标定出来的阈值（**判定一律读这里** ✓）

| 等级 | 规则 |
|---|---|
| `fail` | `edgeNcc < 0.1769` **或** `rgbNcc < 0.2548` **或** `kpMeanDistPx > 19.500` **或** `\|ΔheadTopY\|/\|ΔheadCenterX\| > 3 px` |
| `fix` | `edgeNcc < 0.2611`（"像"的 p05）**或** `rgbNcc < 0.6503`（p05）**或** `\|areaRatio−1\| > 15%` **或** `kpMean > 18.242`（p95） |
| `watch` | `edgeNcc < 0.2907`（p10）**或** `rgbNcc < 0.6659`（p10） |
| `pass` | 其余 |

```
推导方式（写进 JSON 的 derivation 字段，可复核）：
  fail 线 = "像"的最小值 与 "不像"的最大值 的**中点**（分离成立时）；
            **分离不成立时保守取"像"的最小值** —— 宁可漏放一个不像的，也不误杀一个真的
            （误杀会白烧生成钱 ✗）
  fix/watch = "像"分布的 p05 / p10
  kpMean：fail = "像"的最大值、fix = p95
  头部锚点：直接取上游 3 px（`docs/production.md` §Character contract）

★ 实测：`edgeNcc` 的分离**不成立**（margin −0.6542，被反相假素材打穿）⇒ 它的 fail 线走了保守分支 = 0.1769
     `rgbNcc` 的分离**成立**（margin +0.4879：像的 min 0.4987 > 不像的 max 0.0108）
  ⇒ 结论：**`rgbNcc` 才是"是不是她"的主判据；`edgeNcc` 是"姿态/五官有没有跑偏"的辅助判据** ✓
```

### 4.4 同族基线（新素材落在已知姿态族时该用这条）

### 7.2 新增一套服装（半身）—— 🟡 可达但慢：**一套服装 ≈ 一整套动作重产**

```
差别只有两处，其余同 §7.1：
  ① 步骤 1 之前先"造基准静帧"：用图像编辑 provider（qwen-image / seedream）改服装
     → `production generate --pose idle --provider qwen-image --dry-run` 先看请求（不花钱）
     → 生成的图走**同样的 alpha + 归一化 + 几何 QA**（它与基准静帧的刚体注册应当接近 100% 匹配）
  ② 步骤 1 的"新姿态静帧"全部要做同一套服装的版本；历史剪辑**不能混用**（一件不一致就出戏 ✗）

### 7.3 新增一个发型 —— 🟡 最难，建议最后做

```
