# 交接 · 六页"整份搬 demo"（2026-10-14 第四批 · 上线版）

> 站主口径（本轮最高优先）：**用户要的是"打开生产页 = 打开那个 demo 文件"**。
> ⇒ 不再套站点 SPA 外壳、不再挂 `kurisu-player.js`、不做像素差循环；
>   每页 = 对应 demo 文件**整份**（它自己的 `<style>` + 标记 + 内联 `<script>`），
>   只改素材路径；数据先用 demo 自带的占位数字（接真实接口等站主点头）。
> 基准文件：`docs/demo-主页.html`（主页）、`docs/demo-内容页外壳.html`（其余五页）。

## 一、一页一页的对应关系与产物位置

| 路由 | 基准 | 产物 layout | 初始那一屏 |
|---|---|---|---|
| `/` | `docs/demo-主页.html`（整份） | `layouts/index.html` | 无 `.view`（它自己的 `.stage/.crt`） |
| `/alerts/` | `docs/demo-内容页外壳.html`（整份） | `layouts/alerts/list.html` | `v-monitor` |
| `/posts/` | 同上 | `layouts/posts/list.html` | `v-notes` |
| `/labs/` | 同上 | `layouts/labs/list.html` | `v-range` |
| `/about/` | 同上 | `layouts/about/list.html` **+ `layouts/about/single.html`** | `v-about` |
| `/ai/` | 同上 | `layouts/ai/list.html` | `v-ai` |

· `layouts/about/` 要落**两份**同样的模板：`content/about/_index.md` 的 front matter 写着
  `layout: "single"`，Hugo 只认 `<type>/single.html`（本轮实测：只放 list.html 时它会落回老的
  `_default/single.html`，页面还是旧版式）。
· 共享片段（都从 demo 文件逐字抽取）：`layouts/partials/xk-demo/` 下
  `head-meta.html`（Hugo 的 head 契约）、`shell-style.html`、`shell-chrome.html`、
  `shell-views.html`、`shell-script.html`。
· 生成器：`_dev/gen-demo-pages.py`（**demo 文本全是逐字抽取，不手抄**；改口径改它重跑）。
  产出物在 `layouts/` 下，那些才是要提交的源文件。

## 二、与 demo 的**全部**差异（逐条都有理由，没有一处是"自己发挥"）

1. **素材路径**（demo 的 `demo-assets/*` → 仓库里已存在的真文件，逐字节同一份）
   ```
   desk.webp / lab.webp                        → /images/crt/desk.webp · /images/crt/lab.webp
   amadeus_ambient_high_blend.webp             → /kurisu/scene/amadeus_ambient_high_blend.webp
   subtitle_frame_big.webp                     → /kurisu/scene/subtitle_frame_big.webp（原图 382,384 B，未降质）
   opening.hi.webp                             → /kurisu/full/opening.hi.webp   ← demo-assets 里**缺**这个文件
   idle/speaking/thinking.hi.webp              → /kurisu/full/*.hi.webp
   normal.idle · normal.speaking · happy.idle · happy.speaking
   sided_thinking.idle · sided_thinking.speaking · sad.static · blush.static  → /kurisu/avatar/*
   bg/room_* · bg/light_low                    → /kurisu/scene/bg/*（8 张本来就在）
   bg/light_high.webp                          → /kurisu/scene/bg/light_high.webp（**本轮唯一新入库的素材**，45,352 B）
   ```
2. **主页 `.navpill` 的 `href="#"` → 站点真路由**（`/` · `/alerts/` · `/posts/` · `/labs/` · `/ai/` · `/about/`），
   样式一字未动（站主原话："链接指向站点真路由，样式照 demo 不动"）。
3. **五页 `.dock` 的 `<button data-v=…>` → `<a href="真路由">`**（理由：生产页要真链接、可新窗口打开、
   可被爬；demo 的 button 是它自己 JS 切 view 用的）。为了让外观值与 demo 完全一致，
   `shell-style.html` 里**新增**一组 `.dock a{…}`（三条，值逐字照抄 demo 的 `.dock button` 三条 + `text-decoration:none`）。
   demo 自己的元素渲染结果零变化。JS 里那句 `#dock button` 的绑定保留原样（找不到 button 就是空循环）。
4. **行为级懒加载（站主第四批口径③明确允许：只改加载时机、不许改版式、首屏可见的必须照 demo 立刻载）**
   —— 逐条写在 `layouts/partials/xk-demo/shell-script.html` 的 Hugo 注释里，实现见 `_dev/gen-demo-pages.py` 的 `LAZY_PATCHES`：
   ```
   · v-home 的 4 张场景图加 loading="lazy"（五个内容页上 v-home 是 display:none，不进首屏）
   · 背景选择器 10 张缩略图加 loading="lazy"（在关着的弹层里）；当前背景（#bgEl 的 CSS background）照 demo 立刻载
   · 头像泡（折叠后才显示）与"面板/手机各自不可见时"的角色图集不载；可见的那一份照 demo 立刻载
   ```
   ⚠️ 踩过的坑：这段说明**不能**写成 JS 注释留在 `<script>` 外面 —— 会被当正文渲染出来
   （实测像素差从 0.44% 弹到 3.59%）。现在放在 Hugo 注释里，不进产物。
5. **不可见契约（站点必需，站主允许保留"head/标题/#content 之类"）**
   ```
   · <head>：Hugo 的 title / description / canonical / favicon / OG（demo 自己的 <head> 只有 charset+viewport+title）
   · <main id="content" data-xk-ssr="<路由名>">：SPA 契约断言读它（主页那页把 demo 的 body 内容整块包进 <main>，
     所有元素都是 position:fixed/absolute，包一层不影响渲染 —— 实测版式像素差 0.00%）
   · <div id="xk-views" hidden>：空的占位（本轮不挂 app.js，所以它不参与任何逻辑）
   ```
6. **没搬**：站点 SPA 外层（app.js / 左栏 / 顶行 / 输入条 / 页脚 / 搜索层）、`kurisu-player.js`、
   状态机 37 节点 / 语音 / 口型 —— 站主明确要求这些**不要**进这六页。

## 三、demo 文件自身的三处缺陷（照搬原样，未替它补齐）

1. **`v-about` 是空的**：`docs/demo-内容页外壳.html:705-709` 只有三个孤立的 `</div>`，没有任何内容。
   ⇒ `/about/` 打开就是"背景 + dock + HOLO 面板"，没有正文。生产页照搬（= demo 的 about 屏就是这样）。
2. **外壳的 `scene-js` 依赖两个不存在的元素**：它调 `document.getElementById('fallback').style`（:1161）
   与 `#bootveil`（:1236/:1243），但外壳文件里**没有**这两个元素 → `resize()` 抛 TypeError，
   整个 IIFE 在启动处中止 ⇒ 外壳里的 `v-home`（CRT 场景）**在 demo 里本来就画不出来**。
   生产页照搬 → 五页控制台各有一条 `Cannot read properties of null (reading 'style')`。
   （主页那份 `docs/demo-主页.html` 是好的：它两个元素都有。）
3. **`docs/demo-assets/` 缺 `opening.hi.webp`**（只有 `opening.boot.webp`）⇒ demo 原文件单独打开时
   开场永远画不出、canvas 全黑。生产页把它指到我们仓库里那份 `/kurisu/full/opening.hi.webp`。

## 五、三道门禁（本轮原文见交付消息）

| 门禁 | 结果 | 备注 |
|---|---|---|
| `scripts/assert-build.sh public` | **15/15 PASS** | 角色+场景资产 79MB ≤ 80MB（新增 light_high 45KB 后仍有余量） |
| `_dev/check-ssr-contract.py public` | **6/6 PASS** | data-xk-ssr 六个都对应、`#xk-views` 都在、站外资源 0 |
| `_dev/gate-firstscreen.mjs` | **5/6 页 PASS**，`/ai/` FAIL | 见下"冲突"；预算已按站主裁定①改成 1600KB |

**门禁本身本轮改了两处（都在 `_dev/gate-firstscreen.mjs`）**
1. 预算常量 `1,572,864 B → 1,638,400 B`（1536KB → 1600KB）。理由：1536KB 是上一轮自己定的数，
   不是用户要求；主页实测 1569KB，构成全是 demo 自己的素材（opening.hi 1004 + 垫板原图 373 + desk/lab/ambient 179 + favicon 13）。
2. 删掉旧的"hash 路由逐条切页（核对 app.js 的 `data-xk-render`）"整段 —— 它测的是本轮已按口径拆掉的
   SPA 机制；换成新口径断言：**每页初始 `.on` 必须落在它自己那一屏** + `main[data-xk-ssr]` 取值正确 +
   `#xk-views` 在；主页改为断言 `.navpill` 当前项 + `#charCanvas` 真的画出东西（>10000 不透明像素）。
   路由契约仍由 `check-ssr-contract.py` 负责。

## 六、剩下的冲突（做不了 / 需要站主点头）

**`/ai/` 首屏 1637KB > 1600KB（超 37KB）—— 无法在不违反口径③的前提下压下去**
```
构成只有两项，且两项都是"首屏可见"：
  1555 KB  /kurisu/full/speaking.hi.webp   ← 手机里那段全身 speaking 图集（demo 用 hi 档：90 帧 321×432）
    82 KB  /kurisu/scene/bg/room_empty.webp ← 当前房间背景
口径③原文要求"若某张图在首屏可见（例如当前房间/当前角色帧）必须仍然照 demo 立刻载"⇒ 两项都不能延后。
可选的三条路（我没自己做决定）：
  (a) 预算放到 1650KB（`_dev/gate-firstscreen.mjs` 里 1638400 → 1689600，一行）；
  (b) 接受 /ai/ 超着（它只有这 37KB）；
  (c) 允许手机改用 speaking.boot.webp（444KB，24 帧）—— 但这**改变动画**（帧数 90→24），与口径③"渲染结果不变"冲突。
另：/ai/ 在 2.6s 后手机转到 idle 状态，会再载 idle.hi 1285KB —— 这是 demo 自己的行为（它在 speaking/idle 之间切）。
```
