# 攻击地图（世界地图热力 / 点阵）可行性评估

> 结论先给：**能做，而且很便宜——但不要做"热力图"，做"点阵 + 气泡"。**
> 理由是这份数据只有 7 个国家（欧洲 4 国质心相距不到 6°），分级填色的世界地图上只会点亮 7 块颜色，
> 其中 4 块还叠在一起；而点阵气泡能把"欧洲占 66%"这一件事一眼说清，底图只要 4.2 KB gzip，且**零新增请求**。
>
> 评估人：AI 施工窗口 · 2026-10-17 22:39–22:52（+08:00）
> 产出：本文档 + `_dev/map-demo.html`（可浏览器直接打开的独立 demo，已跑通）+ `_dev/gen-worldmap-data.py`（底图生成器）
> 本文档**只做评估与方案**，没有改任何页面、没有跑 hugo、没有 git commit、没有碰服务器。

## 2. 现有取数链路：地图能不能复用？（能，且是零成本复用）

### 2.1 结论：**零新增请求**

`/api/public/home.js`（**28,967 B**，带 `snapshotAt`/`cacheAgeSeconds`/`snapshotTtlSeconds` 包装）的 `data.geo`
**是完整 geo**：`byCountry`（含 `byProvince`）、`coverage`、`byProvinceCN`、`byAsnTop`、`trend`、`note`、`ipDisclosure`
—— 与单独请求 `/geo` 字段**完全等价**。而 `/alerts/` 首屏已经在取 home.js 了。

所以在 `layouts/partials/xk-demo/api-bind.html` 里：

| 位置 | 现有代码 | 对地图的意义 |
|---|---|---|
| `api-bind.html:1202` | `var BASE_JOBS = SSR === 'monitor' ? ['home'] : [];` | 首屏只发 1 个聚合请求，**不要再加 `/geo`** |
| `api-bind.html:1279-1292` | `settleHome()` 把 `data.{alerts,geo,honeypot}` 扇出成三个 part，`saveGood()` 存「上次成功」 | 地图用 `parts` 里的 geo，与 TOP 卡同源同帧 |
| `api-bind.html:1258-1271` | `degraded(p)`：`if (q.indexOf('/geo') >= 0) return !d.byCountry \|\| !d.byCountry.length;` | 冷缓存降级判据已写好，地图沿用即可 |
| `api-bind.html:470-479` | `bindGeo(parts)`：`geo.byCountry.slice(0,4)` → 「TOP 攻击来源」4 行 | **只用了 4 国**，`byProvince`/`byAsnTop` 至今没上过页面 |
| `api-bind.html:539-563` | 第 4 格计数器用 `coverage.sourceBuckets` | 口径与地图一致的前提 |
| `api-bind.html:601-613` | stats 面板「来源 TOP5」用 `.geo li` + `sharePercent` 归一化进度条 | 地图与它共用 `sharePercent`，不会打架 |
| `api-bind.html:202-208` | `ALIAS` 表含 `geo → geo.js` | 单独取 geo 时必须走 `.js` 别名（CF 可缓存），禁带 cache-buster |

### 2.2 所以"地图不是重复造轮子"，但要**新增而不是替换**

`layouts/partials/xk-demo/shell-views.html:60-67` 的「TOP 攻击来源」（4 行 `.row`）已经在讲"谁在打"。
地图加进去的价值是**空间聚集性**（欧洲 66% 挤在一小块），这是 4 行文字给不出的信息；
但把 4 行换成地图是**净损失**（拓扑上是"文字 → 图形"，但失去了精确次数、占比、可复制文本）。
⇒ 建议：**保留 TOP 卡，地图作为第 5 个 ops-tab 或 stats 面板的新卡片**（`#atkGraph` 已被"攻击路径图"占用，新元素别撞 id）。

### 2.3 零第三方脚本约束的真实口径（不是"不能有分号之外的东西"，而是只查三个属性）

`_dev/check-ssr-contract.py` 对 8 个页面（`index/alerts/posts/ai/test/what/lab/status`）做三条断言，其中安全相关的一条是：

```python
RE_EXT_RES = re.compile(r'(?:src|href|poster)="https?://(?![^"]*xiaokeqing\.cn)[^"]+"', re.I)
```

⇒ **只禁止 `src` / `href` / `poster` 里的站外 URL。**
内联 SVG、`<canvas>`、`<script type="application/json">` 内联数据、CSS 里的 `url(#id)` 全部合规。
站内 CDN 上的 echarts / d3 / 世界 GeoJSON **一律不行**（会被这条正则打成 `https://cdn...` 命中）。
另外 `https://xiaokeqing.cn` 自己的域名在白名单里。

体积门禁：`_dev/gate-firstscreen.mjs:45` `BUDGET = 1689600`（1650 KB / 页，导航后 1.5 s 内全部资产）。
现状 `public/alerts/index.html` = 213,264 B 原始 / **68,043 B gzip** ⇒ 加 4–12 KB 内联数据**预算压力可忽略**。
真正的成本是**观感**和**接线工作量**，不是体积。

## 3. 三个方案的体积 / 工作量 / 视觉收益

体积口径说明：`varint+base64`（坐标×10 取整、首点绝对后续差分、zigzag varint）是这类数据的合理编码；
直接存浮点 JSON 会虚高 3~4 倍。下表两种都给。

| | **A. 内联世界轮廓自己画** | **B. 陆地点阵 + 气泡**（推荐） | **C. 不做地图：条形榜 + 时区带** |
|---|---|---|---|
| 底图数据（陆地轮廓） | 抽稀 0.15°：**9.8 KB**（JSON 45.4 KB）/ gzip 6.6 KB | **不需要**（点阵位图代替） | 0 |
| 底图数据（**国界多边形**，分级填色必需） | 0.25°：**15.4 KB** gzip 10.6；0.15°：19.8 KB gzip 13.2；0.40° 省一点但国界会烂 | 点阵位图 `maskB64` 8,520 字符 + 175 国质心 + 51 微国 = **12,555 B / gzip 3,764 B**（实测） | 0 |
| 运行时请求 | 0 | 0 | 0 |
| 实现工作量（含接线） | **2–3 人天**：varint 解码 + 路径重建 + 墨卡托/等距圆柱投影 + 分级填色 + 国名映射 + 省份补充表 + 交互 | **0.5–1 人天**：位图解码 ~30 行 + 投影 + 气泡 + 聚合 + hover（demo 已写完 80%） | **0.5 人天**：复用现有 `.geo` 列表 + 7 条时区偏移静态表 |
| 视觉收益 | 高——但**在这份数据上失效**：只有 7 国能填色，且 4 国质心相距 <6°，填出来是"一坨欧洲" | 中高——气泡面积+颜色编码份额，"欧洲 66%" 一眼可见，还能表达"聚成一坨"这件事本身 | 中——读得最准，但零空间直觉 |
| 数据精度匹配度 | 差：GeoIP 只到国家，用国界填色 = 把"国家"伪装成"国土被占领" | 好：点位本来就是国家质心，气泡不承诺精度 | 好 |
| 无 JS / 打印兜底 | 难（一张 canvas 空白） | 易（`<details>` 表格 + 现有 `.geo` 列表） | 天然可读 |
| 失败模式 | 国界数据源许可/体积/精度三者互相拉扯 | 微国坐标要靠人补（不补就丢 6.6% 的 AD） | 无 |

### 3.1 为什么不是 A（虽然它"看起来最像地图"）

1. **分级填色必须用国界多边形，不能用陆地轮廓**。实测：陆地轮廓抽稀到 0.15° 只要 9.8 KB，
   但那只是一条条海岸线，没有国界 —— 无法给"法国"填色。换成 288 个国界多边形，同样 0.15° 要 **19.8 KB**（gzip 13.2）。
2. **就算填出来，也只有 7 块颜色**。24h 里能达到门槛的只有 7 国，其余 190 多国为空。
   一张"只有 7 个国家有颜色、其中 4 个在欧洲互相压着"的世界地图，信息量不如 4 行文字。
3. **省/州级救不了它**。`byProvince` 只有 CN 有 2 条，`knownProvinceCount: 96` 但**没有省级质心表**；
   要做"省级热力"就得再补一套省界数据（几百 KB 量级），与"最省"背道而驰。
4. 110m（1:1.1 亿）国界在屏幕上画 1500 px 宽时，边界误差已经可以用肉眼看出（小国会糊成一团）。

> A 唯一值得留的场景：将来上了省级数据、且想要"全国被扫描分布"的效果，再考虑。现在做是纯亏。

### 3.2 为什么 B 是最省的"真地图"

- **底图是位图，不是矢量**：1° 全球网格 360×142 = 51,120 格，陆地 15,496 格，按 bit 打包后 base64 = 8,520 字符（8.3 KB）。
  上线只需要 `grid + maskB64 + centroids + micro` 四项 = **12,555 B，gzip 3,764 B**（实测）；
  生成器附带产出的 `note` / `optionA`（方案 A 体积实测表）属于构建期信息，**不必进页面**。
  解码只需一个循环（`bytes[i>>3] & (1<<(i&7))`），30 行。
- **视觉上够用**：1° 点阵在 1400 px 宽的画布上，1 格 ≈ 3.9 px，画成 1.6 px 的方点，大陆轮廓清晰可辨（demo 截图已验证）。
- **表达力反而比填色强**：气泡面积按份额、颜色按份额，欧洲 66% 会变成一个压在西欧上的大气泡，
  "四个国家挤在同一块"这件事用**聚合气泡**直接说出来（demo 里点 `重叠聚合` 可见 `FR+NL+GB+AD 66%`）。
- 数据源：Natural Earth 1:110m（**公有领域**，免署名）；构建期下载一次，运行时零请求。

### 3.3 为什么 C 是必须保留的降级

C 不是"退而求其次"，它是**无 JS / 打印 / 窄屏**的兜底，也是 B 的 `aria-label` 内容来源。
而且 C 里"时区带"是个真需求：现有页面**没有**任何按时间的国家维度视图，`trend` 只有全局小时桶。
C 的额外成本极低（7 条国家→UTC 偏移静态表 + 现有 `.geo` 样式），建议**跟着 B 一起做**，作为 B 的 `<details>` 兜底。

## 4. 推荐方案

**主图：方案 B（1° 陆地点阵 + 国家气泡 + 重叠聚合），底图数据内联，随 home.js 的 `data.geo` 更新，零新增请求。**
**兜底：方案 C（同一份数据的国家条形榜 + `byAsnTop` 榜），放在 `<details>` 里，也是无 JS 时的内容。**

理由，按权重排序：

1. **成本**：4.2 KB gzip、0 新增请求、0.5–1 人天（demo 已完成大半），且不碰 `BASE_JOBS` 与取数逻辑。
2. **数据匹配**：GeoIP 精度只到国家 → 点位用国家质心 → 气泡不承诺精度，不会说假话；填色会。
3. **视觉收益**：能一眼看出"欧洲聚成一坨占 66%"，这是现有 4 行文字给不出的。
4. **可访问性**：canvas 外的表格兜底天然成立；A 的分级填色在无 JS 时基本无法等效表达。
5. **可撤退**：整块是独立 canvas + 一个 `bindMap()`，删掉不影响任何现有面板。

## 5. 风险与应对

| # | 风险 | 实测证据 | 应对 |
|---|---|---|---|
| R1 | **GeoIP 精度只到国家/省**，点位是国家质心，读成"攻击者在某城市"就是造谣 | `geoSource` 是 DB-IP **Lite City**；`byProvince` 只有 CN 的 2 条 | 图注写死"国家质心·非真实坐标"；不做城市级点位 |
| R2 | **单 IP 刷量让"次数"严重失真** | FR 12,637 次只来自 **15** 个 IP（842 次/IP）；TR 883 次来自 **2** 个 IP（442）；AD 161 次/IP | 度量必须可切「次数 / 独立 IP」；默认建议**次数**（与现有 TOP 卡一致），但切换要显眼；图注写明差异 |
| R3 | **分母误用** | totalAlerts 79,216 vs geocoded 31,522（39.8%） | 只用 `coverage.geocoded` 做分母；文案按 1.2 节模板 |
| R4 | **微国在 110m 数据里不存在** | Natural Earth 1:110m 只有 177 个国要素，**AD/SG/HK/MO 都没有**，而 AD 是第 5 大来源（6.64%） | 生成器手工补 51 个微国/城邦坐标（已做）；`miss` 面板会列出"无坐标未落图"的国家，不允许静默丢点 |
| R5 | **欧洲质心过密，逐国画必叠** | FR(2.3,46.6) / NL(5.5,52.3) / GB(−2.7,53.9) / AD(1.5,42.5)，两两屏距 < 40 px（1400 px 画布） | 重叠聚合（阈值 `0.8×(r1+r2)`），聚合组 hover 列明细、数字不合并 |
| R6 | **接口慢** | 两次实测 14.4 s / 28.9 s（冷） | 地图**绝不单独请求 /geo**，只吃 home.js 的 `data.geo`；`cacheSeconds: 45` + 页面 40 s 刷新已够 |
