## 一、Cloudflare 立即刷新（HTML/资源短缓存）

### 背景（为什么需要）
- 源站（srv2）对 HTML 发 `Cache-Control: public, max-age=300`，Cloudflare 边缘会缓存 300 秒。
- 每次发布后，最多 5 分钟内你／访客可能拿到**旧版本页面**；资源已带 `?v=<8位sha>` 指纹，所以只有 HTML 有这个问题。
- 想「发布完立刻生效」只有两条路：**边缘 Purge**，或者缩短 TTL（不能消除窗口）。

### 方式 A：手动清（10 秒，不用给我任何东西）
1. 浏览器打开 <https://dash.cloudflare.com/>
2. 左侧选中站点 **xiaokeqing.cn**
3. 顶部菜单 **缓存 / Caching** → **配置 / Configuration**
4. 点 **清除缓存 / Purge Cache**
5. 选 **清除所有内容 / Purge Everything** → 确认
6. 生效时间：通常 1~5 秒（控制台会写「已清除」）

> 发布后想自己确认：`curl -sI https://xiaokeqing.cn/what/ | findstr /i "cf-cache-status last-modified"`，`cf-cache-status: MISS` 就说明拿到新的了。

### 方式 B：给我一个 Token（让发布脚本自动 Purge，一劳永逸）
1. <https://dash.cloudflare.com/profile/api-tokens>
2. 点 **Create Token**
3. 选最下面的 **Create Custom Token**（不要用模板）
4. 填三处：
   - **Token name**：`xk-publish-purge`
   - **Permissions**：`Zone` → `Cache Purge` → `Purge`
   - **Zone Resources**：`Include` → `Specific zone` → `xiaokeqing.cn`
5. **Continue to summary** → **Create Token**
6. 复制那串 token（**只显示一次**），发我，或自己存到 `F:\7AAA\AI\blog\_dev\.cf-token`（该目录已在 .gitignore，不会进仓库）

我拿到后会在 `scripts/publish-*.ps1` 的发布成功后加一步：
```bash
curl -X POST "https://api.cloudflare.com/client/v4/zones/$CF_ZONE/purge_cache" \
  -H "Authorization: Bearer $CF_TOKEN" -H "Content-Type: application/json" \
  --data '{"purge_everything":true}'
```
并用 `curl "https://api.cloudflare.com/client/v4/zones?name=xiaokeqing.cn"` 先取 zone id 写进 `.cf-zone`。

## 二、腾讯云主机安全（云镜）误报

### 现状：**误报源已经被我清掉了，可能你什么都不用做**
- 告警详情是：`Malware:112 report mod: 7 md5 188bacae… path: /runc`、`mod: 0 path: /tmp/srv2-site-receive.sh`。
- 这两个都是**我们自己的部署脚本**（每发布一次就往 `/tmp` 写一个接收脚本、再执行），被云镜按启发式判成恶意文件并隔离。
- 我刚做的清理（srv2 10.0.0.10 / VM-0-10-ubuntu）：
  - `/tmp/*.sh`（05.sh、07.sh、08.sh、10.sh、24.sh、srv2-site-receive.sh 等历史脚本）→ **已全部删除**
  - `/runc` 目录 → **已不存在**（当时是云镜自己解包留下的临时目录）
  - 部署脚本现在写到 `~/.xk-deploy/`，不再碰 `/tmp`
- 因此下一次发布**不应该再触发这条告警**。如果它不再报，就**不要加白名单**（白名单一旦放宽，真恶意文件也会被放过）。

### 如果它还是报（按这个顺序做，别直接关防护）
1. 打开 <https://console.cloud.tencent.com/cwp>
2. 左侧 **入侵防御** → **文件查杀 / 恶意文件**
3. 找到命中记录，点右侧 **处理** → **加白 / 信任**
   - 类型选 **文件路径**
   - 路径填（**只填这两个，别写 `/tmp/*`**）：
     - `/home/ubuntu/.xk-deploy/*`
     - `/runc`
   - 生效主机：只选 `10.0.0.10`
4. 若界面是旧版：左侧 **设置** → **白名单管理** → **文件白名单** → **添加**，同样两条
5. 告警记录里把那次「严重」标成 **已处理 / 误报**（留痕，避免以后被当成真事件讲）

### 不建议做的
- 不要**卸载**云镜 agent，也不要关「实时监控」——这台机器对公网开 443，agent 是唯一能看到落地文件的东西。
- 不要把 `/tmp/*` 整体加白。

## 三、GitHub 推送（现在每次发版靠 bundle 中转）

### 诊断结果（跟你之前的判断不一样，先看这个）
| 位置 | 到 GitHub 的连通性 | 结论 |
|---|---|---|
| 你本机 Windows | `https://github.com` 200 / 2.4 s | 网络通，**只是没有凭据**（`~/.ssh` 里没有任何 GitHub key） |
| srv1（SecAgent 源码） | `https://github.com` 200 但 **8 s+**，`git fetch` 直接超时 | 网络质量差，**不要依赖它拉 GitHub** |
| srv1 匿名只读 | `git ls-remote https://…` 偶尔能成 | 只当参考，不可靠 |

> 结论：**srv1 保持 bundle 中转**（脚本已固化，4~5 MB，几秒），要补的是**你本机推 GitHub**这条链。

### 方式 A：一次浏览器登录（推荐，2 分钟，不用建 Token）
我现在就能把本地 remote 从 SSH 换成 HTTPS，第一次 push 时 Git Credential Manager 会弹浏览器：
1. 浏览器弹出 GitHub 登录页 → 输入账号密码 → **Authorize Git Credential Manager**
2. 授权后凭据存进 Windows 凭据管理器，**以后 push 不再问**
3. 你说一句「可以弹」，我就切 remote 并执行 `git push`，你在弹窗里点一次授权即可

命令（我执行，供你核对）：
```powershell
cd F:\7AAA\AI\blog; git remote set-url origin https://github.com/xiaokeqing/xiaokeqing.github.io.git
cd F:\7AAA\AI\SecAgent\sec-agent; git remote set-url origin https://github.com/xiaokeqing/SecAgent.git
git push origin main      # 此时弹浏览器
```

### 方式 B：Fine-grained PAT（不想弹窗、想脚本化）
1. <https://github.com/settings/tokens?type=beta> → **Generate new token**
2. Token name：`xk-local-push`；Expiration：`90 days`
3. **Repository access**：`Only select repositories` → 勾 `xiaokeqing.github.io` 和 `SecAgent`
4. **Permissions** → `Repository permissions` → **Contents: Read and write**（其余留 No access）
5. **Generate token** → 复制 `github_pat_…`
6. 在 Windows 上执行（一条，token 只落进凭据管理器，不写进仓库）：
```powershell
git config --global credential.helper manager
# 第一次 push 时用户名填你的 GitHub 用户名，密码粘贴这个 PAT
```

### 顺带说明
- 两个仓库的 remote 现在都是 `ssh://git@ssh.github.com:443/…`（走 443 不是 22，因为 22 被墙）。
- 如果你更想用 SSH：需要在本机 `ssh-keygen -t ed25519 -C "xk-local"` 生成 key，再把公钥贴到 <https://github.com/settings/keys>。但**本机当前一个 GitHub key 都没有**，所以这条路还得多一步生成。
- srv1 的 remote 我刚按原样恢复成 `ssh://git@ssh.github.com:443/…`（我试过临时换 https，`git fetch` 超时，已回滚）。
