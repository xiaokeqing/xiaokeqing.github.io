### 3.2 不可达（实测可删）—— `page_intro_m01..m18`，18 条


⇒ `page_intro_m01..m18` 永远进不了候选池（连下游的 `subset.length === 1` 分支都轮不到）。它们是 rev6 之前的页面介绍稿，删掉对任何页面零影响。这 18 条共 **109.424 秒 / 1,247,760 字节 / 1.19 MB**。

## 5. 脚本 `scripts/voice/prune_bank.py`

标准库 only（无 pandas），Python 3.6+，Windows 路径安全。核心语义：

- **默认 dry-run**，只打印分组保留/删除统计与"将删除 N 条 / 释放 X MB"，不写盘；
- `--apply` 才写：先 `bank.json.bak-<YYYYmmdd-HHMMSS>` 备份（两份目标各一份），再写 `.tmp-prune` 后 `os.replace` 原子替换，最后回读校验（能解析、条数对、`totalBytes`/`groups` 与重算一致）；
- 同步重算顶部 `lineCount` / `totalBytes` / `groups`（沿用原键序，清空的组从 groups 里移除），`format`/`generator`/`codec`/`tri`/`expandNote` 等其它字段原样保留，缩进 1 空格、键序不变——**0 改动的 roundtrip 逐字节等于原文件**（已用 `scripts/voice/prune_bank.py` 的 `rebuild()+dump_like_original()` 验证：`roundtrip identical: True`）；
- 双目标：默认同时写 `static/kurisu/voice/bank.json`（真源）与 `public/kurisu/voice/bank.json`（产物），可用 `--bank` 覆盖；
- 安全阀：`REFERENCED_IDS`（内置 12 个硬引用 id + 出处行号）默认**拒绝删除**；保留组被清空时也默认拒绝（`--allow-empty-group` 放行并打印风险）；`--keep-ids` 优先级最高。

参数速查：

| 参数 | 作用 |
|---|---|
| `--dry-run` / `--apply` | 只看 / 真写（互斥） |
| `--keep-groups` | 逗号分隔保留组，**默认全 7 组 ⇒ 空跑 0 删除** |
| `--keep-ids` | 额外强保留 id |
| `--keep-groups-add` | 在默认之外追加保留组 |
| `--drop-ids` / `--drop-sources` | 明确要删的 id / source（如 `synth-rev4`） |
| `--allow-drop-referenced` | 放行删除被硬编码引用的 id |
| `--allow-empty-group` | 放行清空某个组 |
| `--bank` / `--repo` | 自定义目标文件 / 仓库根 |
| `--json` / `--quiet` | 机器可读单行 JSON / 只输出结论 |

已实测的场景：默认空跑（0 条）、方案 A（18 条）、方案 B（50 条）、方案 C（150 条 + 空组风险拦截）、删 `greet_first`/`greet_back` 被拒（exit 1 并列出 1877-1879 出处）、在 `%TEMP%` 副本上 `--apply`（备份 + 写回 + 校验全通过）。

## 6. 风险与自检命令
