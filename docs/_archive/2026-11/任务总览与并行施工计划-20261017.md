## 3. 并行方案：怎么最快做完

### 3.1 关键路径（决定总工期）

```
A1 prompt 瘦身 ──> A2 首句约束 ──> A3 few-shot 检索 ──> A4 情绪标签 ──> A5 语音
                                    （每一个都能独立验收，串行但时长可控）
B2 窄屏修复 ─┐
B1 契约补页 ─┼─> 一次发布（互相不冲突，可合并成一个版本）
B3 口径文案 ─┤
B4 首屏轮换 ─┘
C1 周报 timer ─> C5 靶场重置 ─> C6 靶场接告警面板
```

**总工时**：A 轨道 16h、B 轨道 5h、C 轨道 11h、D 轨道 0.8h ≈ **33h 串行**。
并行后（A 是长链，B/C 可与之交错）**约 18–20h 实际工时**，分 3 个工作日。

### 3.2 五轨并行怎么排（推荐）

| 时段 | 主轨（我一个人做） | 并行轨（子代理/脚本跑） |
|---|---|---|
| 第 1 段 | A1 prompt 瘦身（要反复试，必须我自己盯） | B1 契约补页 + B3 口径文案（子代理改模板） |
| 第 2 段 | A2 首句约束 + A4 情绪标签（同改 prompt 层） | C1 周报 timer 部署 + C5 靶场重置脚本 |
| 第 3 段 | A3 few-shot 检索（要挑语料，最耗时） | B2 窄屏修复 + B4 首屏轮换（前端，子代理并行） |
| 第 4 段 | A5 语音（取决于 E2 决策） | C6 靶场接告警 + C4 取数加速 |
| 收尾 | 发布 + 生产验收 + 文档同步 | 旧博客跳转（C2）、GitHub（C3） |

### 3.3 并行时的三条硬约束（踩过坑）

1. **同一时间只能有一个发布动作**：`publish-site-to-srv2.ps1` 会用临时 worktree 切版本，两个并行发布必然打架。→ 所有修改攒成一个批次发布。
2. **生成器 `_dev/gen-demo-pages.py` 是单点**：所有页面壳改动都落在这一个文件，并行改必须排队（PowerShell 回写会把它写坏，一律用 Python 读改写）。
3. **子代理只准写文件、不准构建/发布/提交 git**：构建会互相覆盖 `public/`，git 会抢锁。

### 3.4 我建议的今晚开工顺序

1. **B1 + B2 + B3 + B4 打包一次发布**（前端，风险低，1 个批次就能把「看起来糙」的小毛病清掉）
2. 然后 **A1 + A2**（后端 prompt，是「像人」的根子，不影响前台展示）
3. **A3/A4** 视你反馈再定
4. C 轨道（周报 timer、靶场重置）可以插空跑，不占用你等待时间

## 5. 给审阅 AI 的核对清单（可直接跑）

```bash
# 1) 线上页面是否都在
for p in / /alerts/ /posts/ /ai/ /test/ /what/ /lab/ /projects/; do
  printf '%-12s ' "$p"; curl -s -o /dev/null -w '%{http_code} %{size_download}B %{time_total}s\n' "https://xiaokeqing.cn$p"
done

# 2) 公开 API 是否真的在返数（只读）
curl -s 'https://demo.xiaokeqing.cn/api/health'
curl -s 'https://demo.xiaokeqing.cn/api/public/audit' | head -c 400
curl -s 'https://demo.xiaokeqing.cn/api/public/honeypot' | head -c 400

# 3) 靶场门禁是否闭环（应 302 → 402/401）
curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' 'https://lab.xiaokeqing.cn/'
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: lab.xiaokeqing.cn' 'http://127.0.0.1:18080/'

# 4) 静态契约与断言（在仓库根目录）
python _dev/check-ssr-contract.py public
bash scripts/assert-build.sh public

# 5) 后端测试用例数（D1 待复核项）
cd ../SecAgent/sec-agent && mvn -o -q test 2>&1 | tail -20
```

复核时请重点看这三件事是否成立：
1. **数字有出处**：页面上每个数字都能在 `/what/` 的「数据从哪来」表里找到端点与字段。
2. **失败可见**：任一公开端点取不到数时，页面显示「未取到」，绝不补样例值（可在断网/改 hosts 下自测）。
3. **门禁是门禁**：靶场在无 Cookie 时必须是 302/401，不能因为加了页面入口就变成公开可访问。
