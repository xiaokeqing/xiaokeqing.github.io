## 二、首屏从 3.4MB 降到 1.2MB：逐笔账（每一笔都可复算）

| # | 改动 | 省下 | 依据 |
|---|---|---:|---|

## 三、修掉的两个真 bug（都不是我引入的，但都在 P0-② 的验收口径里）

1. **点「攻防靶场」会回到主页**（`static/js/app.js`）
   `hugo.toml` 的菜单是 `identifier="labs"` + `url="/#/labs"`，而路由名/模板键是 `range`：
   `parseHash('#/labs')` 取到 `'labs'` → `VIEW_TPL['labs']` 不存在 → 返回 `null` →
   `currentRoute()` 退化成 `routeFromPath(location.pathname)`；在主页 pathname 是 `/` → **home**。
   修法：加 `HASH_ALIAS = { labs: 'range' }`（与 `routeFromPath` 的 `/labs → range` 一致）。
   证据：修前 `#/labs` → `data-xk-render=home`、正文 361；修后 → `data-xk-render=range`、正文 1005。
2. **`data-xk-ssr` 的命名是"labs → range"，不是 bug**（这条我核实后不改）
   · `layouts/baseof.html` L31：`eq .Section "labs"` → `$cur = "range"`（构建期就写 `range`）
   · `static/js/app.js` L338：`/^\/labs/` → `{ name: 'range' }`（运行期也判成 `range`）
   · app.js L455 的 `data-xk-ssr === route` 比较是 **range === range** → **复用成功**
   证据：`_dev/check-ssr-contract.py` 六页全 PASS；真浏览器里 `/labs/` 的 `data-xk-render=range`、
   `[data-xk-pg-run]` 存在、`main.innerText` 1005 字符、控制台 0 报错。
   ⇒ 判据应是"`data-xk-ssr` == app.js 的**路由名**"，不是"== URL 段名"。

## 四、状态机（P0-①）的宿主触发：从"定时器占位"改成"事件驱动"

`hostTriggerEveryMs`（7s 周期插入）**保留为兜底节拍**，另外三类**真事件**接上了，全部记进
`window.__xkSm.hostTimeline`（`{tMs, reason, from, entry}`），reason ∈ voice / emotion / idle / cadence：

| 事件 | 触发点 | 推的入口剪辑 |
|---|---|---|
| `voice` | `Player.speak(phraseId)` 被调用（有台词/音频在播，含切页解说、问候、兜底句） | `speaking_trans` / `speaking_short` |
| `emotion` | `refreshStatus()` 里**真实状态行文本发生改变**（数字都来自真实节点/白名单端点；20s 最短间隔防抖） | `angry_trans`/`sad_trans`/`surprise_trans`/`shy_trans`/`trans_smile` |
| `idle` | 连续待在 `idle*` 类剪辑上累计 > 12s | `closed_eye_trans` |
| `cadence` | 兜底：7s 没别的宿主事件就轮着来（voice→emotion→idle） | 同上三类 |

手动入口（演示/验收）：`KurisuPlayer.hostTrigger('voice'|'emotion'|'idle')`。

**为什么必须这么做**（独立复算的结论，与本轮实测一致）：只按正概率出边走，2000 步只覆盖 9/37 个
节点、全困在 idle 变体簇 —— **她永远不说话、不换表情**。原版就是这么设计的：那 9 条 `prob=0` 的边
是"宿主触发入口"，概率游走**故意**不选它们。

**另外两条口径**（都核过原始数据）：
· 出边概率和 ≠ 1 的两个节点（`trans_standby`=0.4、`speaking_med`=**1.2**）**是原版数据本身**，
  不是提取错误：`_kurisu-full/meta_json/graph_config.json` 逐边对照 `statemachine.json` → **87/87 条
  概率完全一致（0 处不符）**，`speaking_med` 的三条出边原文就是 0.4/0.4/0.4。游走**按出边和归一化**。
· 状态机在主页**默认关**（`data-xk-kurisu-sm="on"` 不写；`layouts/partials/xk-kurisu-stage.html`
  里留了开关和原因）。原因：37 段 medium 全量 48MB，一次 60 秒访问会多拉 ~28MB（已加 6MB 带宽闸）。

## 五、**没做**的 / 需要站主决定的（如实）

1. **"把 demo 外壳 markup 逐页搬进生产页"这件事我没做，也不建议照原样做。**
   事实三条：
   · `docs/demo-内容页外壳.html` / `layouts/partials/xk-views/v-*.html` 里的 `v-monitor` 等**带着演示数字**
     （`1284 告警 / 96 拦截 / 37 蜜罐 / 45.155.x.x` …），原样搬进生产页会直接违反本站"数字只来自真实
     只读接口、取不到写读不到"的纪律；
   · 线上六页**已经是同一套设计**（大屏面板 / 暗色玻璃 / CRT 场景 / 左侧导航），只是用站点自己的
     `xk-*` 类名 + 真实数据节点实现的 —— 上一轮第 11/12 轮就是干这个的；
   · 真要把 demo 的 markup 搬进来，等价于"重新实现一遍站点已有的数据层"（违反"不要另写第二套"）。
   ⇒ 我做了**视觉层接线就绪**：`assets/css/xk-app.css`（全量 `#xk-app` 前缀化，383 行）已移出
   `assets/css/extended/`（不再被总样式表自动打包，省掉每页 26KB 惰性 CSS）；`layouts/partials/head.html`
   里加了一条**按页生效**的 `<link>`：页面 front matter 写 `xkAppShell: true` + partial 里放
   `<div id="xk-app">` 就会只在该页加载。**要不要真搬、搬哪几页，需要站主拍板。**
   我把这条一致性也写进门禁了：产物样式表里 `#xk-app` 规则数 ⇔ 页面上 `#xk-app` 根元素，
   要么都有、要么都没有（现在两者都是 0 = 未接线，不是坏）。
2. **speaking_long 的 hi 档没发**：它的 2 页合计 6.12MB，加上后总资产 83.8MB **> 80MB 上限**。
   要发就把上限提到 85MB（或先重编码）。
3. **语音音色不是桐莉栖**：本机没有云端 TTS 的 Key、也没装 2.77GB 的 GPT-SoVITS 权重与推理环境，
   所以 L1 用的是 **Windows SAPI(zh-CN 女声 Huihui)** 离线合成 —— 链路（音频 + 包络 + 门控 + 口型）
   全部跑通，**换音色 = 换这批 wav + 改 bank.json 的 url，播放器一行不用改**。
   另：Opus 编码器本机没有（ffmpeg/opusenc 全缺）→ 发的是 8kHz/16bit PCM（一句 ~72KB，
   与规格里 Opus 的 30~80KB/句同量级）；第一版发的 µ-law 被 Chrome 拒播（`NotSupportedError`），已换掉。
4. **L2（自由回答的语音）没接**：没有 `/api/public/tts` 的 Key；`speakImpl` 里留了同一条包络契约的
   接入位（有 endpoint 就走，没有就如实返回 `TTS_DISABLED`/`NO_SUCH_LINE`）。
5. **P1 的其余项**（房间活动位、中景眨眼、情绪焊真实告警严重度、`data-xk-skin` 接科技模式开关、
   定时器/rAF 清理统一、favicon）本批**没做**；`speaking` 的 `idle→idle1` 加权插播也没做。
