## 一、已知弱点与取舍

| # | 现象 | 影响 | 为什么暂时这样 | 可能的改法 |
|---|---|---|---|---|
| 1 | 手机（iOS/微信）画质差、偶发"脸空白" | 移动端观感 | 图集单张 34~53MB 解码，系统内存压力下位图被丢弃；透明 VP9+alpha 在 iOS 不可用 | 已做手机小档 + 解码失败重试降档；可再考虑按需切片图集 / HEVC+alpha |
| 2 | 口型"同步"未达标 | 简历里"同步"一句尚不能写 | 实测 lag 70~100ms、r≈0.51；包络与音频是开环 | 显式对齐补偿 + Web Audio 时钟驱动 + 验收脚本；目标 lag ≤40ms |
| 3 | 评测样本不足（问答只采 4/40） | 要点命中率等**不可作基线** | 公开池 30/日、评测池 60/日 | 扩题库 + 提高采样；真基线还需会话标识与多轮题 |
| 4 | 额度偏紧（公开 30/日、每 IP 6/分） | 访客易撞额度 | 个人档位，防刷 | 分层池（已有 public/eval/self 三池）；按行为分级或加验证码 |
| 5 | 无多轮记忆、公开面禁工具调用 | 追问会断片、不能自取实时数据 | **刻意**：最小 AI 自主权 + 可审计 | 登录自用面已支持 3~5 轮；公开面工具调用需白名单 + 审计设计 |
| 6 | 单机单点（srv1 2vCPU/1.87GB 全栈） | 无冗余 | 个人成本 | 关键路径（静态站/隧道）已在 srv2；后端可加只读副本 |
| 7 | srv2 上行实测 271~338 KB/s | 大文件上传慢 | 云主机带宽 | 图片走 CF R2/图床；发布走差量 |
| 8 | 未备案 | 国内访问与 CDN 受限 | 成本/流程 | 需要时再办 |
| 9 | 内容后台刚起步 | 只能本机改 md 再发布 | 单人使用 | 正在做：Git 即后台（上传/在线小改/列表/图片压缩 + 令牌鉴权） |
| 10 | 前端曾"花而不清"（R2 批） | 观感下降 | 优化方向偏装饰 | 正在收敛：删浮卡/滚动行/count-up，骨架屏只留慢端点 |

**历史真缺陷（都已修，价值在于"发现方式"）**：发布幂等只比 `index.html` 导致"假成功" · 最终分发文件真峰超标（只保采样峰） · 宿主情绪名静默演错表情 · 自由文本字段内网地址泄漏 · 手机布局视口被撑到 620px 致固定导航跑出屏幕。

## 二、性能与成本现状

- 首屏预算 1650KB：主页 925 / 监测 270 / 笔记 270 / AI 85~98 / 测试 270 KB（warm 与 cold 均 0 超标）
- 资源：透明视频 40 组 **9.54MB**（替 71MB 图集）· 手机不再拉 hi 图集（改前单次 1,028,055B / 解码 38.8MB → 0）
- 语音：原声 **484 条 / 46.2MB** + 自合成 **150 句 / 10.95MB**（真峰全量 ≤ −1.5 dBTP）
- 云 TTS：免费额度已用 **173 / 10,000**（≈0.026 元）· 两台服务器实例费 `[待核对]`

## 三、开放问题（需要决策）

1. 要不要上 CDN / 对象存储（图片与语音）？
2. 要不要为移动端做更清晰档（代价：解码内存与体积）？
3. 公开面要不要开**只读工具调用**（能答实时数据，但要白名单 + 审计）？
4. 要不要**多轮记忆**（体验提升最大，但要会话存储与并发设计）？
5. 要不要备案（决定国内加速与合规面）？
6. 语音要不要改成"**念日语 + 中文字幕**"（中文念读已证不可行）？

## 四、请优化什么（逐条回答即可）

**A. 架构与数据面**
- A1 只读端点已 9~12 个：是否需要统一的"数据契约层"（版本化 schema）以降低前端耦合？
- A2 真实攻击数据的**聚合与故事线**算法还有哪些可提升（去重、归因、跨源关联）？
- A3 三池额度与限流策略是否合理？有没有更好的公平性设计？

**B. 前端与移动端**
- B1 手机端"糊"的根因是源分辨率放大 2.5×：切片图集 / 按需档位 / 视口自适应，哪种更值？
- B2 CRT 场景在窄屏必然按高度放大：letterbox 还是自适应构图？
- B3 角色交互（点头像/长按/语音开关）还可怎么做得更自然？

**C. 性能与体积**
- C1 透明视频与图集如何取舍（体积 / 内存 / 兼容性）？
- C2 首屏与空闲预取的策略还能怎么优化（预取命中率 vs 浪费）？
- C3 语音资源（57MB）如何按需下发？

**D. 安全加固**
- D1 公开面提示词注入护栏还能怎么加强？
- D2 出口闸门（IP/凭据/自由文本）是否有遗漏的字段类型？
- D3 令牌登录（后端口令）相比 Cloudflare Access，安全上有哪些必须补的（限速/轮换/审计）？

**E. 工程效率**
- E1 生成器范式（改产物先改生成器）是否值得保留，还是该迁移到模板/组件？
- E2 三道门禁还缺什么（资产引用完整性？冷缓存？视觉回归？）
- E3 一次一批 + 精确 ref + 三档回滚的流程还能怎么压缩时间？
