## 一、未备案阻断的证据（可直接引用/截图/贴给客服）

### 1.1 访客视角（站主本机 Windows，2026-10-15 20:31 实测）

```bash
# ① HTTP/80 直连 EIP + 真域名 Host → 被 302 拦到腾讯云 webblock 页
> curl.exe -sS -i --max-time 20 -H "Host: xiaokeqing.cn" http://{公网IP-腾讯云}/
HTTP/1.1 302 OK
Connection: Keep-Alive
Location: https://dnspod.qcloud.com/static/webblock.html?d=xiaokeqing.cn
# ② HTTPS/443 直连同一 IP（--resolve 强制 SNI=xiaokeqing.cn）→ 连接被重置
> curl.exe -sS -o NUL -w "code=%{http_code}`n" --max-time 25 --resolve xiaokeqing.cn:443:{公网IP-腾讯云} https://xiaokeqing.cn/
code=000        curl: (35) Recv failure: Connection was reset
# ③ 对照：https://direct.xiaokeqing.cn/ 同样 code=000（Connection was reset）
```

**结论（访客视角）**：未备案域名对 `{公网IP-腾讯云}`（srv2 公网 IP）的 80/443 直连被腾讯云拦截 —— 80 走
`302 → dnspod.qcloud.com/static/webblock.html?d=<域名>`，443 直接 RST。这与 `docs/服务器配置-详细版-给外部AI.md` §4 的旧铁证一致 ✓。

### 1.2 服务器视角（srv1 / srv2 自测，2026-10-15 20:30~20:32 实测）

```bash
# srv1（阿里云杭州）→ {公网IP-腾讯云}
$ curl -sS -i -H 'Host: xiaokeqing.cn' http://{公网IP-腾讯云}/ | head -6     → HTTP/1.1 301 Moved Permanently / Server: nginx / Location: https://xiaokeqing.cn/
$ curl -sS -o /dev/null -w 'code=%{http_code} size=%{size_download}\n' --resolve xiaokeqing.cn:443:{公网IP-腾讯云} https://xiaokeqing.cn/
  → code=200 size=33213
# 对照：用一个"根本不存在备案"的假 Host 也一样 301（说明 srv1→srv2 这条路径上根本没有拦截发生）
$ curl -sS -i -H 'Host: none-filed-test-xyz.cn' http://{公网IP-腾讯云}/      → HTTP/1.1 301 Moved Permanently / Location: https://none-filed-test-xyz.cn/
# srv2 自测自己：80 → 301、443 → 200（0.058s，本机回环）——同样不复现拦截
```

**结论（服务器视角）**：**同一条拦截，从 srv1/srv2 发起时并不复现**。⇒ 两个直接推论：
1. 判断"站点能不能打开"必须用**访客视角**；服务器侧测试会给人"一切正常"的错觉 ✗（这也是 ①②两项监控的探测点选择依据）。
2. 本文 §1.1 的证据比服务器侧的证据更接近真实用户遭遇，提交备案/咨询客服时**用 §1.1 的截图**。
   （机制上"为什么源不同结果不同"本轮**未做定论**，不编解释 ✗；如需给客服一句话，就说"从访客网络访问被拦、从云主机访问不被拦，请确认拦截口径"。）

## 三、现在走 CF 隧道的"临时方案"（怎么用它扛过备案期）

### 3.1 现状（已经在跑，可用 ✓）

```
方案：apex/www 的 DNS 用 Cloudflare **Tunnel `secagent-static`**（橙云）→ cloudflared 出站 → srv2 127.0.0.1:18080 → /opt/secagent/site
为什么这么切（2026-10-14）：未备案 ⇒ 境内直连被拦（§1.1）；GitHub Pages 9.6~17 KB/s、CF 隧道 0~10.7 KB/s、直连 271~338 KB/s
代价：走 CF 免费链路明显更慢（本轮 srv1 实测首字节 1.7~6.5s/页）；换来的是"站能打开" ✓
维护要点：不要动 `direct.xiaokeqing.cn` 的 A 记录（留给调试与备案核验）；`static.*` 只是 248B 占位页，别当主站备份 ✗
```

### 3.2 ⚠️ 与备案的冲突点（**这是本材料最需要站主拍板的一条**）

```
备案（接入备案）的核心是"域名解析/接入到该接入商（腾讯云）的境内资源"。
而 CF 隧道要求该域名由 Cloudflare 接管（橙云 = 解析到 Cloudflare 的 IP/CNAME，公网看不到 {公网IP-腾讯云}）。
⇒ **提交备案前，apex（与 www）必须从"Tunnel 橙云"切回"A {公网IP-腾讯云} / DNS only 灰云"**，
   否则腾讯云/管局做接入信息核验时，解析到的不是腾讯云的 IP，很可能核验不过。
⇒ 切回灰云后：境内直连会被"未备案"拦（§1.1 依旧拦），也就是**备案审核期间网站对外可能不可访问**。
   官方对"备案期间网站是否必须关闭/放合规占位页"有明确要求，但**本轮未逐字取回** ⇒ 以提交时
   备案小程序/控制台的提示与省管局要求为准 [待确认]。常见做法是：只挂一个不含任何内容的合规占位页，或直接不解析。
⇒ 备案通过后要不要切回 CF 隧道？**建议先问客服再决定**：备案抽查看的是"接入信息与备案信息一致"，
   长期跑在 CF 后面可能与备案登记的接入 IP 不一致（本轮不擅自下结论 ✗）。速度对比摆在 §3.1，站主二选一。
```
