## 3. 交接者必须知道的 6 条机制

1. **双轨**：站点 SPA（app.js）与六页 demo 是两套。六页由 `_dev/gen-demo-pages.py` 从 `docs/demo-*.html` **重新生成**——
   **改 layouts/* 必须同步改生成器并重跑**；生成器锚点必须匹配 demo 原文（不是产物文本）；补丁有先后依赖（L1/CRT 补丁要在 T5.6 引用的代码之后）。
2. **动画链**：CLIPS 四剪辑（opening/idle/speaking/thinking）canvas 逐帧。
   `xkClipIm(name)`：先 peek hi 缓存（**绝不能 img() 创建——创建即发请求**），未就绪兜底 boot 档，hi 到位按同一帧号无缝接力；
   boot 档期间 opening 走 `fi % 24` 循环等 hi，不当开场播完。门禁 home 检查点已是 9s（序列 ~5.5s 落定）。
3. **语音链**：bank.json 12 句 GPT-SoVITS v3 日语 + 中字幕；手势门控（首次 pointerdown/keydown 解锁）；XKV 状态可观测。
4. **发布链**：push ≠ 上线。`scripts/publish-site-to-srv2.ps1 -FromRef HEAD`；**scp 报 `pipe: Unknown error` 是 Windows OpenSSH SFTP 老毛病** ⇒ 走手动通道：
   `scp -O` 传 tar → `install` 接收脚本 → `sudo -n bash /opt/secagent/scripts/srv2-site-receive.sh <tar>`（原子切换+失败自动回滚）。
5. **门禁三件套 + 方法论**：改完必跑三道门禁；对"拦截型"逻辑（如 T5.2）必须**故障注入**验证真能拦（今天它抓到了一个 const 赋值 bug）。
