### 3.1 一个必须写下来的环境限制（跨域）

本机预览是 `http://127.0.0.1:8790`（源 = `127.0.0.1:8790`），而后端 CORS 白名单里**没有**这个源：

```
GET https://demo.xiaokeqing.cn/api/public/overview   Origin: http://127.0.0.1:8790
  → 200，但响应**不带** access-control-allow-origin          （curl 实测）
GET …/overview   Origin: https://xiaokeqing.cn
  → access-control-allow-origin: https://xiaokeqing.cn        （curl 实测）
POST …/api/public/ask  Origin: https://xiaokeqing.cn
  → 200 + 真实响应体（本批的"额度用尽"夹具就是从这条取的，逐字）
```
⇒ 浏览器里从 `127.0.0.1:8790` 真发 POST 会被浏览器按 CORS 拒掉（**后端口径如此，不是前端 bug**）。
所以 ② 的前端行为用 **CDP Fetch 伪造响应**验证（上面 19 项）；"用真实响应体"这条用 **curl 服务器侧**单独证明（夹具逐字来自真实响应）。
线上 `https://xiaokeqing.cn` 是**被允许的源**，所以线上这一条链路成立。

### 3.2 本批踩到并记住的三个坑（都已修，写下来防复发）

1. **`__xkAdmin.fetch` 里用 `this.allowed()` 会炸**：调用方把 `fetch` 拆出来当变量（`var adminFetch = __xkAdmin.fetch`）时 `this === undefined`
   ⇒ `TypeError: Cannot read properties of undefined (reading 'allowed')`（真浏览器捕获）。改成闭包引用 `admin` 对象。
2. **闸门不要 `return`**：输入栏的挂钩 `window.__xkAskBar` 必须在**任何情况下**都存在，否则"本页加载之后才开隐蔽入口（5 次连点头像）"没有落点。
   现在：先挂挂钩 → 末尾 `poke()` 做判定（未登录返回 false，什么都不动）。
3. **窄屏 CSS 顺序**：`.xk-askbar` 基础规则写在 `@media (max-width:980px)` **之后**才对 —— 反了会被基础规则压掉
   （实测 phone375 栏左边缘 −111px、字号仍 13px、与 `.dock` 重叠）；另外 ≤980px 时 `.dock` 是**底部横排**，输入栏要 `bottom:70px` 让到它上面。
