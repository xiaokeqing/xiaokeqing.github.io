# 窗口分工规范（多 AI 并行时怎么不打架）· 2026-10-15

> 用途：你同时开 3~4 个 AI 窗口干活时的**分工与纪律**。每个新窗口开工前先读这份 + §一 的表。
> 核心一句：**按"会碰哪些文件"切窗口**，不是一任务一窗口、也不是一个窗口跑全部 ✗

---

## 二、三条防打架规则（务必转告每个窗口）

```
① **同一文件同一时间只有一个窗口能改** ✗
   开工前必跑 `git status --short`：若看到别人正在改的文件 ⇒ **不要碰** ✓，先做你清单里的别的
② **提交纪律**
   · 只 `git add` 自己的路径 ✗（禁 `git add -A`）
   · **不许 rebase / 不许 force push / 不许改别人的提交** ✗
   · 提交信息写清：任务号 + 做了什么 + 验收证据 ✓
③ **发布唯一** ✗
   · `push` ≠ 上线；上线要跑 `scripts/publish-site-to-srv2.ps1`
   · **发布只能由 C 窗口（或你指定的"发布官"）做** ✓ —— 两个窗口同时发布会说不清"线上是哪版" ✗
```

## 三、每个窗口的固定开场白（模板，复制即用）

```
你负责：**<T编号 + 任务名>**，只做这一件，别顺手改别的 ✗
先读（顺序别变）：
  ① docs/项目总体规划-MasterPlan-20261015.md
  ② docs/待办-施工任务清单-给执行AI.md（看 §15/§16/§18 里这条的状态）
  ③ docs/总账-决策与事实台账-20261015.md（口径与数字，别重复问）
  ④ docs/窗口分工规范-20261015.md（你只能碰"一、表"里你的那几类文件 ✗）
开工前：`git status --short` 必须干净（或有别人在改的文件就别碰那些 ✗）
过程中：改 `layouts/*` 必同步 `_dev/gen-demo-pages.py` ✗；不许出现假数字 ✗；不许加第三方请求 ✗
交付前：跑三道门禁（assert-build / gate-firstscreen / check-ssr-contract）→ 只 add 自己的路径 → 提交
收尾：把状态写进 **`docs/状态-<窗口名>.md`**（见 §四 ✓），**不要**改任务清单主文件 ✗
不要发布 ✗（发布由 C 窗口统一做）
```

## 四、状态回写（避免多窗口抢同一个文档 ✗）

```
每个窗口只写**自己那一个**状态文件：
  docs/状态-A-评测.md ｜ docs/状态-B-声音.md ｜ docs/状态-C-站点角色.md ｜ docs/状态-D-素材产线.md ｜ docs/状态-E-文档设计.md
格式（四行就够 ✓）：
  任务号 / 状态（进行中·已完成·卡住）/ 改了哪些文件 / 验收证据（命令输出或截图路径）/ 下一步
⇒ 每天收工（或任务完成）时更新一次 ✓；**任务清单主文件（§15/§16/§18）只由规划侧统一合并** ✓
   这样 5 个窗口也不会同时改同一个文件 ✗
```

---

## 五、冲突与异常怎么处理

```
· 发现别人正在改你也要改的文件 ⇒ **停手**，在状态文件里写一句"我需要的文件 X 被窗口 Y 占用"✓，然后等你/规划侧裁决
· 需要跨窗口协作（例如 B 的语音要 C 的页面用）⇒ 写进各自状态文件 + 在 `docs/状态-*.md` 里注明接口约定，
  **不要直接改对方的文件** ✗
· 线上出问题 ⇒ 秒级回滚：把 srv2 `/opt/secagent/site` 软链指回上一版 release ✓（发布脚本保留最近 4 版）
· 谁的活卡住超过约定时间 ⇒ 在状态文件写清卡点，由规划侧决定换人/换方案 ✓
```

## 六、每天收工前的三件小事（10 分钟，能省掉一堆扯皮）

```
① 每个窗口更新自己的 `docs/状态-<窗口名>.md` ✓
② 确认 `git status` 里**没有你忘了提交的东西** ✓
③ 规划侧把各窗口状态合并进任务清单（§15/§16/§18）+ 给出下一天的任务分配 ✓
```
