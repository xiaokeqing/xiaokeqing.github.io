## 0. 一句话方案

**服务器生成一串 ≥32 字符的随机令牌 → 只把 `sha256(令牌)` 写进 srv1 的 `.env` →
站主手动把明文粘进浏览器 localStorage → 请求带 `X-User-Token` →
后端恒定时间比对哈希，命中即走「自用池」（额度软上限 500/日，只提醒不停）。**

明文令牌**任何时刻都不进仓库、不进数据库、不进日志、不进前端代码**。

## 1. 令牌形态与存放（红线：明文绝不入库）

| 项 | 取值 | 理由 |
|---|---|---|
| 令牌长度 | **≥32 字符**（建议 48，`secrets.token_urlsafe(48)` 生成） | 32 字符 ≈ 192 bit 熵，暴力枚举不可行；短于 32 直接**拒绝启用**（fail-closed） |
| 字符集 | `A-Za-z0-9-_`（URL-safe base64） | 可安全放进请求头 / localStorage，不用转义 |
| 服务器存什么 | **`APP_USER_TOKEN_SHA256` = 小写十六进制 sha256(令牌)** | 服务器只持有"能不能对上"的判据，拿到 `.env` 也**推不回**明文 |
| 不存什么 | ✗ 明文、✗ 明文副本、✗ 明文前缀、✗ 令牌的日志片段 | 明文只出现在站主自己的密码管理器里 |
| 轮换 | 改 `.env` 里那一行 → `--force` 重建容器 → 旧令牌立刻失效 | 不需要换镜像、不需要改代码 |
| 吊销 | 置空 `APP_USER_TOKEN_SHA256=` → 登录面**整体关闭**（见 §8 回滚） | 语义级回滚，秒级 |

**生成命令（在 srv1 上跑，本机不落明文）**：

```bash
# 1) 生成明文令牌（只在终端显示一次，请立刻存进密码管理器）
TOKEN=$(python3 -c 'import secrets;print(secrets.token_urlsafe(48))')
echo "明文令牌（只显示一次）: $TOKEN"
# 2) 只把哈希写进 .env（明文不进 .env、不进 shell history 以外的任何文件）
HASH=$(printf '%s' "$TOKEN" | sha256sum | cut -d' ' -f1)
sed -i '/^APP_USER_TOKEN_SHA256=/d' /opt/secagent/.env
echo "APP_USER_TOKEN_SHA256=$HASH" >> /opt/secagent/.env
unset TOKEN HASH
```

> 纪律：**任何日志、任何工单、任何文档都不写明文**。交付件里只出现「长度」与「哈希前 8 位」。

## 2. 传递方式（前端手动粘贴 ⇒ localStorage ⇒ 请求头）

```
站主在浏览器打开隐蔽入口（?admin=1 或连点头像 5 次）
   → 点 👤 → 弹出输入框 → 粘贴令牌 → 前端存 localStorage['xk-user-token']
   → 之后每个自用请求自动带请求头  X-User-Token: <令牌>
```

* `X-User-Token`：**新增的独立请求头**，与既有的 `X-API-Token`（系统级）、
  `Authorization: Bearer`（登录会话 / 评测）**互不覆盖、互不推断**。
* 前端可以做的一件事：把令牌在**本地**校验成 `sha256` 后展示前 8 位（可选），
  但**绝不**把令牌发给除 `xiaokeqing.cn` 以外的任何域。
* ✗ **绝不允许**：把令牌写进任何 `.js` / `.html` / Hugo 模板 / 构建产物 / 环境变量文件里的前端侧文件。

### 2.1 前端契约（站点线照此实现，逐字为准）

| 项 | 约定 |
|---|---|
| 请求头名 | `X-User-Token` |
| 请求头值 | 站主手动粘贴的令牌原文（≤200 字符；超长后端直接 401，不做截断） |
| 本地存放 | `localStorage['xk-user-token']`（关闭标签页仍在，便于站主长期自用）；**不写 Cookie**（避免被其他域名/边缘缓存带走） |
| 登录态显示 | 已有 `sessionStorage['xk-admin-ui']=1` 控制按钮可见性；**新增** `localStorage['xk-user-token']` 存在 ⇒ 登录态文案「已登录 · 自用模式」 |
| 清除 | 点 👤 可在菜单里「退出登录」= `localStorage.removeItem('xk-user-token')`（本地即可，不需要请求后端） |
| 校验时机 | 存令牌后立刻调 `GET /api/user/status` 做一次确认（**这是唯一会 401 的探针**），401 就提示「令牌无效，请重新粘贴」 |

## 3. 校验（恒定时间 + 每 IP 限速 + 失败封禁）

```
请求 → ApiTokenInterceptor
        ├─ 路径以 /api/user/ 开头？
        │    ├─ 否 → 走既有逻辑（评测 / 会话 / 系统 Token / 白名单）
        │    └─ 是 → UserTokenService.check(ip, X-User-Token)
        │           ├─ 本 IP 处于封禁窗口       → 429 + Retry-After，记一条审计
        │           ├─ 登录面限速超限（默认 10/min） → 429 + Retry-After
        │           ├─ 令牌缺失                 → 401 + 计数一次失败
        │           ├─ 令牌长度 != 64 或非十六进制 → 401（先判形状，不做哈希）
        │           └─ sha256(令牌) 恒定时间比对哈希
        │                 ├─ 命中 → 放行，打标 SelfIdentity，清失败计数
        │                 └─ 未命中 → 401 + 计数一次失败（≥10 次/10 分钟 ⇒ 封 10 分钟）
        └─ 未配置 APP_USER_TOKEN_SHA256 ⇒ 一律 401 + reason=USER_LOGIN_DISABLED（默认关闭，fail-closed）
```

* **恒定时间比较**：逐字节 XOR 累加（与既有 `ApiTokenInterceptor.constantTimeEquals`
  和 `EvalIdentity.constantTimeEquals` 同一写法），**不**用 `String.equals`。
* **为什么先比长度再比内容**：sha256 十六进制恒为 64 字符；长度不符直接拒，
  省一次哈希，也不泄露"前缀对了几位"。
* **登录面也限速**（站主明确要求）：`/api/user/status` 与 `/api/user/ask` 共用
  一个「每 IP 每分钟」窗口，默认 **10 次/分钟**（独立桶，不复用公开面 6/20 次/分钟，
  避免"为了页面刷新率调公开面"顺手放宽登录面）。
* **失败计数与短时封禁**：每 IP 滑动窗口计数，**10 分钟 ≥10 次失败 ⇒ 封 10 分钟**
  （窗口与阈值均可配）。成功一次即清空该 IP 的失败计数。
* **不落原文**：任何日志/审计只写 **IP 掩码 + 结果 + 时间**，绝不写令牌、不写其前缀、不写其哈希全文。

## 4. 分层：`X-User-Token` 命中 ⇒ 自用池（软上限，只提醒不停）

| 维度 | 公开面（访客） | 评测身份 | **自用池（本方案）** |
|---|---|---|---|
| 凭据 | 匿名 | `APP_EVAL_TOKEN`（Bearer） | `X-User-Token` |
| 额度池 | `app.quota.public-daily-limit` = 30 | `eval-daily-limit` = 60 | **`app.quota.self-daily-soft-limit` = 500** |
| 超额行为 | **硬停**（429/如实告知额度用尽） | **硬停** | **只提醒不停**（软上限） |
| 计数文件 | `data/model-quota-public.json` | `data/model-quota-eval.json` | **`data/model-quota-self.json`** |
| 入口字符上限 | 1200（body 4000） | 无（内部界面） | **4000** |
| 入口总预算 | 25 s | 25 s（`/api/chat`） | **60 s** |
| `max_tokens` | 2000（`app.llm.max-tokens`） | 2000 | **4000**（见 §4.2 落地说明） |
| 工具调用 | ✗ 一律不调（只解释） | ✗ 只模拟不下发 | **只读工具允许；处置类仍不允许**（见 §4.3） |
| 3~5 轮窗口 | 无（一次性提问） | 由 `/api/chat` 会话管 | **✓ 独立窗口（§5）** |

### 4.1 软上限的确切语义

* 达到 500 次/日：**继续服务**，但在响应里带
  `quota.softLimitReached=true` + `note`「今日自用调用已达软上限 500 次，仍会继续服务（不硬停）」，
  并在服务端日志打 **一次** WARN（每天一次，不刷屏）。
* 为什么不做硬停：站主原话是「自用额度不设硬上限（或软上限如 500/日，**到点提醒不硬停**）」；
  且自用池是站主自己的账，硬停只会把站主挡在门外，而它并不防第三方（第三方根本不该有令牌）。
* 仍然**独立记账**：公开面被刷爆不会吃掉自用额度，自用额度也不会被公开面占用
  （沿用既有「三本账」纪律，本方案只是加第四本）。

### 4.2 `max_tokens = 4000` 的落地说明（诚实标注）

现有模型出口的 `max_tokens` 来自**全局**键 `app.llm.max-tokens`（当前 2000，
T25 定的硬天花板）。自用池要 4000 只有两条路：

* **(a) 全局提到 4000** —— 一行配置，但**同时放宽公开面与评测**（它们共用同一个键）
  ⇒ 与「公开面成本护栏不放宽」冲突，**本方案不采用**；
* **(b) 按身份下发 `max_tokens`** —— 在 `LlmProvider` 出口读「当前身份」（`SelfIdentity`）决定取值。
  这是**正确的**做法，但要改两个 provider 的请求构造（DashScope / DeepSeek），
  属于**第二步（低价窗口）**的改动范围。

**本批次（编译期就绪部分）的处理**：把 `app.user.max-tokens: 4000` 配置键与
「自用池按身份取 max_tokens」的读法**先钉进 `SelfPoolPolicy`**，
并在 provider 侧留 **TODO(SELF-MAX-TOKENS)** 注释指向本节的 (b) 方案；
**不改** `app.llm.max-tokens` 的全局值 —— 宁可自用池暂时与全局一致（2000），
也不为了让自用池变宽而顺手放宽公开面。**这是设计决策，不是遗漏**（不扩 scope）。

### 4.3 工具调用（只读允许 / 处置不允许）

* 站主要求：「允许**只读工具调用**（若开关存在；不存在就留 TODO 不扩 scope）」。
* 现状盘点（已核对源码）：
  * 公开身份有**双向拦截** —— 编排层 `MultiAgentCoordinatorImpl.runResponder()`
    在 `isPublicRequest()` 时直接分叉到「只解释」；工具层 `QueryLogsTools` /
    `QueryMetricsTools` / `InternalDocsTools` 各自在入口处拒绝公开身份。
  * 评测身份有**单向拦截** —— `MultiAgentCoordinatorImpl` 在 `isEvalRequest()` 时分叉到「只模拟」。
  * **没有**现成的「只读工具白名单开关」这种东西。
* 本批次落地：自用池身份**不加**新的工具限制（＝比公开面宽、与站主内部会话同档），
  并在代码里留 **TODO(SELF-READONLY-TOOLS)**：将来若要「自用池只许只读工具」，
  应在 `MultiAgentCoordinatorImpl` 的 RESPONDER 分叉处加第三条分支，
  **而不是**在工具类里逐个加判断（那正是公开面那次的失败模式：记得加的加了、忘了的没加）。
* 明确**不在本批次**做的事：不新增「只读工具白名单」配置、不改既有工具类。

## 5. 3~5 轮对话窗口（仅登录面启用）

| 项 | 取值 | 说明 |
|---|---|---|
| 轮数上限 | **5 轮**（配置 `app.user.conversation.max-rounds:5`，允许 3~5） | 「轮」= 一问一答算一轮（与既有 `MAX_WINDOW_SIZE` 的"消息对数"口径一致） |
| 过期 | **30 分钟**（配置 `app.user.conversation.ttl-minutes:30`） | 超过即当作新会话，历史不进上下文 |
| 标识 | 请求体带 `conversationId`（前端生成，如 `xk-<随机串>`） | 不带则后端自动生成一个并**在响应里返回**，前端存 sessionStorage |
| 存储 | **进程内** `ConcurrentHashMap`（`UserConversationStore`） | 重启即清（可接受：自用池单人使用；不引入 Redis/DB） |
| 上限 | 最多跟踪 200 个会话，超出按最久未访问淘汰 | 防"伪造 conversationId 撑内存" |
| 隔离 | **只服务登录面**：公开面（`/api/public/ask`）不带窗口、也不读本存储 | 匿名访客永远没有多轮记忆，这是成本护栏的一部分 |
| 历史注入 | 取最近 ≤5 轮，按时间顺序传给 `OrchestrationService.run(question, history, deadline)` | **复用既有编排链路**，不另写一套 |

**为什么不给公开面也开窗口**：多轮 = 更多上下文 token = 更多成本，而公开面是
匿名可达的；「匿名 + 无限记忆」是成本漏洞，不是体验优化。

## 6. 接口（管理面 `/api/user/*`，与公开面代码路径完全隔离）

| 方法 | 路径 | 作用 | 成功 | 失败 |
|---|---|---|---|---|
| GET | `/api/user/status` | 登录探针：校验令牌并回显自用池额度状态 | 200 `{code:200, data:{authenticated:true, pool:"self", quota:{limit,used,remaining,softLimitReached}, conversation:{maxRounds, ttlMinutes}}}` | 401 `{code:401, reason:"TOKEN_INVALID"}` / 429 `{code:429, reason:"LOGIN_RATE_LIMITED"` / `"IP_TEMPORARILY_BANNED"`} |
| POST | `/api/user/ask` | 自用提问（复用编排链路 + 3~5 轮窗口） | 200 `{code:200, data:{answer, conversationId, round, maxRounds, quota, generatedAt, generated, citations}}` | 401（同上）/ 429（同上）/ 400 `{reason:"BODY_TOO_LARGE"}` / 500 `{reason:"MODEL_UNAVAILABLE"}` |
| POST | `/api/user/logout` | 语义占位（令牌在客户端，服务端无会话可销） | 200 `{code:200, note:"…"}` | 401 |

**代码隔离（硬约束）**：

* 新代码全部落在 **`org.example.selfapi`** 新包（`SelfApiController` / `UserTokenService` /
  `SelfIdentity` / `UserConversationStore` / `SelfPoolPolicy`），
  **不往 `org.example.publicapi` 里加一个字符** —— 那个包有一条构建期隔离测试
  （`PublicApiIsolationTest`：出现处置/管理能力符号即**构建失败**），
  把登录面混进去会同时破坏「公开面只读」的证明与本方案的隔离证明。
* 新增一条**对称的隔离测试**（`SelfApiIsolationTest`）钉住本包**不得引用 `publicapi` 包**
  （反向也隔离：两条面各改各的，谁也别顺手调谁的口径）。

## 8. 配置项与回滚

### 8.1 新增配置（`.env` 里全部走环境变量；`application.yml` 只给默认值）

| 环境变量 | 默认 | 含义 |
|---|---|---|
| `APP_USER_TOKEN_SHA256` | **空** | 令牌 sha256（64 位小写十六进制）。**空 = 登录面整体关闭** |
| `APP_USER_LOGIN_PER_MINUTE` | 10 | 登录面每 IP 每分钟上限（status + ask 共用一个桶） |
| `APP_USER_FAIL_THRESHOLD` | 10 | 触发短时封禁的失败次数 |
| `APP_USER_FAIL_WINDOW_SEC` | 600 | 失败计数窗口 |
| `APP_USER_BAN_SEC` | 600 | 封禁时长 |
| `APP_USER_MAX_BODY_CHARS` | 4000 | 自用提问请求体上限 |
| `APP_USER_DEADLINE_MS` | 60000 | 自用提问总预算 |
| `APP_USER_CONV_MAX_ROUNDS` | 5 | 窗口轮数（3~5） |
| `APP_USER_CONV_TTL_MINUTES` | 30 | 会话过期 |
| `APP_QUOTA_SELF_SOFT_LIMIT` | 500 | 自用池软上限（**只提醒不停**） |
| `APP_QUOTA_SELF_STORE_FILE` | `data/model-quota-self.json` | 自用池计数文件 |

> ⚠️ 与 `APP_QUOTA_*` / `APP_WEBSTATS_*` 同一个坑：`docker-compose.yml` 的 `environment:`
> 段必须**显式透传**这些键（compose 的优先级高于单纯的环境变量绑定），
> 否则「在 `.env` 里加一行」不生效**且不报错**。本条已列入第二步的部署清单。

### 8.2 回滚（语义级，不用换镜像）

| 场景 | 操作 | 生效时间 |
|---|---|---|
| 想整体关掉登录面 | `.env` 置 `APP_USER_TOKEN_SHA256=`（清空）→ `srv1-redeploy.sh --force` | 容器重启后（约 30~60 s） |
| 令牌疑似泄露 | 生成新令牌，只更新 `.env` 里那一行哈希 → `--force` | 同上；旧令牌立即失效 |
| 改错了代码 / 行为异常 | `srv1-rollback.sh --to <上次 digest>` | 镜像级即时回滚 |
| 只想临时止血 | 清空 `APP_USER_TOKEN_SHA256=` 即「退回无登录面」，**其他功能一律不受影响** | 同上 |

**关键性质**：登录面是**加法**，且由一个空值开关控制。
清空该键后系统行为**逐字节回到改造前**（没有任何公开面/评测面逻辑被改动）。

## 9. 威胁模型（本方案防什么、不防什么）

| 威胁 | 是否防住 | 机制 / 说明 |
|---|---|---|
| 从 `.env` 或备份里读走令牌 | **部分** | 只存 sha256 ⇒ 拿到哈希推不回明文；但明文在站主浏览器里，需站主自保 |
| 暴力猜令牌 | ✓ | 192+ bit 熵 + 恒定时间比较 + 10 次/10 分钟即封 10 分钟 |
| 时序侧信道推断令牌 | ✓ | 恒定时间比较（逐字节 XOR 累加） |
| 公开面访客刷爆自用额度 | ✓ | 第四本独立账 + 公开面拿不到令牌 |
| 前端被 XSS 读出 localStorage 令牌 | **不防** | 静态站 + 无第三方脚本是现有前提；令牌权限**仅限自用池**（不能处置、不能读内部管理面） |
| 站主设备被完全控制 | **不防** | 任何持有令牌者都能用自用池；这是"自用"的定义 |
| 令牌被中间人截获 | **不防** | 依赖 HTTPS（站点已有证书）；明文令牌不进 Cookie 也降低了被边缘/其他域带走的面 |
| 分布式换 IP 爆破 | **部分** | 进程内按 IP 限速挡不住分布式；192 bit 熵使爆破本身不可行 |

**明确不做**：不做 Cloudflare Access（站主不绑卡）、不做账号密码体系、
不做 JWT/刷新令牌、不做多用户、不做服务端会话 Cookie。

```

  · 列表 / 读取 / 写入 / 删除 / 上传图片（压缩后入库 static/images/）
```

## 附录 B：与前端的三个接口对齐点（施工单）

1. **请求头**：所有自用请求加 `X-User-Token`（值取 `localStorage['xk-user-token']`）。
2. **探针**：拿到令牌后调 `GET /api/user/status` 确认登录态；401 ⇒ 「令牌无效，请重新粘贴」；
   429 ⇒ 「尝试过于频繁，请 N 秒后再试」；网络失败 ⇒ **不要**清 localStorage（下次可能就好）。
3. **降级文案**（逐字建议）：
   * 未登录点 👤：「自用入口：请粘贴自用令牌（令牌只保存在本机浏览器）」
   * 令牌无效：「令牌无效或已轮换 —— 请向站主要一份新的自用令牌」
   * 登录面已关闭（401 `USER_LOGIN_DISABLED`）：「自用入口当前未启用（服务端未配置令牌）」
   * 额度软上限：「今日自用调用已达软上限 500 次，**仍可继续使用**（仅提醒，不限额）」
   * 被限速/封禁：「尝试过于频繁，请 N 秒后再试」（N 取响应头 `Retry-After`）
