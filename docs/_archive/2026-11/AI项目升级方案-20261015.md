# AI 项目升级方案 · 把"安全博客 + 数字角色"升级为「AI 驱动的安全数字人」

> **背景**：项目原本是安全实验室博客（真实攻击监测），后来加了数字角色 + 语音。
> **问题**：现在算不算 AI 项目？**算一半** —— 有真 AI 能力，但缺"评测 / 数据闭环 / AI 决策"三块 ✗。
> **本文**：给出升级路线（阶段任务 T13~T16）、验收标准、工时、风险与插点，可直接派工。
> 标注：`[已实测]` ｜ `[待核对]` ｜ `[风险]` ｜ `[待拍板]`

---

## 0. 定位改写（一句话）

```
原来：安全实验室博客（带个会动的角色）
改成：**AI 驱动的安全数字人** —— 真实攻击数据 → LLM 理解与决策 → 数字角色用语言/表情/动作表达

四层齐全（评审最认这个结构 ✓）：
  数据层：真实攻击日志、蜜罐凭证、地理富化、故事线（别处没有的独特语料 ✓）
  推理层：RAG 混合检索问答（生产 ✓）+ 事件→行为决策（待补 T14）
  交互层：日语语音（本地克隆 ✓）+ 帧/视频动画 + 口型（待接线）
  工程层：端侧推理（6GB 跑通 ✓）、成本控制（缓存/熔断/红线 ✓）、可复现管线、门禁与原子发布 ✓
```

## 2. 为什么"还不算完整 AI 项目"（三个缺口）

```
缺口一：**没有 AI 质量评测** ✗（这是最大的分水岭）
  现在只有工程指标（时延/显存/PSNR/alpha MAE/NCC ✓），没有"它做得好不好"的指标 ✗
缺口二：**没有数据闭环** ✗
  真实攻击日志已经是现成语料，但没有系统化成"可评测的知识库 + 问答对" ✗
缺口三：**AI 没有参与她的行为** ✗
  她的动作目前是"概率 + 固定事件"✗，LLM 只负责问答 —— 两条线没连起来 ✗
```

## 3. 升级路线（三阶段 + 一份说明书，各自可独立交付）

### T13（阶段一，约 1 天）评测包 —— **性价比最高，今天就能出数**

```
目标：给"语音 + 问答"两件事各一套可复现的评测，产出数字进文档
步骤：
 1) **ASR 回译一致率（全自动、零成本 ✓）**
    · 用 ASR（素材包 ASR 包，或 whisper.cpp / FunASR）把生成的 60 句日语语音转回文字
    · 与原文算 **CER/WER**（日语用字符级 CER ✓）；逐句出表，平均数进台账
    · 若 ASR 环境难装（ASR 包 2.69GB + CUDA ✗）：退一步用现成 API（本地可跑的模型优先 ✓）
 2) **问答质量集**（30~50 条）
    · 从真实攻击日志/故事线里造问题（"最近 24 小时 TOP 来源是谁""蜜罐抓到哪些口令"…）
    · 每条记录：期望要点（key points）｜是否应拒答（fail-closed 用例 ✓）
    · 评分：人工或 **LLM-as-judge**（用另一个模型按要点打分 ✓）；指标 = 要点命中率、拒答正确率、引用正确率
 3) **TTS 主观评测流程**（半小时准备，半天收数）
    · ABX/MOS：5~10 人 × 20 句，5 分制；与"Windows SAPI 占位音"做 A/B 对照（有对照组才可信 ✓）
 4) 评测脚本入库：`scripts/eval/`（回译 CER + 质量集 + 打分脚本 ✓ 可重跑）
交付物：`docs/评测报告-语音与问答-20261015.md` + `scripts/eval/*` + 数字进 `docs/总账…` §2
验收：① 60 句 CER 表（逐句 + 均值）② 质量集 ≥30 条、含 ≥3 条拒答用例、得分表 ③ MOS/ABX 结果表 ④ 脚本可重跑
工时/风险：1 天 ｜ 低（唯一风险是 ASR 环境 ✗ → 有退路 ✓）
```

### T14（阶段二，约 1~2 天）LLM 决策行为 —— **最有说服力的一条** ✓

```
目标：把"真实攻击事件"变成"她的情绪 / 动作 / 台词"，让 AI 真正驱动角色
做法：
 1) 服务端加一个**决策端点**（或复用 ask 的通道）：输入=当前告警摘要（等级/类型/TOP来源/新事件/时间）
    输出=**严格 JSON**：{ emotion: angry|surprised|shy|sad|calm|disappointed, clip: <状态机剪辑名>,
                          line_ja: <日语台词或 null>, line_zh: <中文字幕>, urgency: 0..1, reason: <一句话> }
 2) 约束：① 只允许选**存在的**剪辑名（从 statemachine.json 白名单校验 ✗ 防幻觉 ✓）
          ② `line_ja` 只能从**预渲染台词库**里选 id（不允许自由文本 → 否则没法出声 ✗）
             —— 或允许自由文本但标记"仅字幕不出声"✓
          ③ 决策结果 **缓存**（同一告警指纹 5 分钟内不重复请求 ✓ 省钱 ✓）
          ④ 失败/超时 → 回退到现有"概率+固定事件"逻辑 ✓（绝不卡住 ✗）
 3) 前端：把决策结果接到 **T8 的状态机接线**（宿主触发入口正好为它设计 ✓，9 个 prob=0 入口）
 4) 用 `?seed=` / replay 固定几个样例，做成**可复现的演示脚本**（截图/录屏 ✓）
验收：① 给定 5 组不同告警场景，输出合法的情绪/剪辑/台词（附 JSON 原文 ✓）
      ② 幻觉率 0（剪辑名与台词 id 全部在白名单内 ✓）
      ③ 失败注入（端点超时）→ 回退正常、页面不卡 ✓
      ④ 缓存命中：同场景 5 分钟内第二次不发请求 ✓
工时/风险：1~2 天（不含 T8 接线工时）｜ 中（幻觉与延迟是主要风险 ✓ 已有对策 ✓）
```

### T15（阶段三，约 2~3 天，可选）语音闭环：ASR → LLM → TTS

```
目标：访客**对着站点说话** → 她听懂 → 回答 → 说出来（完整语音助手形态 ✓）
步骤：
 1) ASR：素材包 ASR 包（CUDA-Graph、warm 时延 −75% `[待核对]`）/ 或用浏览器端流式 ASR ✓ 二选一
 2) 链路：录音 → ASR → /api/public/ask → 回答 → TTS（本地预渲染优先，自由文本走云端 ✓）
 3) 交互细节：按住说话 / 静音检测 / 打断（她说话时用户再说就打断 ✓）
 4) 延迟预算：首字 ≤1.5s、首音 ≤3s（超了就显示"我在想…"状态 ✓ 并切 thinking 剪辑 ✓）
验收：① 端到端 demo 录屏（含打断）② 延迟分解表（ASR/LLM/TTS 各段）③ 权限被拒/网络断时的降级 ✓
工时/风险：2~3 天 ｜ 中高（受 ASR 环境影响 ✗；可先用文字输入版验收 ✓）
```

## 4. 数据闭环（与 T13/T14 并行，成本很低 ✓）

```
① 攻击日志 → RAG 语料：按天/事件类型切块 + 元数据（时间/来源/等级）→ 进现有知识库 ✓
② 自动问答对：用 LLM 从每天的告警里生成 5~10 条"事实型问题 + 期望要点"，人工抽查 ✓ → 持续扩充评测集 ✓
③ 评测集版本化：`scripts/eval/datasets/*.jsonl`（可重复跑、可对比不同 prompt/模型 ✓）
⇒ 这就形成了"真实数据 → 知识库 → 评测 → 改进"的闭环 ✓（AI 项目最缺的就是这个 ✗）
```

## 6. 风险与坑（沿用现有台账 ✓）

```
[风险] ① ASR 环境：素材包 ASR 包 2.69GB + CUDA，可能又遇 Windows 编译/依赖问题 ✗
       对策：优先浏览器端或现成 Python 包；实在不行 T13 的 CER 改用云端 API 跑一次（只为出数 ✓）
[风险] ② fish.audio 在**境内被 SNI 重置**（HTTP 可建、TLS 漏 SNI 即 RST）✗
       对策：TTS L2 三选一（CF Worker 中转 / DashScope 境内 0.22s / 暂缓）—— 见任务清单 §16.4 ✓
[风险] ③ 6GB 显存要排队：ASR + TTS + 浏览器同机会打架 ✗ → 分时跑，或用 CPU 版 ASR 兜底 ✓
[风险] ④ LLM 决策的**幻觉**（编出不存在的剪辑名）✗ → 白名单校验 + 台词 id 约束（T14 已写 ✓）
[风险] ⑤ 成本：自由文本 TTS + 决策请求都会花钱 ⇒ 必须缓存 + 月硬顶熔断 ✓（现已有闸 ✓）
[风险] ⑥ 别把"演示数据"当评测结果 ✗ —— 评测必须用真实数据/真实模型输出 ✓
```
