| 12:53 | 交叉验证：**srv2 → srv1:22 可达**（`OPEN`）；站点 `https://xiaokeqing.cn/` = **HTTP 200**（CF 隧道与业务正常） |
| — | 结论：**srv1 没宕机**，是我这个来源被挡（最可能是 fail2ban 判定异常会话所致） |

* 我**没有**做的事：没有硬撑、没有换路硬试、没有改动任何线上配置。

* **教训（写给下一次）**：不要在 SSH 上跑可能产生巨量输出的命令（`docker logs | grep` 全量）；
  应先在远端 `tail`/`wc -l` 收敛，或重定向到远端文件再取需要的片段。
  这类"只读操作"同样会撞上主机侧防护，而且它挡的是**运维通道本身** —— 代价比读不到日志大得多。

## 3. 重建步骤（站主侧确认 `stable` 已更新后执行）

> 纪律：**停 timer → 重建 → 起 timer**；**禁手工 `docker compose up`**（走 `srv1-redeploy.sh`）。

### 3.1 前置：写入令牌哈希 + 补 compose 透传

```bash
# ① 生成明文令牌；明文只落到 root-only 文件，终端只显示哈希与长度
sudo bash -c '
set -euo pipefail
umask 077
TOKEN_PLAIN=$(python3 -c "import secrets;print(secrets.token_urlsafe(48))")
HASH=$(printf "%s" "$TOKEN_PLAIN" | sha256sum | cut -d" " -f1)
printf "# XK self token · 生成于 %s · 读一次后请删除本文件\n%s\n" "$(date -Is)" "$TOKEN_PLAIN" > /root/xk-self-token.txt
chmod 600 /root/xk-self-token.txt
# .env 只写哈希（先删旧行再加，避免重复）
sed -i "/^APP_USER_TOKEN_SHA256=/d" /opt/secagent/.env
printf "APP_USER_TOKEN_SHA256=%s\n" "$HASH" >> /opt/secagent/.env
chmod 600 /opt/secagent/.env
echo "令牌已设置：长度=$(( $(wc -c < <(printf %s "$TOKEN_PLAIN")) ))  哈希前 8 位=${HASH:0:8}  （明文在 /root/xk-self-token.txt，本脚本不打印它）"
unset TOKEN_PLAIN HASH
'
```

**compose 透传（必做，否则"改了不生效且不报错"）**：`/opt/secagent/docker-compose.yml` 的
`secagent.environment:` 段里加 `self-daily-soft-limit`，其余新键靠 `env_file: .env` 已足够：

```bash
sudo cp -a /opt/secagent/docker-compose.yml /opt/secagent/docker-compose.yml.bak-selftoken-$(date +%Y%m%dT%H%M%S)
sudo python3 - <<'PY'
import re, pathlib
p = pathlib.Path('/opt/secagent/docker-compose.yml')
s = p.read_text(encoding='utf-8')
old = '"public-daily-limit":${APP_QUOTA_PUBLIC_DAILY_LIMIT:-30}}'
new = '"public-daily-limit":${APP_QUOTA_PUBLIC_DAILY_LIMIT:-30},\n                         "self-daily-soft-limit":${APP_QUOTA_SELF_SOFT_LIMIT:-500}}'
assert s.count(old) == 1, f"锚点出现 {s.count(old)} 次，拒绝改动（fail-closed）"
p.write_text(s.replace(old, new), encoding='utf-8')
print("compose 已补 self-daily-soft-limit=500")
PY
sudo docker compose -f /opt/secagent/docker-compose.yml config >/dev/null && echo "compose 语法 OK"
```

> 为什么走这段 JSON 而不是另加环境变量：`SPRING_APPLICATION_JSON` 的优先级**高于**环境变量绑定，
> 只加环境变量会**静默沿用** compose 里写死的值 —— 这是本项目反复踩过的坑。

## 4. 重建后四行自检（原文照贴给站主）

```bash
# 行 1：正确令牌 ⇒ 200 且 authenticated=true（+ 自用池额度）
TOKEN=$(sudo cat /root/xk-self-token.txt | tail -1)
curl -s -o /tmp/r1 -w 'HTTP=%{http_code}\n' -H "X-User-Token: $TOKEN" http://127.0.0.1:9900/api/user/status
python3 -m json.tool /tmp/r1

# 行 2：错误令牌 ⇒ 401/403，且**不含任何敏感信息**（不得回显令牌/哈希/内部路径）
curl -s -o /tmp/r2 -w 'HTTP=%{http_code}\n' -H 'X-User-Token: wrong-token-wrong-token-wrong-token-xx' http://127.0.0.1:9900/api/user/status
cat /tmp/r2; echo
# 行 2b：缺失令牌 ⇒ 401 TOKEN_MISSING
curl -s -o /tmp/r2b -w 'HTTP=%{http_code}\n' http://127.0.0.1:9900/api/user/status; cat /tmp/r2b; echo

# 行 3：启动自检行（decision=whitelist{…} / persona=loaded(…) / LLM / OUTBOUND 仍正常）
sudo docker logs --since 10m secagent 2>&1 | grep -E 'decision=whitelist|persona=|LLM-PROVIDER-SELFCHECK|OUTBOUND|自用登录面|自用池' | tail -20

# 行 4：/api/health + 公开面不受影响（匿名问一次）
curl -s http://127.0.0.1:9900/api/health | python3 -m json.tool | head -20
curl -s -o /tmp/r4 -w 'HTTP=%{http_code}\n' -X POST -H 'Content-Type: application/json' \
     -d '{"question":"什么是 SSH 暴力破解？"}' http://127.0.0.1:9900/api/public/ask
python3 -c "import json;d=json.load(open('/tmp/r4'));print('code',d['code'],'state',d['data'].get('state'),'pool',d['data'].get('quota',{}).get('pool'))"
```

**判定标准**：行 1 = `HTTP=200` + `"authenticated": true` + `"pool": "self"` + `"softLimit": true`；
行 2 = `HTTP=401` + `reason=TOKEN_INVALID`（正文里搜不到令牌、哈希、内部路径）；
行 2b = `HTTP=401` + `reason=TOKEN_MISSING`；行 3 三类自检行都在且无 `MISSING`；
行 4 = health `status=ok` 且公开面仍 `code 200` + `pool=public-demo`（额度用尽时是 `state=model-failed` + 明确的额度文案，**仍属正常**）。

> 自检用的明文令牌只出现在 shell 变量里，**不写进任何文件**；自检记录里也不贴它。

> 回滚**不需要**重新构建、**不需要**改代码 —— 三档都只用既有脚本或一行 `.env` 变更。

## 10. 前端契约一页（**转站点线**，接 👤 按钮的 3b 部分）

> 逐字为准。本页只讲前端要做什么，后端行为都有测试钉住（见 §1.3）。

### 10.1 部署前置与跨域实测（**已实测通过，站点线只需知道结论**）

> ⚠️ 先纠正一个**我一开始搞错的判断**（记在这里，避免站点线照错的做）：
> 我最初用 `https://xiaokeqing.cn/api/user/status` 探测，得到 `200 text/html`（首页），
> 差点写成"nginx 需要给 `/api/user/` 加反代"。
> **那是错的**：`xiaokeqing.cn` 是**静态站（srv2）**，它上面本来就没有 `/api`，
> 任何 `/api/*` 落到 SPA 兜底返回 `index.html` 是**预期行为**。
> 前端调 API 的 base 是 **`https://demo.xiaokeqing.cn`**（见页面 `<meta name="wb-api">`）。
> ⇒ **srv2 的 nginx 不需要为 `/api/user/` 加任何东西。**

**在正确的主机上实测（2026-10-16，只读探测）：**

```bash
# ① 登录面口径：无令牌 ⇒ 401 JSON（不是 200 HTML、也不是 500）
$ curl -s -i https://demo.xiaokeqing.cn/api/user/status | head -3
HTTP/1.1 401 Unauthorized
Content-Type: application/json;charset=UTF-8
{"code":401,"message":"自用入口未启用（服务端未配置令牌）","reason":"USER_LOGIN_DISABLED"}

# ② 跨域预检：必须允许来源 https://xiaokeqing.cn 且允许请求头 X-User-Token
$ curl -s -i -X OPTIONS -H 'Origin: https://xiaokeqing.cn' \
       -H 'Access-Control-Request-Method: GET' \
       -H 'Access-Control-Request-Headers: x-user-token' \
       https://demo.xiaokeqing.cn/api/user/status | head -8
HTTP/1.1 200
access-control-allow-origin: https://xiaokeqing.cn
access-control-allow-methods: GET,POST,PUT,DELETE,OPTIONS
access-control-allow-headers: x-user-token          ← 关键：X-User-Token 已被允许
access-control-max-age: 3600
```

**结论（站点线照此对接即可）**：

| 项 | 实测结果 | 含义 |
|---|---|---|
| 登录面可达性 | `demo.xiaokeqing.cn` 上 401 JSON | 路由通；**无需**改 nginx |
| fail-closed | 无令牌与错误令牌都返回 `401 USER_LOGIN_DISABLED` | 当前 `APP_USER_TOKEN_SHA256` 尚未写入 ⇒ 登录面按设计关闭（**不假装登录**） |
| 跨域来源 | `access-control-allow-origin: https://xiaokeqing.cn` | 站点 ↔ API 跨域已放行 |
| 预检请求头 | `access-control-allow-headers: x-user-token` | 带上令牌的请求不会被浏览器拦（**这是最容易漏、且表现是"点了没反应"的一条**） |
| 敏感信息 | 401 响应体只有 `code/message/reason` 三个字段，无令牌、无哈希、无内部路径 | 失败响应可安全展示 |

> 写入 `APP_USER_TOKEN_SHA256` 之后，**同一路径**的期望响应变为：
> 正确令牌 ⇒ `200` + `{"loggedIn":true,…}`（见 §10.3）；错误/缺失 ⇒ `401` + `TOKEN_INVALID` / `TOKEN_MISSING`。
> 也就是说：**接口形状与跨域行为都不会变，只会从"未启用"变成"可用"**。

### 10.2 请求头

| 项 | 约定 |
|---|---|
| 头名 | `X-User-Token` |
| 头值 | 站主手动粘贴的令牌原文（32~200 字符） |
| 出现范围 | **只**发给 `xiaokeqing.cn`（含 `www`）下的 `/api/user/*`；**不要**发给第三方域或 CDN |
| ✗ 禁止 | 把令牌写进任何 `.js` / `.html` / Hugo 模板 / 构建产物 / 仓库文件；✗ 写进 `document.cookie`（能被别的域/边缘带走） |

### 10.2 令牌输入与存放

```
站主：隐蔽入口（?admin=1 或连点头像 5 次）→ 👤 按钮 → 弹出输入框 → 粘贴令牌 → 确认
前端：localStorage['xk-user-token'] = <令牌>        // 长期自用，关标签页仍在
      sessionStorage['xk-admin-ui'] = 1            // 既有：控制按钮是否可见（本批不改）
      立即 GET /api/user/status 探测一次：
        200 ⇒ 显示「已登录 · 自用模式」
        401 ⇒ 提示「令牌无效或已轮换」**但不要**立刻删除 localStorage（可能只是粘贴出错，让站主重试）
```

* **退出登录**：点 👤 菜单里「退出登录」= `localStorage.removeItem('xk-user-token')`（本地即可；后端无会话可销）。
* ✗ **不要**把令牌放进 URL 查询串（会进浏览器历史、Referer、日志）。

### 10.3 登录态字段（`GET /api/user/status` 成功 200）

```json
{"code":200,"message":"success","data":{
  "loggedIn": true,              // 站主自检口径字段
  "authenticated": true,         // 同义（服务端无会话，指令牌校验通过）
  "pool": "self",                // 前端据此显示「自用池」
  "generatedAt": "2026-10-16 13:20:00",
  "quota": {"pool":"self","softLimit":true,"available":true,
            "limit":500,"used":37,"remaining":463,"softLimitReached":false,
            "storeFile":"data/model-quota-self.json","note":"…软上限…只提醒…"},
  "conversation": {"maxRounds":5,"ttlMinutes":30},
  "limits": {"maxBodyChars":4000,"deadlineMs":60000,"maxTokens":4000},
  "note": "自用模式：额度为软上限（只提醒不硬停）；本响应不下发、不记录任何令牌内容。"
}}
```

> 金额度相关键总是存在（即使配额服务未接入也保持同一形状），前端**不需要**做空值兜底。

### 10.4 自用提问（`POST /api/user/ask`）

```jsonc
// 请求
{"question":"…", "conversationId":"xk-<随机>"}      // conversationId 可省；省了后端生成并在响应里回
// 响应 data（成功）
{"answer":"…", "state":"model", "generated":true, "round":2,
 "conversationId":"xk-…", "maxRounds":5, "historyRounds":1,
 "citations":[…], "citationsInAnswer":true,
 "pool":"self", "clientIpMasked":"…", "quota":{…}, "toolExecutionAllowed":true}
// 未生成（模型/链路不可用）：HTTP 仍 200，但 state=model-failed / generated=false
//   —— 前端必须按 state 显示"未生成"，**不要**把 answer 当结论渲染（正文里写明了没有结论）
```
* 多轮由 `conversationId` 维持：前端把它存 `sessionStorage` 即可（**登录面才有多轮**，公开面没有）。
* 窗口满 5 轮自动忘掉最旧一轮；30 分钟无活动即当新会话。

### 10.5 五条降级文案（**逐字建议，可直接用**）

| # | 触发 | 文案 |
|---|---|---|
| 1 | 未登录时点 👤 | 「自用入口：请粘贴自用令牌（令牌只保存在本机浏览器，不会上传到别处）」 |
| 2 | 401 `TOKEN_INVALID` / `TOKEN_MISSING` | 「令牌无效或已轮换 —— 请向站主要一份新的自用令牌」 |
| 3 | 401 `USER_LOGIN_DISABLED` | 「自用入口当前未启用（服务端未配置令牌）」 |
| 4 | 429 `LOGIN_RATE_LIMITED` / `IP_TEMPORARILY_BANNED` | 「尝试过于频繁，请 N 秒后再试」（N 取响应头 `Retry-After`；无该头时默认 60） |
| 5 | 200 且 `quota.softLimitReached=true` | 「今日自用调用已达软上限 500 次，**仍可继续使用**（仅提醒，不限额）」 |

补充两条（非降级，但会影响显示）：
* `state=model-failed` / `generated=false` ⇒ 「本次没有生成结论（模型或链路不可用）」——**不要**把正文当答案。
* 网络失败或 5xx ⇒ 「连不上服务，请稍后重试」；**不要**因此清掉 localStorage。
