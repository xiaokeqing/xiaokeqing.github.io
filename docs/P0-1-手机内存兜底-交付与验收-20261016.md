## 一、根因（已定的方向）

iPhone Safari 连 `video/webm;codecs=vp9` 都不认 ⇒ `__xkVid` 走 auto 降级进 pixel 档 ⇒ 画 `/kurisu/full/*.hi.webp`；
单张 hi 解码 **35.5 ~ 53.3MB**（manifest `decodedBytes` 实测：opening 38.8MB / idle 35.5MB / speaking·thinking 53.3MB）
⇒ iOS 逐标签页内存上限把已解码位图丢掉 ⇒ 上屏**一整块灰**；同一页时好时坏；微信内置浏览器内存更紧 ⇒ 更差。

## 二、落地做法（`_dev/gen-demo-pages.py` 的 `XK_TIER` 模块）

| # | 口径 | 实现 |
|---|---|---|
| ① | 手机**强制只用中档**，hi 一个请求都不发 | `T.noHi = mobile \|\| lowMem` ⇒ `initTier='medium'` = `/kurisu/full/*.boot.webp`（**同瓦片** 321×432 / 380×290、24 帧、解码 10.6~13.3MB ⇒ 画质不变、内存降 3~4 倍） |
| ② | 位图被丢弃的检测 | `XK_TIER.sample(cv)` 抽检"她应该在那里"的竖条（非透明像素计数）；手机面板另抽 `phoneCanvas` |
| ③ | **重试一次** ⇒ 仍失败**降档**，写 `degradeReason` | `retry()`（删缓存里的 Image 重新取图 = 重新解码）→ `degrade()` hi→medium→poster；**宁可出静态帧，不许静默留灰块** |
| ④ | `__xkVid.probe` 的 alpha 采样**每次切剪辑都采一次** | `if(c.have >= 0 && V.probeClip !== c.name){ V.probeClip = c.name; probeAlpha(c); }`，历史留在 `V.probes[]` |
| ⑤ | 诊断 | `window.__xkTier = { mobile,lowMem,noHi,initTier,tier,degraded,degradeReason,retries,checks,lastCheck,events,errors }`；旋钮 `?xk-tier=hi|medium|poster|auto`、`?xk-tier-fail=`、`?xk-tier-blank=1` |

纪律：**桌面 auto = hi，逐字等于改前**；不改配色/背景/字体。
