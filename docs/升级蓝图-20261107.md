## 1. 这个项目是什么

**一句话**：一个人在公网上搭的**个人安全观测站** —— 把主机、网络、蜜罐三类安全数据汇到一台只读网站上，能看到"谁在打我、从哪来、用什么手法、有多猛"，并且每个数字都能下钻到原始日志。

**三块组成**：
- **采集**：srv2（香港）跑 Suricata 全流量 + dionaea 蜜罐 + 靶场容器；srv1（杭州）跑 Wazuh（主机侧告警/文件完整性/漏洞）。
- **处理**：SecAgent（Spring Boot）把三路数据归一化、去噪、聚合、打分，产出"事件 / 攻击链 / 统计 / 日报"。
- **展示**：Hugo 静态站（Netlify 托管）+ 浏览器端调只读 API，**站上不写任何后门**（纯静态 + 只读接口）。

**拓扑**：

```
          浏览器
            │ https
     ┌──────┴───────┐
     │ Netlify CDN  │  ← xiaokeqing.cn / www（静态站，构建自 GitHub）
     └──────┬───────┘
            │ XHR（只读 JSON，CORS 白名单）
     ┌──────┴─────────────┐
     │ demo.xiaokeqing.cn │
     └──────┬─────────────┘
            │ ① CF 橙云 → cloudflared 隧道（srv2，ingress: demo → 127.0.0.1:19900）
            │ ② 反向 SSH：srv2 19900 → srv1 127.0.0.1:9900（srv2-api-tunnel.service）
     ┌──────┴──────┐          ┌──────────────┐
     │ srv1 杭州   │          │ srv2 香港    │
     │ SecAgent    │◀──eve────│ Suricata     │
     │ Wazuh mgr   │  增量同步 │ dionaea 蜜罐 │
     │ Milvus/RAG  │          │ 靶场容器     │
     └─────────────┘          └──────────────┘
```

### 4.3 处置链（封禁/解封）

```
告警/研判 → ResponseController(/block) → ResponseActionService
   ├ ResponseGuard 护栏：白名单 25 条（内置 13 + 自有 4 + IPv6 8）、本机公网 2 条、健康检查源 3 条、
   │                    默认 TTL 60min、人工上限 1440min、策略上限 10080min、拒封本机/网关/受保护网段
   ├ BlockRecordStore 记账（expiresAt、markUnblockedByIp、listActive）
   ├ SshBlockExecutor → ssh root@srv2 → /usr/local/sbin/secagent-block-cli（forced command）
   │     block <ip> <ttl> <reason> → ipset add secagent_block/secagent_block6 + iptables/ip6tables DROP
   │     unblock/flush/status；无 ipset 时回退逐条 iptables + 状态文件到期清理
   ├ UnblockScheduler：到期自动解封（走同一 SSH 通道）
   └ AuditService + SecurityEventNotifier（通知旁路失败不影响处置）
```

**坑（已修）**：① `SPRING_APPLICATION_JSON` 里 `"self-assets":"${ENV:-}"` 的**空默认值会覆盖环境变量** ⇒ 白名单永远是 0，必须写死同一串 IP；② 判断网关能力**不能用 `instanceof`**（Spring 代理会 false，静默退回 MOCK），要用 `ObjectProvider<SshBlockExecutor>`；③ `ipset create … -exist` 会沿用历史同名集合的类型（曾把 `hash:net` 需求留在 `hash:ip` 上，需先 destroy 再 create）。

### 5.3 故障处置（都真踩过）

| 症状 | 处置 |
|---|---|
| srv2 nginx 整个消失（`ss` 只剩 docker-proxy 的 443） | `sudo mkdir -p /run/nginx` → `sudo setsid /usr/sbin/nginx -g 'daemon on;' </dev/null >/dev/null 2>&1 &`；根治用 drop-in `RuntimeDirectory=nginx`。**以后改配置一律 `systemctl restart nginx`，别用 `-s reload`** |
| `nginx -t` 报 `open() "/run/nginx/nginx.pid" failed` | 不是配置错，是 pid 目录没建；别据此判断 |
| 子域全 530 | 隧道 connector 挂了或 ingress 写坏：`yaml.safe_load` 校验 `ingress.yml` → `systemctl restart cloudflared-static` → CF 里看 `secagent-static` 是否 healthy 4 conns |
| 浏览器一直显示旧图 | Netlify `/images/*` 30 天缓存 ⇒ 换 URL（`?v=`） |
| 发布后线上还是旧版 | 发布只发 HEAD 干净 worktree：先 commit 再 push 再发布 |
| `top-ports` 恒 0 | REAL 模式启动空窗（回填后未触发首次摄取）；已在 `init()` 里同步跑一次 |

## 6. 数据口径（站主的硬要求）

## 8. 已知坑合集（新人先读这一节，能省半天）

1. **两份同构代码**：`layouts/index.html` 与 `assets/js/xk-scene.js` 的角色渲染必须同改（本轮就是首页那份还写着"只认单页 hi"，导致 540 图集在首页完全不生效）。
2. **`hiAtlas` 的视频闸**：判 `Vv.mode !== 'pixel' && Vv.mode !== 'off'`，不能只看 `videoOK`（`poster` 阶段也是 true）。
3. **`smUseHi` 阈值**：`canvas.width >= 700`（不是 480）；否则小画布白下 3.9 MB。
4. **播放器内存**：`ensureMediumClip` 原先整段 decode 常驻，120 帧 540 要 185 MB；已改成窗口 ±1 页，**别回退**。
5. **esbuild banner**：`static/js/kurisu-player.js` 带 banner，重压要 prepend。
6. **Hugo `assets` 缓存**：改完 JS 若 hash 不变，先删 `resources/_gen`；仍不变就核对该资源是否真被 `resources.Get` 引用（本仓有内联副本的情况）。
7. **WindowsApps stub**：断言里的 `python3` 要剔除 PATH。
8. **PowerShell 无 heredoc**：中文脚本一律写文件再跑（`write` 工具 + `python -X utf8 file.py`）。
9. **ssh 引号**：`ssh host 'a|b'` 会被本地 PowerShell 拆坏 ⇒ 远端命令写 `.sh` + `scp` + `sudo bash`。
10. **Netlify 文件名限制**：不能含 `#`/`?`（E-mote 纹理踩过）。
11. **项目可见性**：Netlify Private 项目会全站 401，要单独把 Production visibility 改 Public。
12. **不要搬 NS**：代理/隧道记录都在 Cloudflare，把注册商 NS 换成 Netlify DNS 会让 `demo.`/`lab.`/`static.` 全挂。
13. **Netlify 缓存 30 天**：换图换 URL。
14. **资产上限**：角色+场景 ≤256MiB（断言 ⑨），新图集前先算总账。
15. **`data/ops_snapshot.json` 命名**：必须下划线，写 `ops-snapshot.json` 模板取不到。
