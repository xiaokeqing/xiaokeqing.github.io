# 自用入口（登录按钮）· 设计与口径 · 2026-10-16 批次 A

> **站主原话**："主页登录后对话那个按钮**访客不要显示**，这个是属于我自己的功能"；"页面要干净"；
> "但要给站主留一个**隐蔽入口**（否则他自己也进不去）"；"已登录会话：可一直显示『已登录 · 自用模式』"。
> **执行**：登录按钮**默认不渲染**（`hidden`），只由隐蔽入口打开；打开后本会话一直显示。

---

## 1. 入口方式（两个都做了，任选其一即可）

| # | 入口 | 触发方式 | 隐蔽性 | 恢复 |
|---|---|---|---|---|
| a | **URL 参数** | `https://xiaokeqing.cn/?admin=1`（或任意页 `?admin=1`）<br>也接受 hash：`https://xiaokeqing.cn/#admin` | 访客看不到任何痕迹；地址栏会留参数 | 关掉参数即回到访客态（本会话已打开的仍显示到标签页关闭） |
| b | **连点头像 5 次** | **1.5 秒内**连点左上角她的头像 5 下 | 对访客就是"多点了几下头像"，**零痕迹**（无地址栏变化、无按钮出现直到第 5 下） | 关闭标签页即失效 |

**为什么两个都做**（自主决定，记录在案）：
* `?admin=1` 适合站主在**任意设备**（含手机、无键盘）上一步到位，且便于以后写进书签；
* 连点 5 次适合**已经停在该页、不想改地址**的场景，也是对"URL 参数会被别人猜到"的兜底；
* 两者都**只在浏览器本地生效**（`sessionStorage['xk-admin-ui']=1`），服务端零改动、零新端点。

## 2. 显示后的行为

| 状态 | 按钮外观 | 点击后 |
|---|---|---|
| 未配置 Cloudflare Access（**当前线上状态**） | `👤` + `aria-pressed="false"` | 提示 **"登录通道待接入（需开 Cloudflare Access）—— 开了之后这里才会真的登录。"** |
| 已登录（Access Cookie 在） | `🔓` + `aria-pressed="true"`，title = `已登录 · 自用模式` | 提示 **"已登录 · 自用模式（本会话本地状态；凭据不经前端）"** |

## 3. **绝不硬编码令牌**（红线，怎么保证的）

```js
function accessCookie(){ try { return document.cookie.indexOf('CF_Authorization=') >= 0; } catch(e){ return false; } }
```
* 只判定 **Cookie 名字是否存在**（`CF_Authorization` 是 Cloudflare Access 签发的会话 Cookie）；
* **不读取它的值、不写进任何一个 DOM、不发给任何端点、不进 localStorage/sessionStorage、不打日志**；
* 前端**没有任何**写死的 token / JWT / client-id；将来接 Access 也只需要"站主在 CF 打开 Access + 配策略"，
  前端这段判定代码**不用改**（Cookie 名字是 CF 固定的）。

## 4. 为什么这么设计（**本地静态站没有后端会话**）

1. 本站是 **Hugo 纯静态产物 + nginx**，没有任何服务端会话、没有登录端点、没有数据库 ⇒
   "登录"这件事**只能**由边缘层（Cloudflare Access）来做，前端能做的只有"**看 Cookie 在不在**"。
2. 所以前端**不能**提供"用密码登录"的能力（那必然要在前端塞凭据 ⇒ 违反红线）。
   正确形态就是：**Access 兜底 + 前端只做显示态切换**。
3. 站主还要一个"页面干净"的访客体验 ⇒ 默认完全不渲染登录按钮，
   **只有站主自己（知道入口）**才会看到它 ⇒ 访客页面 DOM 里连这个按钮都不存在（不是 `display:none`，是 `hidden` 属性 + 未触发时不渲染可见）。
4. **登录后才该加载的东西**（自用面板 / 更细数据 / 全量语音库）：统一走
   `window.__xkAdmin.fetch(url)` —— **未登录直接 `Promise.reject('ADMIN_ONLY')`，一个请求都不发** ✗（站主追加②最后一条）。
