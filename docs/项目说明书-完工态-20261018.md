---

## 1. 它是什么

一台云主机上的安全观测站：把主机层（Wazuh）、网络层（Suricata）、蜜罐（Cowrie / Dionaea）三类告警汇到同一套只读公开 API 与界面，并配齐检测规则、处置闭环、攻防演练、内容门禁与自动巡检。全部由一人设计、实现、部署与运维。

设计主线只有一句：**数字要么可核对，要么写「读不到」，绝不补数**。

## 3. 功能全景（完工态）

### 3.1 观测与检测

- **三类数据源汇聚**：Wazuh / Suricata / 蜜罐 → 统一只读 API（20 个公开端点，全部可 curl 复现）。
- **告警界面**：实时攻击流（10 s 轮询）、攻击图谱、ATT&CK 矩阵（按 T1110/T1190/T1021/T1046/T1505/T1071 聚合）、数据统计（概览/封禁处置/来源地图/访问统计/发布版本 5 个子标签）。
- **攻击地图**：国家气泡 + 质心落点 + 24 小时逐时回放（700 ms/小时），标注"落点是国家质心，不是攻击者真实坐标"。
- **检测规则**：Suricata 7 条（同源多端口爆破、扫描器指纹、MSSQL 探测等）+ Wazuh 3 条（`same_field` / `different_field` / `if_sid`）；阈值按真实爆破节奏（5 分钟窗口 max 14 / median 12）实测标定，避免"要么不响、要么刷屏"。
- **噪音治理**：自家 agent 心跳（sid 2013031，占 94.86%）提供抑制规则并默认 opt-in；`/noise/` 页把"有效信号占比"长期量化成指标。
- **蜜罐与样本**：Cowrie 记录登录尝试、口令结构与会话节奏，下载文件按大小上限落盘留存；`/samples/` 同时呈现文件样本与"抓不到文件但行为可复现"的用例，抓不到就写 0 条。
- **弱口令统计**：690,971 行日志 → 6,055 个唯一口令哈希 / 6,033 个前缀桶，只给结构与次数，明文永不下发。
- **IP 情报**：任意公网 IP 聚合告警、蜜罐、封禁痕迹，附启发式威胁分（缺字段从分母剔除并重标化，明确声明"不是概率模型"）。
- **攻击链复盘**：从单 IP 全量事件还原攻击链，量化出"已部署的 120 秒 5 次失败规则在该源上命中 0 次"，据此改阈值——检测缺口由数据发现，不靠猜。

### 3.2 处置与防护

- **处置闭环**：护栏命中 → 计数 → 可选自动封禁（带到期时间，默认 60 分钟）→ 写审计留痕 `AUD-xxx` → 到期或手动解封 → 留痕保留可审计。对外累计拦截 98 次；自测留痕已清理，公开面零测试脏数据。
- **四道护栏**：输入长度/字符集、Prompt 注入、输出敏感特征、限流与配额。红队 27 例常态回归，绕过条目持续修（base64 载荷与中文化改写是重点）。
- **限流与配额**：按 IP + 全局双桶（`/tts/say` 30/天/IP 与 300/天全局，`/password` 30/分钟/IP），命中缓存不吃额度。
- **脱敏**：内网/保留/链路地址统一"内网 / 未知"；公开面 IP 策略可配（当前按站主拍板展示真实来源 IP）。
- **安全响应头**：CSP Report-Only、HSTS 180 天含子域、X-Frame-Options、Referrer-Policy、Permissions-Policy，注入在 `location /` 级（避免 server 级被 location 覆盖）。
- **审计可追溯**：每次处置写 `response-audit.json`，含动作、触发方、留痕号、可回滚。

### 3.4 工程与质量

- **原子发布**：干净 worktree 构建 → 85 项断言 → tar → 远端解包 → symlink 原子切换 → 整树哈希校验 → 失败自动回滚；20+ 次发布零"半站点"。
- **构建断言 85 项**：体积、外链指纹、禁词、页面登记、SSR 契约、排版 P0（横向溢出/重叠/文字被裁/表格窄屏）。
- **SSR 契约**：每页必须有 `data-xk-ssr` 标记，新增页面先登记才允许发布。
- **布局审计**：9 项 × 3 宽度（390/768/1280），98 页 285 个测量点；对比度问题 195 → 0，字号 <13px 234 → 3，横向溢出 0。
- **定时巡检**：每 15 分钟 16 项（页面 200、端点 200、站点完整性、API 与发布版本一致），结果挂 `/status/`。
- **站点探活**：每 5 分钟探站点与 API，连续 3 次失败告警，`/data/uptime.json` 可视化。
- **部署防再犯**：镜像 ID 硬校验（不一致 `exit 7`）、compose 备份恢复、RUNBOOK 三事故判据（SIGPIPE 假失败、镜像标签错位、5 分钟定时器回滚）。
- **前端性能**：共享 CSS/JS 外链化 + sha256 指纹，首页 158,678 → 61,672 B；preconnect、localStorage 秒显上次数据、骨架屏、`prefers-reduced-motion` 全覆盖；二次访问静态资源全 304。
- **首屏聚合**：5 个并发请求合成 1 个 `/api/public/home.js`（alerts/geo/honeypot/audit/health 五块），单块失败只降级该块；3.4 s → 1.8 s。
- **双仓库与文档**：前端/文档/脚本与后端分离，RUNBOOK、口径核对、简历事实清单、完工核对表齐备，两仓库干净且已推 GitHub。

## 5. 明确不做（设计取舍）

评论/登录/多租户、对外提供靶场服务、手机 App、短信电话告警、视频档人物（VP9-alpha 在 iOS 不支持且实测比图集更糊）、HTML 边缘缓存（会破坏"发布即生效"）、自研模型训练。

## 6. 运维要点（交接用）

1. 发布：`scripts/publish-site-to-srv2.ps1`（含 CF purge）；后端 `scripts/deploy-remote-build.ps1`。
2. 回滚：`releases/` 切 symlink 即回滚，脚本 `--rollback` 一键。
3. 巡检：`systemctl status consistency-check.timer`；报告 `/reports/ci/latest.json`。
4. 监控：`/data/uptime.json`、`/status/` 状态卡、`/var/log/xk-uptime-alert.log`。
5. 事故判据与误判清单见 `docs/RUNBOOK-部署.md`、`docs/RUNBOOK-靶场.md`。
