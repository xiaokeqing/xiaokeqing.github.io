# 评审意见：《动画与语音实现规格-给外部AI.md》（2026-10-14）

> 总评：**规格可执行度高，机制层无需返工**。三类意见：① §8 托管变更（整站搬 srv2）要补风险账与隔离规格；
> ② 若干实现细节优化；③ 让成品"更厉害"的低成本加分项（全部在现有素材与红线内）。

---

## 一、§8 托管变更：方向可行，但必须补四笔账

整站从 Pages 搬到 srv2 + Cloudflare 隧道 + `static.xiaokeqing.cn` 缓存规则——**测速依据扎实
（隧道 249KB/s vs Pages 22KB/s），自有域名不违反零第三方红线**。但这是全文档**唯一改变系统
拓扑的决定**，规格里只写了收益，没写代价：

| 要补的账 | 内容 |
|---|---|
| ① 流量预算 | srv2 是 300GB/月流量包（隧道出向也计入）。写进规格：CF 缓存规则下 origin 只承担 miss 流量；按"每访客懒载 10~15MB"估算，300GB 可承 2~3 万访客/月，**定一条红线（如 ≤150GB/月给站点）+ 现有流量日报加一项** |
| ② 隔离规格 | srv2 是检测机。静态服务必须：只读目录 + 独立低权用户（或容器，mem/cpu 限额对齐 Dionaea 的先例）+ 纳进 `srv1-installed-manifest` 同类落点基线 + Wazuh 盯 web 进程。**写进 §8，否则"检测机少折腾"的纪律被自己打破** |
| ③ 隧道单点 | 隧道挂 = 整站挂（比以前"只是 API 断"严重一档）。Pages 保留为备份很好，但要写**切换手册**：DNS 切回步骤 + 多久能切 + 谁执行（Windows 侧？）。半页就够 |
| ④ 缓存清刷流程 | hash 文件名 + Cache Rule 已对；补一句"改素材后如何刷新 CF 缓存"（改 hash=自动失效，但 HTML 引用的刷新路径要写） |

## 二、实现细节优化（6 条）

1. **闭嘴层裁小**（§4）：规格仍写"整帧闭嘴图平移贴"。每个说话剪辑一张整帧（764×1028 RGBA）
   加载与解码都浪费——离线裁成**嘴部小补丁**（锚点 anchor_track + CRT 内归一化坐标），
   视觉等价，内存省一个数量级。至少加一句"只载当前剪辑的闭嘴帧，不预载全部"。
2. **hi 档名单写死**（§8）："主页常用 6~10 段"别让执行方自选，直接在规格里列名
   （建议：idle / idle1 / speaking_short / speaking_med / speaking_long / thinking_speaking2
   / surprise_speaking / + opening 180 帧已有 hi）。
3. **包络格式定契约**（§3.4/§4）：`{sampleRate, hopMs:10, values[0..1]}` 写进 manifest 契约，
   L1 离线算与 L2 服务端算产出同一格式，客户端不区分来源。
4. **页面隐藏**（§7 降级）：已有"页面隐藏暂停"，补实现口径：`visibilitychange` 停 ticker 并
   **清零时间累加器**（否则回来时跳帧快进）。
5. **键盘音效**（§2.3 已列素材，规格未接线）：`computer_use_keyboard_loop.wav` 转 opus 循环，
   音量跟随场景机（仅 computer_use 位播放，进出 0.5s 淡入淡出），受 autoplay 门控同一开关管理。
6. **emotion 标签走服务端**（§5①）：ask 返回 emotion——**改系统提示词让模型直接输出
   `emotion:` 字段**比前端关键词映射稳（模型知道自己在答什么）；前端关键词只做服务端
   没带标签时的兜底。

| 4 | **首访/回访分流** | localStorage 标记：首访播完整开场 84 帧 + 问候；回访跳过特写直接中景 + "欢迎回来"（L1 多录 2 句） | L1 台词 +2 句 |

| 6 | **回归问候** | 标签页切走时她不看屏幕（idle_side_wind 类），切回时 key_point_speaking 打招呼 | 现成剪辑 |

## 四、§10 未决项的直接答案

| 未决项 | 我的答案 |
|---|---|
| 1) 语音 Key | 不阻塞：L1 先行上线（本机 02 包或云端同音色），L2 等 Key 自然接入 |
| 2) L1 本机 vs 云端 | **先云端出活**（当天可听），02 包本机管线作支线；试成后重录替换，静态文件零代码改动 |
| 3) 5 个空底图要不要合成 | **要做**——用户 §0③ 明确要求"房间里也要动"，这是唯一解。但**先做 2 个位置**（computer_use + sleep_desk）验证工艺（inpaint/拼接 + NCC 对原整图验收），过了再补其余 3 个；P3 验收的"2~3 个实时合成"正好对上 |
| 4) 60MB 上限 | 接受。理由已足（37 剪辑补齐 ≈44MB + hi 档），且 §8 已有 CF 缓存兜底 |
| 5) 闭嘴 mask 映射 | 处置正确（显式读 closed_frame_idx），P5 验收已有对照截图，无需额外动作 |

## 五、两处小勘误

- §2.1 表：06 包（v2Pro）标"更省资源的一档"——v2Pro 是**音质分支**不是轻量分支，6GB 显存
  先试它的理由不成立；先试它的正确理由是"如果 v3 装上不顺利"。（不影响执行，改一句描述）
- §6 原理行："06/04 包"应为"04 包"（06 是语音包）。
