# XK-LAB 整体升级方案（2026-10-30 版）

> 目标不是"再加功能"，而是把已经做出来的东西**讲成一个东西**。现在的问题不是做得少，是没人看得出你在做什么。

---

## 一、诊断：为什么"看着杂乱"

先摆事实，不凭感觉。

### 1.1 结构问题：12 个栏目一个权重

现在导航里有：主页 / 监测中心 / 安全日报 / AI 问答 / 笔记 / 靶场 / 状态 / 接口 / 工具 / 介绍，加上页脚可达的 `/reports/` `/samples/` `/tags/` `/categories/` `/about/`。

这带来三个后果：

- **没有主线**。"监测中心"和"工具"和"AI 问答"和"课程笔记"平级，访客不知道先看哪个，也不知道它们之间什么关系。
- **第一印象错位**。首页是一台 CRT 显示器 + 二次元角色，点进来的人第一反应是"这是个谷子站"，而不是"这是个安全项目"。
- **简历上没法写**。简历需要一句能立住的话，现在的站点给不出来——因为它什么都做了一点。

### 1.2 命名问题：同一个东西三种叫法

- 数据页面叫"监测中心"，日报叫"安全日报"，架构说明散在"介绍"和"接口"里。
- 靶场叫"靶场"（`/lab/`）、实战笔记叫"靶机实战"（分类）、红队回归哪儿都不显眼。
- "工具"里有 CVE 查询、密码强度、IP 查询——这些其实都是"证据/分析"的一部分，单独成栏反而稀释了主线。

### 1.3 视觉语言问题：两套风格并存

- CRT 舞台 + 人物 + 语音（二次元叙事）；
- 深色仪表盘 + 表格 + 数字（SOC 叙事）。

两套都在，而且都在首屏附近，谁也没赢。访客的感受就是"花了，但不知道在看什么"。

### 1.4 能力被埋没了

按现在的实现，其实有四个**很硬、但站内看不出来**的东西：

| 真实能力 | 现在的展示位置 | 问题 |
|---|---|---|
| 三源采集（主机 Wazuh / 网络 Suricata / 蜜罐 Cowrie+Dionaea），7 天 29.3 万条告警 | 分散在监测中心各模块 | 没有一个"总览"把它们串起来 |
| 降噪 94.86%、自定义规则 10 条、每日 08:10 日报 + 语音摘要 | 日报页（要滚动才看到口径） | 像"报告"，不像"工程能力" |
| 85 项构建断言 + 原子发布 + 失败自动回滚 | `/status/` 的一个折叠块 | 简历上最有含金量的一条，站内几乎看不见 |
| 27 例红队回归 + 自己发现并修掉 4 条护栏绕过（23.53%） | `/lab/` 里一段文字 | 完全没有"我做过安全测试"的证据链 |

**结论**：不需要新功能，需要**重新组织 + 重新叙述**。升级的核心动作是"删栏目、并栏目、立主线、摆证据"。

## 二、定位：一句话讲清楚

### 2.1 对外一句话

> **我在公网上放了一个诱饵，24 小时记录谁在打我、怎么打；这个站点就是它的仪表盘——每个数字都能点进去看到原始证据。**

### 2.2 身份标签（简历/自我介绍用）

不要叫"个人安全网站"，改叫三个更硬的词：

- **公网安全观测站**（是什么）
- **单人多源 SOC**（规模与角色：一个人干完采集、检测、降噪、展示、运维）
- **可复核**（差异化：数字能点穿到原始日志，不是截图讲故事）

### 2.3 一句话说"为什么做"

真实动机是有意思的：想看看到底谁在扫我、用什么手法、我能不能看懂。这条动机比"学习安全"更可信，也更容易讲成故事。

## 三、信息架构：12 → 5

### 3.1 新导航（五项，其余全部降级）

```
攻击实况    ← 现在的主页 + 监测中心 + 安全日报，合并成"今天发生了什么"
证据         ← 数字点穿：告警 → 规则 → 原始日志 → 每日/每周报告
它怎么运转   ← 架构图 + 数据流 + 检测规则 + 发布流水线（85 断言）
靶场与验证   ← 靶场容器 + 红队 27 例 + 4 条绕过修复 + VulnHub 实战
笔记         ← 课程笔记 39 篇 + 自写复盘 14 篇（明确是"学习记录"，不占主线）
```

### 3.2 新旧对照

| 现在 | 新位置 | 处理方式 |
|---|---|---|
| `/`（CRT 舞台） | 攻击实况 | 舞台降为顶部横幅/开屏动画，1.2 s 后让位给数据 |
| `/alerts/` 监测中心 | 攻击实况 | 并入，作为"细看某一类"的下钻入口 |
| `/daily/` 安全日报 | 攻击实况 + 证据 | 今日卡上移到首屏；归档页保留 |
| `/reports/` 周报 | 证据 | 归档里加"周报"页签 |
| `/api/` 接口文档 | 它怎么运转 | 作为"接口层"一章，不再独立成栏 |
| `/status/` 状态 | 页脚小灯 | 只保留一个健康指示灯，点开才是详情 |
| `/tools/` 工具 | 证据 | 变成证据页的工具条（查 IP / 查 CVE / 查哈希） |
| `/lab/` 靶场 | 靶场与验证 | 并入 |
| `/samples/` 恶意样本 | 靶场与验证 | 并入，作为"抓到了什么" |
| `/what/` 介绍 | 攻击实况首屏 | 内容拆进 Hero 与"它怎么运转" |
| `/ai/` AI 问答 | 保留但**只从两处进**：首页解说员 + 笔记页 | 不再占导航主位 |
| `/posts/` 笔记 | 笔记 | 保留，但明确标注"课堂笔记（按课程整理）"与"自写复盘"两类 |

### 3.3 旧地址怎么处理

给旧 URL 加 301 或新页面里的一行"这页已经并入 X"，别让外链 404。Hugo 用 `aliases` 字段即可。

## 四、首屏重写（5 秒讲清楚）

现在首屏：一台显示器 + 一个人在看你，没有任何一句"这是什么"。

改成四行（全部用现有数据，不需要新接口）：

```
公网安全观测站                                    ← 标题
一个人搭的多源 SOC：7×24 采集主机、网络、蜜罐三路数据，
7 天 29.3 万条告警，94.86% 的噪音被自动压掉。
                                                  ← 一句话
[ 今日告警 15.2 万 ]  [ 最凶来源 荷兰 · 10.8 万 ]  [ 上线断言 85 项 ]
                                                  ← 三个硬数字（实时，来自 /api/public/*）
[ 看今天发生了什么 ]   [ 这套东西怎么搭的 ]        ← 两个按钮
```

下面紧跟一块「现在正在发生」：最近 10 条告警的来源国 + 手法 + 命中的规则名（滚动条），它是"活的"最好的证据。

角色（桐莉栖）保留，但**降级为解说员**：
- 只在首页出现，站在数据旁边做一句口头点评（现成的语音系统）；
- 去掉其它页面的角色装饰与语音，让"安全"成为第一印象。

## 五、简历口径（三条，可直接用）

> 这三条与站内页面一一对应，面试官点开就能验。

1. **独立设计并运维公网安全观测站**：2 台云主机 + 13 个容器承载 Wazuh（主机）、Suricata（网络）、Cowrie/Dionaea（蜜罐）三源采集，7×24 运行，7 天累计 29.3 万条真实攻击告警。
2. **建成告警降噪与日报流水线**：自定义检测规则 10 条，把 94.86% 的低价值事件自动归档，每日 08:10 生成含语音摘要的可读日报并邮件送达；单日最多 15.2 万条告警压缩成 1 页。
3. **建立可复核的工程底座**：85 项构建断言 + 原子发布（失败自动回滚）+ 整树哈希校验；站点 190+ 页面、3 Mbps 链路上首屏 < 1 s、首页 877 KB。
4. （可选第四条）**靶场与红队**：7 台靶场容器、27 例红队回归；自查发现并修复 4 条护栏绕过（命中率 23.53%）。

## 七、验收口径（怎么算"升级成功"）

1. 陌生人打开首页，**5 秒内**能说出"这是个安全观测站，一个人做的，数据是真的"。
2. 任意一个数字，**三次点击内**能看到它的原始出处。
3. 简历上那三条，每一条都能在站内找到对应页面并当场演示。
4. 导航不超过 5 项，首屏不超过 4 种视觉元素。
5. 3 Mbps 下首屏 < 1.5 s（当前 877 KB / FCP 764 ms，有余量）。

## 八、需要你拍板的三件事

1. **角色去留**：保留成"解说员"（首页 + AI 问答），还是彻底去掉走纯工具风？
2. **笔记位置**：留在站内但降级为"学习记录"，还是挪到子域/独立栏目，主线只留安全？
3. **首页让位**：接受把现在的 CRT 舞台降为开屏动画、1.2 s 后让位给数据（这是"第一印象"改变的关键一步）。

这三条定了，D1 就能开工。
