## 五、硬约束（违反即返工 ✗）

```
① **视觉必须与现有六页同源**：暗色玻璃面板 + 现有配色 token + 现有圆角/阴影/字级（读 §一④ 的 shell-style ✓）

③ **不许假数字**：空态/失败态写"读不到" ✓ 不许编示例数据 ✗；也不要设计"演示数字" ✗
④ **移动端必须可用**：手机竖屏也要能看（现有页面已适配 ✓ 延续 ✓）
⑤ 首屏字节有预算：单页首屏 **≤1650KB**（当前主页 860KB / ai 1592KB ✓）
   ⇒ 你的设计要标注"哪些元素首屏加载、哪些懒加载" ✓
⑥ 你可以做：设计文档 + 组件规格 + **可直接嵌入的 HTML/CSS 原型片段**（前缀化 ✓）+ 交互说明 ✓
   你不可以做：改 `layouts/**`、改 `static/**`、`git add/push`、发布、动服务器配置 ✗
```

## 六、交付格式（照这个给，落地方照着就能实现 ✓）

```
① **信息架构**：每块放哪一页、哪个位置（左/右/主区/折叠），与现有卡片的关系 ✓
② **组件规格**：宽高/间距/圆角/字级/颜色（**引用现有 token**，别写绝对值 ✗）；空态、加载态、失败态各长什么样 ✓
③ **HTML + CSS 原型片段**：可直接嵌入、选择器已前缀化、无第三方依赖 ✓（纯静态、可离线打开 ✓）
④ **数据映射表**：组件字段 ← 哪个接口/文件的哪个字段 ← 要不要脱敏/截断/格式化 ✓
⑤ **交互**：展开/折叠、hover、tab 切换、刷新节奏（几秒/几分钟）、是否要手动刷新 ✓
⑥ **验收清单**：肉眼可判断的条目（例："封禁榜里的 IP 必须全部打码"✓、"失败时显示读不到"✓）
⑦ **与现有元素的兼容说明**：会不会和现有卡片抢空间、移动端要不要折叠 ✓
```
