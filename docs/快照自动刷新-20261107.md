# 快照自动刷新（GitHub Actions）· 设置说明

1. 为什么要它：数据页读的是同源静态快照 `static/api/public/*.js`（不是 demo.xiaokeqing.cn 实时接口，那条隧道对大响应只有 ~600 B/s）。快照不刷，页面上的数字就是旧的 —— 这份工作流每 10 分钟刷一次。
2. 文件：`.github/workflows/snapshot.yml`，`on: schedule: ["*/10 * * * *"]` + 手动 `workflow_dispatch`，只管一件事：抓 12 个端点写回 `static/api/public/`。
3. 加 secret：仓库 → **Settings → Secrets and variables → Actions → New repository secret**，Name 填 `XK_SNAP_URL`，Value 填 `http://<srv1>:9900`（本机 curl 实测就是 9900 端口）或经隧道/反代后的等价地址；**结尾不要带 `/api`**。
4. 网络前提（唯一硬前提）：GitHub 托管的 runner 在公网，够不到家里那台 srv1 的内网地址 —— Value 必须是公网可达的（隧道域名 / 公网地址 / 自建 runner）。给不通时整轮会红一次并打印「12 个端点全部抓取失败」。
5. 没有 secret 时**不失败**：第一步打印 `skip: XK_SNAP_URL 未配置` 后 exit 0，后面步骤全部被 `if` 跳过，整条流水线干净结束（站点发布照旧）。
6. 12 个端点 = 仓库里已入库的那 12 个文件：`home.js alerts.js alerts5.js geo.js metrics.js stories.js webstats.js password.js kb.js deploy.js eval.js daily/index.json`。
7. 单个端点抓失败（超时/非 JSON）只打 `::warning::` 并**保留旧文件**，不整轮失败 —— 快照新旧不一，比一条都刷不上危害小。
8. 提交口径：`git diff --quiet -- static/api/public` 为真就不提交（数据没变时空提交一天上百条，会把真改动埋掉）；有变化才 commit + push，身份固定 `github-actions[bot]`，信息 `chore(snapshot): 定时刷新 API 快照（<UTC 时间>）`。
9. 推送被拒（远端刚有人推）会自动 `pull --rebase` 重试 3 次；仍失败就红一次，下一轮 10 分钟后自然再试。
10. 没有 secret、或想立刻刷一次：本机跑 `powershell -ExecutionPolicy Bypass -File scripts/snapshot-refresh.ps1`（ssh 抓 srv1 → 哈希比对 → 有变化才 commit/push）。这条路径的管理员计划任务站主没批，才轮到 Actions。
