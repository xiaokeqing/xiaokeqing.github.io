【第三步：判定"展示 / 不展示"，每条都要给理由】
 · 判定维度：① 是否泄露内部信息（内部 IP/凭据/拓扑/规则细节 ✗）② 是否可被滥用（封禁清单、绕过手法 ✗）
   ③ 是否有叙事价值（访客看得懂、显得专业 ✓）④ 隐私与合规（攻击者 IP、地理位置 —— 可展示但**必须脱敏** ✓）
   ⑤ 维护成本（要不要人手更新 ✓）
 · 明确分三类：**A 适合展示（现在就做）｜ B 可展示但要脱敏/降级（给出脱敏规则 ✗）｜ C 不适合展示（说明理由 ✓）**
 · 红线：不许把**攻击者完整 IP**、**真实口令明文**、**内部拓扑/端口/规则细节**、**管理面地址**放上去 ✗
   （现有博客已有"蜜罐凭证只给结构、IP 打码"的做法 ✓ —— 照这个口径延续 ✓）

【第四步：展示规划（结合博客现有六页版式，别新造风格 ✗）】
 · 先看现在的页面长什么样：`layouts/index.html`（主页 CRT 场景）、`layouts/partials/xk-demo/*`（作战室 OPS-ROOM 等），
   以及 `docs/交接-六页整份搬demo-20261014.md`（哪些是原型缺陷 ✗）
 · 规划要回答：**放在哪一页/哪个位置**（尽量复用现有卡片与玻璃面板样式 ✓）、**显示什么字段**、
   **数据从哪个接口来**、**取不到时显示什么**（写"读不到"，不许编 ✗）、**多久刷新一次**
 · 重点设计这三块（我已知它们现在**完全没露脸** ✗）：
     ① **处置成果**（`blocked-ips.json` → "已处置/封禁"卡片，IP 必须打码 ✓）
     ② **攻击故事线**（`stories` → 一次攻击的时间线卡片 ✓ 最吸引人 ✓）
     ③ **知识库**（`kb` → 术语/攻击手法科普栏目 ✓）
 · 每块都要给：**字段清单 + 数据来源 + 空态文案 + 刷新策略 + 脱敏规则 + 视觉落点**
