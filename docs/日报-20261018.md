# 每日攻击日报：用法与口径（2026-10-18）

> 这是 `scripts/daily-report.py` 的说明书：怎么跑、每节数字怎么来的、读不到时报告长什么样。
> 生成器**不用 LLM、不联网、不读数据库**：只把本机三个日志文件按固定模板算成 Markdown + HTML，离线也能跑。
> 姊妹文档：[每周战报-部署说明.md](每周战报-部署说明.md)（周报生成器 `scripts/weekly-report.py`）。

## 1. 定位与边界

- **每天 08:05 的角色**：把「昨天 00:00–24:00（UTC+8）」的攻击面摊开给值班的人看——告警量、来源、端口、口令结构、规则命中，以及**这些数字是不是真的**。
- **明确不做**：不做处置、不改防火墙、不写 Suricata/Wazuh 规则、不联 LLM、不拼月报。报告里的每个数字都能用 `python3 -c` 或 `jq` 从原始文件复算出来。
- **为什么不用 LLM 模板**：日报每天同一套结构，模板化后输出稳定、可 diff、可离线跑；LLM 版本只在「措辞润色」上有价值，换来的是不可复现和不必要的网络依赖。

## 3. 怎么跑

### 3.1 srv2 上（常规）

```bash
# 最省事：三个默认路径都吃到，出「今天」的日报
python3 scripts/daily-report.py --out /opt/secagent/reports/daily-%Y-%m-%d.md

# 显式给路径（路径不存在时不会假装有数据）
python3 scripts/daily-report.py \
  --eve /var/lib/suricata/eve.json \
  --cowrie /opt/cowrie/logs/cowrie.json \
  --ci /opt/secagent/reports/ci/latest.json \
  --out /opt/secagent/reports/daily-%Y-%m-%d.md

# 补跑昨天，同时只出 .md 不出 .html
python3 scripts/daily-report.py --date yesterday --no-html --out /tmp/daily-yesterday.md

# 某个具体日期（08:05 跑时一般不需要；补历史用）
python3 scripts/daily-report.py --date 2026-10-17 --out /tmp/daily-1017.md
```

- `--out` 里的 `%Y-%m-%d` 会被替换成**报告日期**（不是当前时间）。
- `--out` 缺省写 stdout：`python3 scripts/daily-report.py > /tmp/daily.md` 也可，但不会自动生成 HTML。
- 用 `--out-dir /opt/secagent/reports` 等价于 `--out /opt/secagent/reports/daily-<日期>.md`。

### 3.2 本机调试（无 srv2 文件时）

```powershell
# Windows / macOS 上也能跑：拿测试样本喂它
python scripts\daily-report.py --eve testdata\eve.json --cowrie testdata\cowrie.json --ci testdata\ci.json --date 2026-10-18 --out out\daily.md
```

### 3.3 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--eve PATH` | `/var/lib/suricata/eve.json` | Suricata JSON Lines。**文件 / 目录 / glob（含 `*?[`）/ `-`（stdin）都行；可重复**（如 `--eve eve.1.json --eve eve.json`）。目录按「`eve` 开头的文件」聚合；glob 按字典序 |
| `--cowrie PATH` | `/opt/cowrie/logs/cowrie.json` | Cowrie JSON Lines，同上（目录前缀 `cowrie`） |
| `--ci PATH` | `/opt/secagent/reports/ci/latest.json` | 一致性巡检 JSON（只读它的汇总字段，见 §4.8） |
| `--date D` | `today` | `today` / `yesterday` / `2026-10-18`。窗口 = 该日 00:00→次日 00:00（按 `--tz`） |
| `--tz NAME` | 环境 `TZ`，否则 `Asia/Shanghai` | 「今日」的时区；本机没有 tzdata 时自动退回 `--utc-offset` |
| `--utc-offset H` | `8` | `--tz` 解析失败时的固定偏移（小时） |
| `--top-sources N` | `10` | 来源 IP Top N |
| `--top-ports N` | `5` | 被攻击端口 Top N |
| `--heartbeat-sids LIST` | `2013031,1000108` | 心跳自噪声 SID（逗号分隔）。改小了会漏识别；不含 `2013031` 时会往 stderr 提醒 |
| `--heartbeat-dst LIST` | `169.254.0.4` | 心跳自噪声的目标地址（逗号分隔） |
| `--note TEXT` | 空 | 人工备注，写进导语之后；会同时留在报告里 |
| `--out PATH` | 无（stdout） | Markdown 输出路径，可含 strftime 占位符 |
| `--out-dir DIR` | 无 | 等价 `--out DIR/daily-<日期>.md`；与 `--out` 互斥 |
| `--no-html` | 关 | 只写 `.md`，不导出 `.html` |

### 3.4 退出码

| 码 | 含义 | 报告在哪 |
|---|---|---|
| `0` | 三个数据源都读到 | 已写出 |
| `2` | 三个都读不到 | **仍写出**（记录「今天读不到什么、为什么」） |
| `3` | 部分读不到（1–2 个） | 已写出 |
| `4` | 参数错误（路径冲突、`--out` 时间格式非法、`--top-*` ≤ 0 等） | 不写 |

cron 判「成功」用 `0`；`2/3` 是「有数但不全」，看 stderr 的 `[读不到]` 行。

## 4. 日报结构（1–9 节）与每节口径

### 4.1 今日概览

| 指标 | 口径 |
|---|---|
| 告警总数（含心跳自噪声） | `event_type=alert` 且在今日窗口内的行数 |
| 其中心跳自噪声 | 目标地址命中 `--heartbeat-dst`（默认 `169.254.0.4`）**或** SID 命中 `--heartbeat-sids`（默认 `2013031`、抑制规则 `1000108`） |
| 真实告警数 | 告警总数 − 心跳自噪声 |
| 去重源 IP（真实告警） | 真实告警里的 `src_ip` 去重（**含内网源**，如 `10.0.0.10`；不静默丢） |
| 高危数（severity=1） | 真实告警里 `alert.severity == 1` 的条数（severity 为字符串 `"1"` 也认） |
| 蜜罐会话数（去重） | 今日 `cowrie.*` 事件的 `session` 去重 |

**1.1 蜜罐细分**：会话建立 / 登录尝试（成功 / 失败）/ 命令输入 / 蜜罐源 IP / 事件总数。
注意口径：**蜜罐接受一切口令，`login.success` ≠ 被攻破**；「登录尝试」= 成功 + 失败。

### 4.2 Top 10 来源 IP

- **不在 Top 榜、只在汇总行展示**：心跳自噪声的单列计入 `--heartbeat-dst` 的目标 IP（如 `10.0.0.10`）**不进 Top 榜**，避免「Top 来源永远是内网心跳」。
- Top 榜 = 真实告警里的 `src_ip` 计数；展示时按 `/24` 前缀合并成一行（`a.b.c.x`），并标出其中含几个原始 IP、独立目标端口数、主要目标端口；同条数按前缀字典序（结果稳定，可 diff）。
- **内网源不掩码**：如 `10.0.0.x` 这类源会原样出现在榜上——它可能正是宿主机/内网里的东西，值得看清。
- 公网 IP 按周报口径掩码成 `a.b.c.x`（IPv6 前 4 段 + `x::`）；去重与计数始终用原始值。

### 4.3 Top 5 被攻击端口

- 按「真实告警」的 `dest_port` 计数；附常识映射（22 ssh / 80 http / 443 https / 3306 mysql / 6379 redis / 2222 ssh-alt …），未知写 `—`。
- 没有 `dest_port` 字段的告警（`null`/缺失）不计入端口榜，也不编一个 `0` 号端口凑行；§1 的告警总数仍包含它们，差距在 §8 可对账。

### 4.4 口令结构分布（只写结构，不写明文）

- 统计范围：今日 Cowrie **登录尝试**（`cowrie.login.success` + `cowrie.login.failed`）。
- 结构 = `字符类别 · 长度桶`：
  - 类别：纯数字 / 纯小写字母 / 纯大写字母 / 大小写混合字母 / 字母+数字 / 字母+数字+符号 / 字母+符号 / 数字+符号 / 纯符号 / 空口令 / 无口令字段；
  - 长度桶：`<6` / `6-8` / `9-12` / `>12`。
- **明文永远不出现**：`password` 字段只在内存里用于算结构与「是否等于用户名」「是否命中内置高频弱口令小表」两个布尔，写完即丢。
- 「其中失败 / 其中成功」两列用来区分「喷库的弱口令」和「蜜罐让进的口令」。

### 4.5 规则命中排行（心跳自噪声 vs 真实告警）

- 先单列一张 **心跳榜**（命中 `--heartbeat-dst` / `--heartbeat-sids` 的 SID），再列**真实告警 Top 10**。
- 为什么要分开：2026-10-18 04:25 的实测基线是 294,112 条 alert 里 279,099 条（**94.9%**）是 `10.0.0.x → 169.254.0.x:80 POST /ca_report.cgi`（SID 2013031）的云 agent 心跳——这不是攻击。混在一起排，「Top 规则」永远是同一条。
- 心跳占比会和 **94.9% 基线**对比：±1.5 个百分点内写「与基线基本一致」，否则写「与基线偏离，值得看一眼」；心跳一条都没命中时单独说明（可能是当天没跑云 agent，或者抑制规则生效——此时「占比 0」不能读成「没有心跳流量」）。
- 私有规则 SID 表：`1000101`–`1000108`（`detections/suricata/xk-lab.rules`）里 `1000108` 是心跳**抑制**规则（opt-in，默认未部署），其余是真实检测。

### 4.6 与昨日对比

- **同文件、同口径、现场重算**：今天/昨天都用同一份 `--eve` 从头扫，绝不拿周报的旧数字硬拼。
- 变化 = 今日 − 昨日，百分比保留 1 位；昨日为 0 时只写绝对差并注「（昨日 0，百分比无意义）」，不编百分比。
- `暂不可比` 只在两种情况出现：昨日读不到、或某天只覆盖半段。

### 4.7 一句话结论

固定句式，一句话串起：`今日 alert X 条，其中心跳跳过、真实告警 Y 条、涉及去重源 IP Z 个、高危 H 条；蜜罐会话 A 个、登录尝试 B 次；主要打 P 端口；Top 来源 S；与昨日比 V；覆盖缺口 W`。空数据时也出这句（「今日 0 条」），不空着。

### 4.8 取数状态（读不到的原因原文）+ 附加段

- 表格：每个数据源 → 参数、状态、行数/可用、覆盖区间（UTC+8 呈现）、文件时间戳 + 是否轮转过期（> 36 小时没更新会标「可能已轮转」）。
- **8.1 一致性巡检**：读 `ci/latest.json` 的 `ts` / `ok` / `failed` / `checks` / `site_integrity`，只展示不改写；`ts` 超过 20 分钟没更新会标「巡检可能没在跑」；字段缺失写「未提供」，不编。
- **8.2 私有规则识别口径**：SID → 含义 → 本报告怎么归类（心跳栏 / 真实栏）。改规则时同步改这张表。
- **报告 §8 顶部的覆盖缺口旗标**：把「今日缺 X、昨日缺 Y」逐条列出（同一缺口在多个指标上只写一行），并给「缺口里没读到事件 ≠ 没攻击」的提醒。

## 5. 数字纪律（最容易踩的坑）

1. **「读不到」≠「0」**：文件不存在/无权限/解析失败，单格写 `读不到（原因）`，不写 0；只有「文件读到 + 该日窗口被覆盖」时 0 才是真的 0。
2. **半段**：日志轮转/截断会让某天只覆盖半段。此时数字标 `*半段`，在 §6 脚注给出缺口时段，并在 §8 复述；不拿半段冒充全天。
3. **心跳自噪声**：默认 `169.254.0.4` + SID `2013031`。节假日/换云链路可能导致新目标，跨月统计别直接拿日报口径拼，改用周报或临时补 `--heartbeat-dst`。
4. **坏行**：JSON 坏 / 时间戳坏的行跳过并计数；坏行不为 0 时，数字是下限（报告会在 §8 注明）。
5. **口令**：只出结构，永不出明文；`password` 是 `null` 时写「无口令字段」，不是「空口令」。
6. **IP 掩码**：公网源 `a.b.c.x`；内网源不掩码；自由文本（规则名、命令片段）里的 IP 也会被掩掉，避免把受害者/内网细节带出去。
7. **数字格式**：千分位逗号（`2,052`）；百分比 1 位小数；Top 榜同数按字典序，保证两次跑 diff 为空。

## 6. HTML 输出

- 与周报同一套渲染：正文用 `weekly-report.py` 的 `render_md_html()`（同目录动态导入，页面模板也复用同一套内联 CSS）→ 日报和周报放在一起视觉一致；**若同目录找不到 `weekly-report.py`，HTML 不生成、只往 stderr 说明原因**（`.md` 照常落盘）。
- `.html` 与 `.md` 同目录同名（`daily-2026-10-18.md` → `daily-2026-10-18.html`）。
- **不写目录 index.html**：日报和周报共用 `/opt/secagent/reports/`，各写 index 会互相顶掉；站点挂靠那一步另行处理。
- 导出失败只警告（`.md` 一定先落盘），不连累退出码。

## 7. 定时任务建议（srv2）

```cron
# 每天 08:05 出昨天的日报（UTC+8 的「昨天」即 cron 前一天的 00:00→24:00）
5 8 * * * cd /opt/secagent && /usr/bin/python3 scripts/daily-report.py --date yesterday --out /opt/secagent/reports/daily-%Y-%m-%d.md >> /var/log/secagent-daily.log 2>&1
```

- 漏跑/补跑：`--date yesterday`（或具体日期）。
- 日志保留：脚本不负责轮转，`/var/log/secagent-daily.log` 自己配 `logrotate` 或改用 cron 直接抛弃 (>/dev/null)。
- 首次部署前先手动跑一次，确认三个默认路径在这台机器上的真实位置（见 §8 的实测口径）。

## 9. 排错表

| 现象 | 原因 | 处理 |
|---|---|---|
| 概览全是「读不到（文件不存在）」 | 路径不对 / 容器内路径与宿主机不同 | 在 srv2 上 `ls -l` 确认真实路径，用参数覆盖 |
| 概览全是「读不到（无读权限）」 | python 进程身份读不了该文件 | `sudo -u` 切到能读的身份，或给 644 + 目录 x |
| 「心跳自噪声」= 0 但你知道有心跳 | `--heartbeat-sids` 改没了 `2013031` 或 `--heartbeat-dst` 没给 | 用默认值；stderr 会提示 |
| 「与昨日对比」全是「暂不可比」 | 昨日被轮转掉 / 只覆盖半段 | 补历史文件（`--eve eve.1.json --eve eve.json`），或接受「暂不可比」 |
| 某天数字标 `*半段` | 文件覆盖不足全天 | 见 §8 顶部旗标里的缺口时段；月底拼月报时用周报口径 |
| HTML 打开是源码 | 用了 `--no-html` 或 `.html` 没生成（权限/目录不存在） | 看 stderr「HTML 导出失败」；`.md` 不受影响 |
| 时间全差 8 小时 | 机器 TZ 不是 UTC+8 且没给 `--tz` | `--tz Asia/Shanghai` 或 `--utc-offset 8` |
| `passlib`/`jq` 类依赖缺失 | 本脚本零第三方依赖，不会发生 | 若真报 ImportError，说明 python < 3.8 |

## 10. 已知限制

- **只支持 JSON Lines 的 eve.json / cowrie.json**：如果 Suricata 配了 `filetype: regular` 之外的自定义格式，需要先转换。
- **心跳识别是启发式**：目标地址 + SID 双闸；如果云 agent 换了目标或 SID 变更，会漏判（漏判表现为「真实告警」虚高），需同步 `--heartbeat-dst/--heartbeat-sids` 与 §8.2 表。
- **跨天会话**：Cowrie 会话按事件时间归属当天，跨零点的会话会在两天各计一次（与周报口径一致）。
- **DNS/HTTP 细节**：日报只统计 alert 面，不展开 DNS 查询/文件下载 hash（周报有专章）。
- **不写 index.html**：与周报共用目录时的站点索引另行处理（见 §6）。
