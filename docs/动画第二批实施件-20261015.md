## 4. 新增的 4 条边（★ 可直接执行的清单）

**事实依据**：`idle → 侧脸族` 原本**没有任何直边**（`idle` 的正概率出边只去 `idle/idle2/idle_mic_wind/idle1/trans_standby/idle_closed_eye`），
侧脸族 3 个节点只能靠 `trans_standby→…` 这条 0.3/0.1 的窄路进入 ⇒ 概率游走时"侧脸"几乎不出现。
站主要"一个正脸一个侧脸" ⇒ 加 4 条边把这个缺口补上。

| # | from | to | from_id | to_id | prob | 宿主触发? | 为什么是这个 prob |
|---|---|---|---|---|---|---|---|
| 1 | `idle`（根，正脸） | `idle_side_wind` | `_8ms718k` | `_cpu0zpb` | **0.1** | **否**（prob≠0 ⇒ 自动游走可走 ✓） | 与既有的 `idle→idle_closed_eye` 同量级；`idle` 正概率出边和 0.9 → 归一化后 ≈11.1% |
| 2 | `idle1`（正脸变体） | `idle_side_soft_wind` | `_5qqy7vp` | `_vo874gi` | **0.15** | 否 | `idle1` 现在只有 `idle1→idle1`(0.15) 与 `idle1→idle`(0.85) ⇒ 侧脸占 15% |
| 3 | `idle2`（正脸变体） | `idle_side_soft_wind` | `_6fknbp9` | `_vo874gi` | **0.15** | 否 | 同上（`idle2` 自环 0.7 / 回 idle 0.3 ⇒ 侧脸占 15%） |
| 4 | `idle_side_wind`（侧脸） | `idle`（正脸） | `_cpu0zpb` | `_8ms718k` | **0.3** | 否 | **补一条回程边** —— 原来侧脸族只能在 `wind/soft/butterfly` 三个节点里自己打转，回不到正脸 ⇒ 会"一直侧着脸" ✗。0.3 与同类回程边（`idle_mic_wind→idle` 0.2 / `idle_side_soft_wind→wind` 0.3）一致 |

**为什么不是宿主触发边**：`prob=0` 的边是"宿主触发入口"（`host_triggered_entries`，现 9 个），
自动游走永远不选它们。这 4 条**要的是"她自己会走到侧脸"** ⇒ 必须是正概率边 ✓
（视线跟随的**转向偏置**再在概率上叠一层 ×1~3，两者不冲突：一条管"能走到"，一条管"看起来在追你看的方向"）。

**验证**：`tools/verify-anim-batch2.mjs --walk 1` 会输出 `gazeEdgesHit`（这 4 条里走到了哪几条）✓

**资产代价**：侧脸族 3 段 medium 图集 = `idle_side_wind` 1,211,630 B + `idle_side_soft_wind` 1,087,574 B
+ `idle_side_butterfly` 4,462,158 B ⇒ 状态机游走的"新暴露面"约 **0.3 MB/段**（带宽闸 `SM_DEFAULT_MAX_BYTES=6MB` 不变）✓

## 9. 这次会话的坑（供下一批参考）

```
① PowerShell 的 `Set-Content`/`-replace` 写 UTF-8 Python 文件会把**中文注释写成乱码**
   （实测：一个仓库外工具脚本被写坏，已整份重写修复；真仓库未受影响 ✓）
   ⇒ 改文件一律用工具直接写，不要用 pwsh 做编码往返
② 控制台输出中文/✓ 需要 `$env:PYTHONIOENCODING='utf-8'` + `[Console]::OutputEncoding=UTF8`，
   否则 Python 在 GBK 控制台上抛 UnicodeEncodeError（脚本逻辑没错，是终端的事）
③ `git apply` 验证要在**含 .git 的副本**上做：`--unsafe-paths` 做不到"改仓库外路径"，
   而直接对真仓库 apply 违反唯一写入者纪律 ⇒ 本次做法 = 把 `.git` + 3 个目标文件拷到仓库外，
   `git -C <副本> apply` 逐份跑（6/6 PASS），最后核对终态与成品**逐字节一致** ✓
④ 位图抖动（dithering）会污染差分：本机图集里背景/头发有 ±5~10 的噪点，
   阈值 18 的整帧差分会把"整张图"都判成变化（第一次测量就踩了）
   ⇒ 眼部定位必须限定脸部内框 + 阈值 ≥45（本次最终用 12× 网格目视定标 + 眼带差分复核）
```
