## 三、规则（强制，接线同批）

| # | 规则 | 说明 |
|---|---|---|
| **R1** | **同一组不许永远选同一条** | 覆盖 `fallback`、`status`、`idle_banter`、`greeting`（尤其前两组：兜底句最容易变成"每错必同一句"） |
| **R2** | **语义决定子集，随机只在子集内发生** | `status` / `fallback` / `event` 先用**状态语义**筛出候选子集（429 ≠ 离线 ≠ 无数据；暴力破解 ≠ 端口扫描），再在子集内随机。**不许为了"不重复"把"被限流"说成"没数据"** ✗ —— 正确性永远压过多样性 |
| **R3** | **加权随机 + 短期不重复** | 见 §四的算法与参数 |
| **R4** | **组内只有 1 条时不假装随机** | 如实记 diag（`noAlternative`），允许重复；同时把它列进"待扩句"清单（线上 `idle_banter` 现在就是 1 条 ⇒ 这条马上会触发） |

## 四、算法（一句话 + 参数）

**一句话**：需要播某组台词时，先按语义筛出子集 `C0`，再在 `C0` 里**排除最近 N 条已播 id**得到 `C`，
在 `C` 上按 **`w_i = 1 / (1 + 近 20 次播放中出现次数)`** 加权随机抽一条，抽中后把该 id 压入 FIFO 记忆 ✓。

| 参数 | 取值 | 为什么 |
|---|---|---|
| **N（短期不重复窗）** | **4**（同一组内的"最近 4 条已播 id"降权/排除） | ① 一次会话里可见的触发约 **10~20 次**，N=4 ≈ 覆盖最近**2~4 分钟**，足以让访客听不出重复；② 组内最小规模是 `fallback`=**3** 条，N 必须 **clamp 到 `组内条数 − 1`**（=2）才保证有候选；③ N=5 会把 `status`/`event` 这类 9~12 条的组压成"4 选 1"，**多样性反而下降**；④ N=2 挡不住"隔一句又回来" |
| `N_eff` | `min(4, groupSize − 1)`；`groupSize == 1` ⇒ 不设约束 | 防"无候选"死锁 |
| 权重窗 | 最近 **20** 次播放（会话级，按组分别计） | 20 次 ≈ 一次会话的完整可见触发量；再长就把"短期"变成"长期惩罚"，会**反过来锁死**某几条句子 |
| 权重 | `w_i = 1 / (1 + count_i)` | 线性倒数：没播过的权重 1，播过 1 次降为 1/2，2 次降为 1/3 —— 简单、可单测、不需要指数/温度参数 |
| 随机源 | `Math.random()` | 台词选择**不需要密码学强度**；不引 `crypto.getRandomValues`，避免给首屏加依赖（与既有状态机里 `smRng` 的选择一致） |
| 记忆持久化 | `localStorage['xk-line-recent-v1']`，按组存 id 数组（上限 `N_eff`） | 刷新页面不重置，"刚听过又听到"才算复读。**只存 id**，不存文本 / 时间戳 / 用户标识（无隐私面） |
| 降级顺序 | ① `C = C0 \ 最近N_eff`；② 若 `C` 空 ⇒ `C = C0 \ 最近1条`；③ 若仍空 ⇒ `C = C0` 并记 diag | 任何情况下**必须能出声**，不许为了"不重复"卡住（静默失败比复读更糟）✗ |
| 去抖 | 保留 `layouts/index.html:1378` 的"同一句正在播则不重播" | 这条是**防叠音**，不是防复读，语义不同、两条都要留 |

**必须同时记 diag**（可 grep 自证）：`linePick{group, subset, chosenId, window:[…], noAlternative:true|false, fallbackLevel:1|2|3}`。
