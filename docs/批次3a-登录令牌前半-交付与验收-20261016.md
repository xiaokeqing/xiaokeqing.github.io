## 四、★新发现（要交回后端线，站点线改不了）

**跨域下 `Retry-After` 不是 CORS 安全响应头。**
`_shots/probe-3a-login.json` 的 `04-429-*` 两场景实测：后端回 `Retry-After: 7` 但不回
`Access-Control-Expose-Headers: Retry-After` 时，浏览器里 `r.headers.get('Retry-After')` **恒为 null**
⇒ §10.5 第 4 条的 N 取不到（只能退到默认 60），**表现是"限流提示的秒数永远显示 60"**。

- 站点线已做的兜底：头 → `body.retryAfter` / `body.data.retryAfter` → 60（三层，已用探针钉住）。
- **后端线需要做的一条**（否则头部路径白写）：429 响应补
  `Access-Control-Expose-Headers: Retry-After`。
- 后端**不补也能用**：只要 429 的响应体里带 `retryAfter`（秒）即可走第 2 层兜底。
