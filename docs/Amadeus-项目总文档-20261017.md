## 4. 处置与封禁链路

1. 规则判定（Wazuh 告警 / 阈值）给出建议处置；
2. 高危动作需人工审批（模型只解释不拍板）；
3. 落地真实防火墙规则（可解封，`unblockMode=REAL`）；
4. 全过程写审计留痕，前端只读展示，误处置有拦截机制。

## 5. 公开面防护

- 统一数据出口闸门（唯一出口：`/api/public/*`，全部只读）；
- 访客限流 6 次/分钟/IP，超限 429 + `Retry-After`；
- 站主令牌（`X-User-Token`）走同一套登录校验后放行，不降低安全边界；
- 提示词注入护栏（`PromptInjectionGuard`），不可信内容统一包裹；
- 问答契约：**只解释、不取证**；检索不到依据直接拒答。

## 6. AI 问答与角色表现

- 检索：BM25 稀疏 + 稠密向量 → RRF 融合 → 轻量重排（`VectorSearchService` + `InternalDocsTools`）；
- 答案附引用来源；自动化评测集（`RedTeamEvalService`）验证拒答与防幻觉；
- 语音：本地 GPT-SoVITS v3 克隆音色，台词库 162 条（rev6 七条「机器口吻讲功能」已上线；rev7 新增 `nav_what`/`nav_lab` 与 10 条垫音 `lead_in`）；另有 484 条原作原声语料，**当前站点零引用**（见 §14.2）；
- 角色表现：40 段透明 VP9+alpha WebM（8.36 MB）+ 概率状态机驱动眨眼/视线/口型；离屏 `<video>` 建好后从不进 DOM，因此 HTML 源码里搜不到视频标签（见 §16.3）；低端设备降级。

## 9. 已知缺口与风险（不遮掩）

1. **靶场已对外开放（口令门禁）**：Pikachu 跑在 srv2 `labnet`（禁出网、独立 IP `172.20.0.10`），`lab.xiaokeqing.cn` 经隧道 → nginx `auth_request` → 口令页（`lab_token` 签名 Cookie，24h）。实测：无 Cookie 302、错口令 401、对口令 200。**访问码不在任何公开页面**；简历可写「可登录访问的本地靶场」，但不要贴地址+口令。
2. **实时 TTS 未接（不阻塞）**：线上语音 = 本地 GPT-SoVITS v3 预生成的固定台词（rev6 七条 + 历史音轨）+ 484 条原声，**完全不经过任何云 TTS**。后端 `TtsService` 里那条 Fish Audio 路径只是「实时合成」的可选实现，默认关闭、**缺 key 不影响任何功能**。若要做实时语音，首选是**已复刻的阿里云 CosyVoice**（`cosyvoice-v3.5-plus-kurisu-8eacef0d…`，日语可用；免费额度 10,000 字符、已用 173）——但中文念读被实测证伪（跨语言串味），要念中文需后端多输出日语版 `speakJa`，属二期改动。
3. **旧语音：已定只删 5 条**（2026-10-17，E1=A）。逐条核对后只有 `greet_first`、`greet_back`、`page_intro_m14/m15/m16`（讲已删的 `/about` 页）确实过时，其余 150 条仍在用；体积 11.06 MB 中约 1.5 MB 属于不再播放的旧条目。详见 §13 E1。
4. **`/projects/` 曾 404，已修**：`content/projects/` 由提交 `7c174ea` 恢复，线上 `/projects/` 现为 200（88 KB）。此前记录的 404 属过期信息。
5. **旧博客：站主决定删除**（2026-10-17，E4）。`xiaokeqing.github.io` 现为 2.4 KB 的「本站已迁移」提示页，站主判定无用，处置方式见 §13 E4；删除动作受「本机无 GitHub 凭证」阻塞（见 §15 C3）。
6. **国内访问 GitHub 慢**：仓库公开可访问，但 github.com 网页在国内不稳定，简历建议放个人主页而非深链。
7. **Cloudflare 往返 ~3.5s**：国内访问 API 有明显延迟，首屏数字会晚 3-5 秒出现（已有「取数中…」占位）。

## 10. 给评审者的建议检查点

1. 打开 `/alerts/`，看英雄数字是否在 5 秒内出现真实值（不是「未取到」）；
2. 点任一条 TOP 来源，看是否拉出该源的事件时间线（IP 应为打码状态）；
3. 在 `/ai/` 提一个「给我某个 IP 的登录凭据」类问题，确认**拒答**而不是编造；
4. 连续提问超过 6 次/分钟，确认 429 + `Retry-After`；
5. 检查 `/api/public/honeypot` 的 `commandsAvailable=false` 是否被前端如实展示为「未接入」。

### 12.4 并行方案要点

- **关键路径是 A 轨道**（prompt → 首句约束 → few-shot → 情绪 → 语音），B/C 与之交错即可；串行约 33h，并行后**约 18–20h 实际工时**。
- **三条硬约束**：①同一时刻只能有一个发布动作（`publish-site-to-srv2.ps1` 会用临时 worktree 切版本，并行必打架）②`_dev/gen-demo-pages.py` 是单点，所有页面壳改动排队，且**必须用 Python 读改写**（PowerShell 回写会写坏）③子代理只准写文件，不准构建/发布/提交。

## 16. 部署、门禁、渲染与发布链（审计用补充事实）

### 16.1 隧道与反向代理

| 域名 | 落点 | 配置文件 | 备注 |
|---|---|---|---|
| `xiaokeqing.cn` / `www` / `static` / `staging` | srv2 nginx `127.0.0.1:18080` | `/etc/cloudflared/static-config.yml` + `/etc/nginx/nginx.conf` | 静态站；`include /etc/nginx/lab.conf` 插在 `nginx.conf:9`（mime.types 之后） |

- **事故记录（已修复）**：`lab.conf` 的 server 块曾排在主站之前，使它成了 `18080` 的**默认 server**，任何不匹配的 Host 都被 302 到口令页。修复方式：主站块显式写 `listen 127.0.0.1:18080 default_server;`，lab 块保持 `server_name lab.xiaokeqing.cn`。验证：`Host: demo.xiaokeqing.cn` → 404（静态兜底）、`Host: lab.xiaokeqing.cn` → 302 门禁、`Host: xiaokeqing.cn` → 200。
- **nginx 不是 systemd `nginx.service`**（该 unit 已 masked）。实际由 `secagent-static.service` 以 `User=xksite` 执行 `nginx -g 'daemon off;'`，reload 走 `-s reload`。此前 reload 静默失败的根因是日志文件 `/var/log/nginx/lab.access.log` 属 root，worker 无写权限（`13: Permission denied`），`chown xksite:xksite` 后恢复。
