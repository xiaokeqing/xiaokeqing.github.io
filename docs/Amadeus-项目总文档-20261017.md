| `/api/public/stories`、`/story?src=` | 单源候选池与点击后懒加载的事件时间线 | 15s |

**脱敏铁律**：公开面**默认展示观测到的真实来源 IP**（`app.public.mask-ips` 缺省 `false`，2026-10-14 站主拍板），但**内网 / 保留 / 链路地址一律显示「内网/未知」**（`PublicIpPolicy.java:30–39`），`/ask` 上访客地址 `masked` 恒为 true；蜜罐凭据只保留结构与频次；自由文本统一过滤（含同类泄漏回归测试）；访客 IP 与内网地址零泄漏；取不到 / 确实没有 / 未接入 三种措辞分开，**绝不补样例值**。

**缓存口径（当晚实测）**：`/api/public/<name>.js` 是内容相同的可缓存别名（响应带 `stale-while-revalidate=90`），CF 侧实测出现过 `EXPIRED` / `MISS`，说明它确实进了缓存；而 `home`、`alerts` 等 JSON 端点仍是 `cf-cache-status: DYNAMIC`，每次都要回源 srv1 再跨境回到浏览器 —— 这就是 §9 第 4 条那 3–4 秒的来源。

## 4. 处置与封禁链路

1. 规则判定（Wazuh 告警 / 阈值）给出建议处置；
2. 高危动作需人工审批（模型只解释不拍板）；
3. 落地真实防火墙规则（可解封，`unblockMode=REAL`）；
4. 全过程写审计留痕，前端只读展示，误处置有拦截机制。

## 5. 公开面防护

- 统一数据出口闸门（唯一出口：`/api/public/*`，全部只读）；
- 访客限流 6 次/分钟/IP，超限 429 + `Retry-After`；
- 站主令牌（`X-User-Token`）走同一套登录校验后放行，不降低安全边界；
- 提示词注入护栏（`PromptInjectionGuard`），不可信内容统一包裹；
- 问答契约：**只解释、不取证**；检索不到依据直接拒答。

### 19.6 发布链「tar 包里没有 index.html」的假失败（根治）

- 现象：发布偶发 `[X] tar 包里没有 index.html`，重试有时就过；成员 2,531 个文件时更容易撞。
- 真因：`scripts/srv2-site-receive.sh:139` 原 `printf '%s\n' "$MEMBERS" | grep -qE '(^|/)index\.html$' || die …` —— `grep -q` 一匹配就退出 ⇒ `printf` 继续写吃 **SIGPIPE(141)** ⇒ `set -o pipefail` 把 141 当整条管道失败。
- 修法：改纯字符串匹配 `case $'\n'"$MEMBERS"$'\n' in *$'\n'index.html$'\n'*|*$'\n'*/index.html$'\n'*) …`，不再有管道。

第一版上线后线上页面是**竖排碎片**：PDF 表格被逐格拆成 `<ul><li><p>对比</p></li><li><p>交换机</p></li><li><p>路由器</p></li></ul>`，课程里「交换机 vs 路由器」「默认子网掩码/CIDR」「DORA 四步」「递归 vs 迭代」「常见 Web 中间件」「虚拟主机」这些核心内容全部失去可读性。

| 步骤 | 结论 |

### 21.3 断句：碎片何时该合并

`MARKER`/标题/代码之外的正文行，只有三种情况才续接到上一段：上一行以 `state['wrap_next']`（越过右边界）结尾、上一行末尾没有句末标点（`END_PUNCT = [。！？：；…”」）)】]$`）、或本行以收尾标点开头。另修两处顺序 bug：非缩进 marker 行先 `flush()` 再起段（否则续行接不上，表现为 pki 的 `件）` 单独成段）；缩进 marker 行也要先 `flush()`（否则待定段落被排到 bullet 之后）。裸编号（`4  、`）例外，不走 marker，避免位权列表被拆段。

### 24.7 /ai/ 的 11.6 MB 为什么没压下去（一次失败的实测，记下来免得下次再撞）

`/ai/` 的大头是 E-mote 模型：`kurisu_c.psb.m.json` 3512KB + `tex#000/001/002` 共 2952KB 的 PNG 纹理 + `resx` 761KB + `FreeMoteDriver.js` 1226KB。

做法（已回滚）：把三张纹理缩到 1024 宽存成 `.webp`、改 `kurisu_c.psb.m.resx.json` 里 `Resources` 的三条路径、

### 27.3 后端：为什么要加一个 `/api/public/daily/index.json`

第一版归档是前端"按日期逐个探"`/api/public/daily/daily-<日期>.json`，实测 30 个并发请求全 `net::ERR_FAILED`。两个原因叠加：

- 公网端点限流 **20 次/分钟**（`PublicApiController` 的 `PublicRateLimiter`）；

### 27.4 部署这一课：`-SkipBuild` 只是验证通道，生产指针在 ACR

`deploy-remote-build.ps1 -SkipBuild -AllowDirty` 用本机编好的 jar 在 srv1 侧构建镜像并重建容器，我据此验证了 `/api/public/daily/index.json` 在 13:10:26 返回 `count=4`、四天日期倒序、`masked=false`。但 **13:10:31 容器被重建，镜像换成 ACR 里那版旧镜像，端点随即 404**。

根因：srv1 上有一整套 systemd 守护 —— `secagent-containerguard.timer`（25 秒）、`secagent-healthwatch.timer`（约 2 分钟）、**`secagent-redeploy.timer`（每 5 分钟读 ACR `stable` 的 digest，与当前运行不同就 pull + 重建 + 硬校验 + 健康核对）**、`secagent-site-probe.timer`、`secagent-srv2deadman.timer`、`secagent-daily-check.timer`。所以：

- **真正的发布姿势**：本机构建 jar → 服务器构建镜像 → 镜像 tag 成 ACR `stable` → `docker push` → `systemctl start secagent-redeploy.service`（或等 5 分钟的 timer）。`-SkipBuild` 那条路 5 分钟内必被回滚，只能当快速验证。
- 推上去的镜像还会被 `srv1-redeploy.sh` 第 5/9 步的 fail-closed 闸门拦住：镜像缺少 `org.opencontainers.image.revision` 就 `[X] 来源不明，拒绝部署`。`secagent:local` 当时只有 `{"org.opencontainers.image.version":"22.04"}`（继承自基础镜像）。
- 修法（已提交 `3a8b15a`）：`scripts/build-on-server.sh` 第 2/4 步的 `docker build` 补两个 label —— `--label org.opencontainers.image.revision=$TARGET_FULL`（完整 commit）与 `--label artifact-md5=$JAR_MD5`（上传 jar 的 MD5）。闸门还会校验 revision 的形状与（若发布指针公告了 commit）两者是否一致；`artifact-md5` 缺失只会降级为 warn。

修复后实测：镜像 `sha256:060e4739…` 带齐两个 label → push 到 ACR 得到 digest `sha256:4dc09123…` → `systemctl start secagent-redeploy.service` 报"当前运行 digest 与发布指针相同 —— 无需变更" → 容器镜像已是新 digest、`/api/health` 200、`/api/public/daily/index.json` **200 / 3164 字节 / count=4**。
