## 2. 对外只读 API（后端 = 唯一数据出口）

| 端点 | 内容 | 缓存 |
|---|---|---|
| `/api/health` | 健康探针（**不在 `/api/public` 前缀下**）：`buildSha`、`uptimeMs`、`vectorStore`、`status` | 无 |
| `/api/public/audit` | 处置审计：封禁总数/生效数/被护栏拦截/执行动作数 + 每条封禁明细 | 45s |
| `/api/public/honeypot` | 蜜罐：总连接、口令结构、登录次数；`commandsAvailable=false`（数据源未接入） | 45s |
| `/api/public/alerts` | 告警流、威胁等级、`stats.byType`、`stats24h.trend` | 45s |
| `/api/public/geo` | 来源国 / 省份 / ASN（DB-IP Lite City / ASN 2026-10） | 45s |
| `/api/public/home` | **首屏聚合**：一次返回 `alerts` + `geo` + `honeypot` + `ipDisclosure`（实测 23–27 KB，随 24h 数据增长） | 45s |
| `/api/public/stories`、`/story?src=` | 单源候选池与点击后懒加载的事件时间线 | 15s |

**脱敏铁律**：攻击者 IP 分段掩码；蜜罐凭据只保留结构与频次；自由文本统一过滤（含同类泄漏回归测试）；访客 IP 与内网地址零泄漏；取不到 / 确实没有 / 未接入 三种措辞分开，**绝不补样例值**。

**缓存口径（当晚实测）**：`/api/public/<name>.js` 是内容相同的可缓存别名（响应带 `stale-while-revalidate=90`），CF 侧实测出现过 `EXPIRED` / `MISS`，说明它确实进了缓存；而 `home`、`alerts` 等 JSON 端点仍是 `cf-cache-status: DYNAMIC`，每次都要回源 srv1 再跨境回到浏览器 —— 这就是 §9 第 4 条那 3–4 秒的来源。

## 4. 处置与封禁链路

1. 规则判定（Wazuh 告警 / 阈值）给出建议处置；
2. 高危动作需人工审批（模型只解释不拍板）；
3. 落地真实防火墙规则（可解封，`unblockMode=REAL`）；
4. 全过程写审计留痕，前端只读展示，误处置有拦截机制。

## 5. 公开面防护

- 统一数据出口闸门（唯一出口：`/api/public/*`，全部只读）；
- 访客限流 6 次/分钟/IP，超限 429 + `Retry-After`；
- 站主令牌（`X-User-Token`）走同一套登录校验后放行，不降低安全边界；
- 提示词注入护栏（`PromptInjectionGuard`），不可信内容统一包裹；
- 问答契约：**只解释、不取证**；检索不到依据直接拒答。
