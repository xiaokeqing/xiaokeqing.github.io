## 2. 对外只读 API（后端 = 唯一数据出口）

| 端点 | 内容 | 缓存 |
|---|---|---|
| `/api/public/health` | 运行态与构建指纹（buildSha、wazuhMode） | 30s |
| `/api/public/audit` | 处置审计：封禁总数/生效数/被护栏拦截/执行动作数 + 每条封禁明细 | 45s |
| `/api/public/honeypot` | 蜜罐：总连接、口令结构、登录次数；`commandsAvailable=false`（数据源未接入） | 45s |
| `/api/public/alerts` | 告警流、威胁等级、`stats.byType`、`stats24h.trend` | 45s |
| `/api/public/geo` | 来源国 / 省份 / ASN（DB-IP Lite City / ASN 2026-10） | 45s |
| `/api/public/stories`、`/story?src=` | 单源候选池与点击后懒加载的事件时间线 | 15s |

**脱敏铁律**：攻击者 IP 分段掩码；蜜罐凭据只保留结构与频次；自由文本统一过滤（含同类泄漏回归测试）；访客 IP 与内网地址零泄漏；取不到 / 确实没有 / 未接入 三种措辞分开，**绝不补样例值**。

## 4. 处置与封禁链路

1. 规则判定（Wazuh 告警 / 阈值）给出建议处置；
2. 高危动作需人工审批（模型只解释不拍板）；
3. 落地真实防火墙规则（可解封，`unblockMode=REAL`）；
4. 全过程写审计留痕，前端只读展示，误处置有拦截机制。

## 5. 公开面防护

- 统一数据出口闸门（唯一出口：`/api/public/*`，全部只读）；
- 访客限流 6 次/分钟/IP，超限 429 + `Retry-After`；
- 站主令牌（`X-User-Token`）走同一套登录校验后放行，不降低安全边界；
- 提示词注入护栏（`PromptInjectionGuard`），不可信内容统一包裹；
- 问答契约：**只解释、不取证**；检索不到依据直接拒答。

## 6. AI 问答与角色表现

- 检索：BM25 稀疏 + 稠密向量 → RRF 融合 → 轻量重排（`VectorSearchService` + `InternalDocsTools`）；
- 答案附引用来源；自动化评测集（`RedTeamEvalService`）验证拒答与防幻觉；
- 语音：本地克隆角色音色，台词库与原声双源；开屏 7 句介绍（rev6）已上线，按「介绍三块功能」口径撰写；
- 角色表现：80 组透明 VP9+alpha WebM（9.1 MB）+ 概率状态机驱动眨眼/视线/口型，低端设备降级。

## 7. 工程与发布链

- Hugo 静态站 + 自研生成器（`_dev/gen-demo-pages.py`）生成演示外壳；
- **39 条构建断言**（`scripts/assert-build.sh`：资产断言、首屏预算、内容哈希、页面结构等），不过不许发布；
- 发布：`scripts/publish-site-to-srv2.ps1` 生成 `site-<时间戳>` 版本目录 → sha256 校验 → 原子切换 → 失败可三档回滚；
- 每版记 `release-info.json`（commit、tree、文件数、字节数、index sha256）；
- Windows 侧协作：AI 助手 + 补丁脚本（可重放、自带断言），改生成器一律用 Python 读写文件。

## 9. 已知缺口与风险（不遮掩）

1. **靶场未对外开放**：Pikachu 已在内网 `labnet` 跑通（禁出网、独立 IP、口令门禁服务已写好），但 DNS 未加、nginx 门禁未生效，**当前不可访问**；简历不应写「在线靶场」。
2. **语音在线 TTS 未接**：固定场景录音（rev6）已上线；问答实时语音需要 Fish Audio 的 key，当前未启用。
3. **旧语音未清**：bank 内仍有 rev5 及更早的 155 条历史音轨，未清理（功能无影响，体积偏大）。
4. **`/projects/` 404**：内容目录已被删除，本地 public 残留是旧的；简历未链接，可暂缓。
5. **旧博客死胡同**：`xiaokeqing.github.io` 目前是 2.4 KB 的「本站已迁移」提示页，应改成自动跳转。
6. **国内访问 GitHub 慢**：仓库公开可访问，但 github.com 网页在国内不稳定，简历建议放个人主页而非深链。
7. **Cloudflare 往返 ~3.5s**：国内访问 API 有明显延迟，首屏数字会晚 3-5 秒出现（已有「取数中…」占位）。

## 10. 给评审者的建议检查点

1. 打开 `/alerts/`，看英雄数字是否在 5 秒内出现真实值（不是「未取到」）；
2. 点任一条 TOP 来源，看是否拉出该源的事件时间线（IP 应为打码状态）；
3. 在 `/ai/` 提一个「给我某个 IP 的登录凭据」类问题，确认**拒答**而不是编造；
4. 连续提问超过 6 次/分钟，确认 429 + `Retry-After`；
5. 检查 `/api/public/honeypot` 的 `commandsAvailable=false` 是否被前端如实展示为「未接入」。
