```
 ├─ Cowrie/ Dionaea  蜜罐（SSH / MSSQL）
 ├─ nginx          静态站点（Hugo 产物）+ /reports/ 巡检报告
 └─ 7 台靶场容器    pikachu / DVWA / Juice Shop / WebGoat / DVNA / DSVW / WebWolf
   │  只监听 127.0.0.1，公网零入口，SSH 隧道访问
   ▼  （告警经 Wazuh API / 只读接口）
srv1（阿里云，47.96.106.187）
 ├─ Spring Boot secagent（单 JVM，公开只读 API + 快照缓存）
 ├─ ACR 私有镜像仓库（发布物）
 └─ 定时任务：CVE 每日抓取、密码字典每日重建、日报
   ▲
   │ Cloudflare（Cache Rules：API 45s、静态 30d、HTML 不缓存）
访客 ──┘
```

关键设计：**前后端彻底分离**。前端是 Hugo 生成的纯静态页（零第三方脚本、零框架运行时），所有数据通过公开只读 API 以 JSON 取；API 侧对每个端点做快照缓存，前端在失败时按"读不到（原因）—— 不补数"的纪律降级，任何数字都不会被编造。

## 6. 技术难点（面试展开用，每条都有"现象→定位→解决"）

### 6.1 发布链"原子切换 + 内容寻址校验"

- 现象：`scp` 全量覆盖会在传输中断时留下半个站点。
- 做法：发送端在干净 `git worktree` 里构建 → 断言通过 → 打 tar → 传 srv2 → 远端解到 `releases/site-<时间戳>/` → **原子切 symlink** → 复算整树哈希与清单比对 → 失败自动回滚上一版。
- 结果：发布 20+ 次，零次出现"半站点"；每次发布写出 `release-info.json`（commit / files / totalBytes / treeSha256 / history）供 `/status/` 页面展示。

### 6.2 一次"明明成功却报失败"的假失败（SIGPIPE）

- 现象：发布链偶发 `[X] tar 包里没有 index.html`，重试又成功。
- 定位：接收端 `printf '%s\n' "$MEMBERS" | grep -qE 'index\.html$'`，`grep -q` 一命中就退出 → `printf` 收到 SIGPIPE(141) → `set -o pipefail` 把 141 当成整条管道失败 → 明明有 index.html 也 `die`。成员越多越容易撞（2,531 个文件）。
- 解决：改用纯 bash 字符串匹配，不再走管道。

### 6.3 首屏聚合与"降级不能让整页黑屏"

- 现象：首屏要打 5 个端点，任一慢就整页"取数中"。
- 做法：后端 `/api/public/home.js` 一次返回五块（alerts/geo/honeypot/audit/health），每块独立 try/catch——**单块失败只降级该块，绝不让整次请求 500**；前端对 home 聚合做失败重试（3 s、8 s 两次退避）而不是退回 5 个请求（慢链路上更慢）。
- 结果：首屏请求数 5 → 1；首屏在 1.8 s 内出数（改造前 3.4 s）。

### 6.4 "改了 CSS 却没生效"——生成器与产物分叉

- 现象：改 partial 无效，刷新还是旧样式。
- 定位：`docs/demo-内容页外壳.html` 是源头，`layouts/partials/xk-demo/shell-style.html` 是生成物，`_dev/gen-demo-pages.py` 每次重跑会覆盖；另有 Hugo minify 会**重命名 IIFE 内标识符**（用 `grep 函数名` 验证前端逻辑会得到假阴性，必须靠 DOM 行为或标记变量验证）。
- 收获：把"改哪个文件才生效"写进 RUNBOOK，并给生成器加断言（外壳 `<script>` 必须恰好 2 处）。

### 6.5 部署"看起来成功"——镜像标签错位与 5 分钟定时器回滚

- 现象：部署脚本报成功，但线上功能没变。
- 定位：运行时容器指向 ACR 的 `:stable`，本地构建的 `secagent:local` 根本没被使用；更隐蔽的是 srv1 上有 `secagent-redeploy.timer` 每 5 分钟比对 ACR digest，发现不一致就把容器换回旧镜像——手工 `docker compose up` 的改动 5 分钟内被"自动回滚"。
- 解决：走官方链路（构建带 `org.opencontainers.image.revision` label 的镜像 → 推 ACR → `srv1-redeploy.sh --expect-commit <sha>`），并把"容器镜像 ID 必须等于 `secagent:local`"做成硬校验（不等则 `exit 7`）。

### 6.6 换图集后首页白屏——元数据没跟着改

- 现象：换高清图集后首页人物全透明，控制台无报错。
- 定位：`manifest.json` 里 `atlas.hi` 的 `w/h/bytes/decodedBytes` 还是旧尺寸，播放器按旧宽高裁帧，裁出来全空。
- 解决：图集与 `frameWidth/frameHeight`、`atlas.*` 元数据必须同一批更新；把这条写进 RUNBOOK（"只换文件不改元数据 = 白屏且无报错"）。

## 9. 面试可能追问的 10 个问题（附答案要点）

1. **为什么前端不用 React？** 站点内容以长文档 + 少量动态块为主，Hugo 静态化能拿到首字节最快、零运行时；动态部分用原生 JS + 事件委托，主包 60 KB 以内。
2. **首屏怎么保证不白屏？** 三件事：HTML 里预渲染骨架、localStorage 上次数据先画（30 分钟内的才用，标注"上次数据·时间"）、home 聚合失败退避重试两次并明示"链路很慢"。
3. **API 快照缓存 45 s 会不会看到旧数据？** 会，所以页面显示"数据时刻"与"边缘缓存龄"；SWR 300 s 只影响后台刷新窗口，不改变服务端 45 s 快照 TTL。
4. **怎么保证"数字不编造"？** 后端每个字段要么有值要么显式 `available:false + reason`；前端三态文案（取数中 / 读不到（原因）/ 空态），不补 0、不补样例；聚合里任何一块失败只降级该块。
5. **限流怎么做？** 按 IP + 全局双桶，`/tts/say` 30/天/IP、全局 300/天，`/password` 30/分钟/IP；命中缓存不吃额度。
6. **检测规则怎么验证有效？** 离线 `suricata -T -S` + 一次性容器全量 `-T`；上线后看 `eve.json`/`fast.log` 实际命中，并用受控测试流量覆盖单条规则，逐 SID 记录命中次数与证据行。
7. **为什么 94.86% 是噪音还不直接关掉？** 那是自家云主机的健康上报，关掉等于盲区；正确做法是加抑制规则（默认注释、opt-in）并把噪音做成页面指标。
8. **发布失败怎么回滚？** `releases/` 保留最近 4 个版本，切 symlink 即回滚；发布脚本 `--rollback` 一键回上一版；每次发布写 `release-info.json` 供核对。
9. **你怎么发现"部署成功但没生效"的？** 部署后强制核对指纹：`buildSha` / `embeddedGitCommit` / `artifactMd5` 三项与目标 commit 比对，不一致就以非零退出（fail-closed），并把"容器镜像 ID 必须等于本地构建 ID"做成硬校验。
10. **一个人维护两台机器最怕什么？** 配置漂移与"看不见的定时任务"。所以：所有变更脚本化（`.ps1`/`.sh` 入库）、关键目录有 RUNBOOK、每 15 分钟 CI 校验站点与版本一致性、改动前先备份并记录 md5。

## 10. 术语表（避免简历里用错）

- **快照缓存 / SWR**：`max-age` 内直接返回缓存，过期后 `stale-while-revalidate` 期间先给旧值再后台刷新。
- **SSR 契约**：每个页面必须有 `data-xk-ssr="<值>"` 标记，构建时逐页校验，防止页面"能打开但没有外壳"。
- **断言（assert-build）**：发布前 85 项自动检查（体积、外链、指纹、禁词、页面登记等），任一失败拒绝发布。
- **原子切换**：新版本先解压到独立目录，校验通过后再切 symlink，避免"半个站点"。
- **fail-closed**：核对不通过就中止，不用"看起来成功"代替成功。
- **蜜罐**：Cowrie（SSH 假服务，记录尝试的账号口令与命令）、Dionaea（MSSQL 等）。
