## 3. 第三轮自查：我自己落地的脚本出过 3 个 bug（都已修）

> 把这段留在报告里，是因为它本身就是"**新方案加入项目后必须复核**"的实证。

| # | Bug | 表现 | 修法 | 状态 |
|---|---|---|---|---|
| A | `print()` 里三元表达式括号位置错 | ⑤ 输出格式串参数错位，多出一个裸参数 | 重写 ⑤ 段，拆成独立变量 | ✅ 已修 |
| B | `keypath.lower()` | `AttributeError: 'tuple' object has no attribute 'lower'` | 改为 `'/'.join(keypath).lower()` | ✅ 已修 |
| C | **键名白名单太窄** | `video-manifest.json` 里键名 `video` 不在白名单 ⇒ 76 个文件只识别 38 条，**漏检率 50%** | 改为"**路径形状优先 + 长度/空格过滤**" | ✅ 已修 |

**Bug C 值得单独说**：它是"**以为在量 A、其实量到 B**"的又一个实例——
我的检查脚本自己就踩了详版 §⑩-6(c) 警告的同一个坑。修正后引用数从 **295 → 358**，
其中 `video-manifest` 从 38 → 76（正确值）。
⇒ **教训**：任何"引用完整性"工具都必须先验证**它是否真的抓到了全部引用**，
否则会给出"看起来干净"的假绿。⇒ 建议 S2 增加一条**自校验**：随机挑一个已知存在的文件，
断言它被识别为"已引用"（正向对照），否则工具本身报错。

### 三个"还能再深一层"的方向（如果站主还愿意继续）

1. **把 D4 从纪律变成机器判分**：目前只有 40 题里 19 条应拒答的人工用例。
   可以做成**每次发布自动跑的数据溯源回归**：断言"页面上出现的每个数字都能追溯到某个端点的某个字段"，
   追溯不到即 FAIL。⇒ 这会让"数据是真的"成为**可自动验证的属性**，而不是口号。
2. **把状态机从"配置"变成"可测试对象"**：38 节点 / 92 边目前只有静态字段。
   可以加一个**不变式检查**：每个节点至少有一条入边、每条 `prob=0` 的边必须有宿主入口对应、
   从 root 出发的马尔可夫链的平稳分布是否覆盖所有 loop 节点。⇒ 接线前就能发现"永远演不到"的节点。
3. **把评测从"跑过"变成"可复现交付物"**：S9 的 bundle + 盲听静态页，
   可以让第三方在不接触任何素材的前提下验证核心指标。⇒ 对"非商业 + 授权敏感"的项目尤其重要。
