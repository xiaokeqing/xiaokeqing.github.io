## 1. 项目是什么

站主是安全工程师方向，把云主机与蜜罐上**真实收到的公网攻击**做成一个"面试官 30 秒内能自行验证"的入口：打开站点就能看到攻击来源、手法、被投递的样本，每个数字都能点回原始告警。

- **谁用**：面试官与同行（30 秒判断真假）、站主本人（战情面板与写作素材）。
- **完成度（2026-11-08）**：198 页、12 个快照端点每 10 分钟自动刷新、903 个后端测试、90 项发布断言、只读 SSE、RAG 问答、带护栏的真实封禁链（dry-run → 审计 → ipset）。
- **口径**：拿不到就写「未取到 + 原因」，绝不补 0、绝不把 mock 当真实。

> 一句话定位（README 原话）：**"把真实公网攻击数据做成面试官 30 秒内能自己验证的第一入口。"**

### 4.3 最容易改错的三处（会直接把发布卡死）

**① 两份同构代码必须同改。**
`layouts/index.html` 里内联了一份首页外壳脚本，`assets/js/xk-scene.js` 是它的"外链版"同构实现。只改一边 → 首页行为与内页不一致，断言 ⑫（`charCanvas` / `opening` / `aspect-ratio:284/600` 等）只查产物，**查不出两边不一致**，线上表现是"刷新后偶发两套动画打架"。同族还有 `layouts/room/list.html`（130,591 B）与 `assets/js/xk-scene.js` 的 CRT 尺寸变量 `--crt-w/--crt-h`。

**② 新 JS 必须放 `assets/js/` 并走 Pipes。**
```go-html-template
{{ (resources.Get "js/xk-foo.js" | minify | fingerprint).RelPermalink }}
```
放在 `static/js/` 会被断言 ⑭ 判死：产物里每个 `/js/*.js` 引用都必须是 `*.min.<64 位 hex>.js`，只有 7 个白名单例外（`xk-saver.js`、`xk-realtime.js`、`xk-app.js`、`phone-emote.js`、`kurisu-player.js`、`xk-rail.js`、`xk-sse.js`——它们手写直出、无指纹）。新增直出文件 = 改断言 + 想清楚 30 天缓存怎么办。

**③ `static/api/public` 会被 `.gitignore` 的 `public/` 吃掉。**
`.gitignore` 里 `public/` 没有前导 `/`，会同时匹配 `static/api/public/`。必须保留：
```gitignore
!static/api/public/
!static/api/public/**
```
否则快照文件不进仓库、Vercel 上没有、页面取数全 404；而且 `git status` 看起来"干净"，极难发现。必要时 `git add -f static/api/public/`。

## 5. 三条数据流

### ① 采集（真实攻击 → 归一化）

```
srv2 香港                           srv1 杭州
├ Suricata（全流量）──eve.json──┐
├ dionaea（445/1433/3306）─────┤ 每分钟 gzip 增量（字节偏移，flock）
├ cowrie（SSH/Telnet 2222）────┤        │
└ 靶场 7 台（故意暴露）────────┘        ▼
                                  Wazuh manager/indexer（7 天索引）
                                        │  （Wazuh agent 收 auth.log/access.log/docker 日志）
                                        ▼
                                  SecAgent :9900
                                  归一化 → 聚合 → 12 份快照 JSON
```

- Suricata 全事件（alert/flow/http/dns/tls）由 `SuricataService` 按**字节偏移**增量读，文件变小就回起点；跨机同步单独记 `/var/log/suricata/.eve.remote_offset`（不记就会"时间戳停在一天前"）。每类事件环形缓冲 5 万条（`BoundedRingBuffer`）。
- 蜜罐：dionaea 落 `dionaea.json`，bistreams 限 120 MB / 7 天；cowrie 落 JSON 日志。
- 保留：Wazuh 索引 7 天（`wazuh-retention.timer` 05:30）。
- 数字口径：任何聚合数都保留"源告警可点回"的 id；取不到时后端返回 `available:false + reason`，前端显示「未取到」而不是 0。

### ② 展示（12 端点 → 快照 → 页面）

```
SecAgent 12 个端点
   │  GitHub Action snapshot.yml（每 10 分钟，curl -m 20，只认 { 或 [ 开头的 JSON）
   ▼
static/api/public/{home,alerts,alerts5,geo,metrics,stories,webstats,password,kb,deploy,eval}.js
static/api/public/daily/index.json
   │  git commit（无变化不提交）→ push main
   ▼
Vercel 重建（hugo --gc --minify --cleanDestinationDir）
   │
   ▼
页面同源 fetch：/api/public/home.js
   ├ 默认：命中构建期快照（0 网络成本，Vercel 边缘 0.26–0.47 s）
   └ ?live=1：回源 https://demo.xiaokeqing.cn/api/public/...（跨境隧道，~600 B/s，仅调试用）
```

关键机制：`layouts/partials/xk-demo/head-meta.html:29` 的 `<meta name="wb-api">` 默认指向 `https://demo.xiaokeqing.cn`，第 35–39 行**清空前把原值抄进 `<html data-wb-api>`**——这样"读同源快照"与"问答/SSE 真回源"两套地址共存。`/alerts/` 每 40 秒轮询一次（`assets/js/xk-bind.js:16` 的 `var REFRESH = 40000;`，`setInterval(load, REFRESH)` 在 2568 行），所以 TTL 必须 > 40 s（现为 45 s）。

### ③ RAG 问答（`POST /api/public/ask`）

```
问题 → 限流（20 次/分/IP）→ 输入清洗/长度限制
     → 检索：稠密（text-embedding-v4, 1024 维）+ 稀疏（BM25，中文双字 bigram）
             → RRF 融合（k=60，免疫量纲差）→ 轻量重排 → topK=3
     → LLM：DashScope qwen-plus（流式关闭，超时短，失败降级）
     → 引用装配（每条答案带 citations：标题/来源/时间）
     → 输出守卫（IP 掩码、拒绝话术、state 标注：ok / degraded / refused）
```

- 检索质量实测：两路+RRF+重排 28/28=100%，MRR 0.9821（RUNBOOK §25.3）。
- 拿不到 LLM 或 Milvus 时返回 `state:"degraded"` + 原因，**不编答案**。
- 匿名面没有 WebSocket；唯一的服务端推送是 `GET /api/public/stream`（只读 SSE，≤200 连接，心跳 15 s，满员 503 + `Retry-After`）。

## 8. 怎么发布

### 8.1 前端链 A：GitHub → Vercel（主链）

```
本地 hugo --gc --minify --cleanDestinationDir + 断言 90/0
        → git push main
        → Vercel 读 vercel.json 构建（HUGO_VERSION=0.167.0，TZ Asia/Shanghai）
        → 边缘部署（sin1）
```

**失败判据**（按出现顺序查）：
1. Vercel 构建日志报 Hugo 错误（模板语法、`resources.Get` 找不到文件、Pipes 管道写错）；产物过大时先看是不是又往 `static/` 里塞了未压缩资产（预算见断言 ⑨：`kurisu`+`crt` ≤256 MiB）；
2. 线上 404 / 白屏 / 样式丢失 → 多半是 Pipes 指纹路径或 `baseURL` 写错；
3. 缓存头不对 → 查 `vercel.json` headers 是否被后续改动覆盖；
4. 断言在本地红过但你硬发了 → **Vercel 不跑 assert-build.sh**，它只跑构建。Actions 的 `deploy.yml` 才跑断言，而它只发布 `redirect-site/` 跳转页，不等于整站发布。

**回滚**：Vercel Dashboard → Deployments → 选上一个 READY → Promote；或 `git revert <sha>` 再 push（Vercel 会重建）。

### 8.2 前端链 B：srv2 自托管镜像（备用域名/演示）

```powershell
cd F:\7AAA\AI\blog
powershell -ExecutionPolicy Bypass -File scripts\publish-site-to-srv2.ps1
```

六步：找 hugo → 生产构建 → 产物校验 → `tar.gz` → scp 到 srv2 → `srv2-site-receive.sh` 原子切换（失败自动回滚上一版）。srv2 nginx 只听 `127.0.0.1:18080`，只能经 CF 命名隧道访问。

**失败判据**：脚本退出码非 0；srv2 上 `curl -I http://127.0.0.1:18080/` 非 200；切换脚本报"上一版缺失"。
**回滚**：重跑脚本发上一版 tar.gz（releases 目录保留两版）。

### 8.3 后端链：bundle → srv1 构建（唯一允许的部署方式）

```powershell
cd F:\7AAA\AI\SecAgent\sec-agent
$sha = git rev-parse HEAD
git bundle create "$env:TEMP\secagent.bundle" main
scp "$env:TEMP\secagent.bundle" secagent-srv1:/tmp/secagent.bundle
ssh secagent-srv1 "cd /opt/secagent && git fetch /tmp/secagent.bundle main && (git stash || true) && git checkout -f $sha"
powershell -ExecutionPolicy Bypass -File scripts\deploy-remote-build.ps1 -TargetSha $sha
```

srv1 侧要求（fail-closed，任一不满足直接失败，不会"带病发布"）：
- `/opt/secagent` 的 `git HEAD == $sha` 且**工作区干净**（有本地改动先 `git stash`）；
- 构建在服务器上做（本机不装 Docker）；
- 注入 `BUILD_SHA` / `ARTIFACT_MD5` / `SOURCE_SHA`。

> 小坑：`git stash` 在没有可存内容时返回 1，会中断 `&&` 链（`ssh` 里就表现为"明明没改动却部署失败"），所以命令里写 `(git stash || true)`。

**三方核对（必须全对，否则脚本 `exit 7`）**：

| 核对项 | 期望 | 怎么查 |
|---|---|---|
| 源码 SHA | `git rev-parse HEAD` == `BUILD_SHA` == 容器环境变量 `SOURCE_SHA` | `docker exec secagent printenv SOURCE_SHA` |
| jar md5 | 构建产物 md5 == `ARTIFACT_MD5` == 容器内 `/app/app.jar` md5 | `docker exec secagent md5sum /app/app.jar` |
| 容器镜像 | 运行中容器的镜像 ID == `secagent:local` 最新 ID | `docker inspect -f '{{.Image}}' secagent` 与 `docker images --no-trunc secagent:local` |

**健康门槛**：先等 `/api/health` healthy，再核对 SHA；不 healthy 就不算发布成功。

**回滚**：`git checkout -f <上一个 sha>` → 重跑 `deploy-remote-build.ps1 -TargetSha <上一个 sha>`。

**`secagent-redeploy.timer` 为什么停用**：按原设计，srv1 由它每 5 分钟按 ACR 的发布指针/`digest` 拉取并对齐容器（`build-image.yml` 只构建推送、不部署）。问题是手工 `git bundle` 部署的新代码会被它在下一次轮询里**覆盖回旧镜像**——这正是"部署显示成功、线上还是旧行为"的事故源（`2cc026f` 因此加了覆盖检测告警）。现在它停用，部署只能走 `deploy-remote-build.ps1`；`build-image.yml` 何时把 `:stable` 推进到新镜像，由人决定。恢复 timer 前必须把两条链合并成一条。

**镜像仓的额外保证**：`build-image.yml` 对每个镜像做三步 fail-closed（① 工作区干净且 HEAD == 触发 commit；② jar 内 `git.properties` 的 commit 与触发 commit 一致；③ 镜像 label 写死 `revision` 与 `artifact-md5`，供 srv1 读取核对）——因为本项目真实发生过"镜像是新的、代码是旧的"。

## 10. 必须遵守的 8 条约定

| # | 约定 | 违反后的直接后果 | 守它的机制 |
|---|---|---|---|
| 1 | **零第三方资源**：不引外部字体/图标/JS/CSS/CDN | 断言 ⑦ 失败 → 拒绝发布（也是隐私与可用性要求） | `assert-build.sh` ⑦ |
| 2 | **`static/images/bg.jpg` 一个字节都不许改** | SHA256 断言 ⑧ 失败；视觉与对比度体系全变 | SHA256 `4b1e13ee…a55660` |
| 3 | **不造数据**：取不到写「未取到 + 原因」，绝不补 0、绝不把 mock 当真实 | 站点失去唯一价值（可验证性）；README 口径承诺 | 后端 `available:false + reason`；`dataSource.degraded` |
| 4 | **公开面数据只来自 `/api/public/*`**：只读、IP 已掩码，前端不得还原真实 IP | 泄露原始 IP = 事故；也是合规红线 | `PublicIpPolicy` + `scrubText` |
| 5 | **匿名面只读**：无 WebSocket；SSE 只允许单向（≤200 连接、心跳 15 s、无客户端上行）；写操作只有 `/ask`、`/tts`（限流） | 双向通道 = 被当跳板/被打爆 | `PublicStreamService` 200 上限；`PublicRateLimiter` 20/分 |
| 6 | **新 JS 放 `assets/js/` 走 Pipes**（`resources.Get\|minify\|fingerprint`）；`static/js/` 只许 7 个白名单 | 断言 ⑭ 判死；或 30 天缓存导致"改了不生效" | 断言 ⑭ + 白名单 |
| 7 | **两份同构代码必须同改**：`layouts/index.html` ↔ `assets/js/xk-scene.js`（含 `room/list.html` 的 CRT 变量） | 首页与内页行为分叉，断言查不出，只能靠人 | 只在文档与 code review 层面 |
| 8 | **先断言后发布 + 只 `git add` 自己改的文件**（绝不 `git add -A`） | 把别人的半成品/私钥/临时文件带上线 | 流程纪律；`.gitignore` 只是兜底 |

补充环境事实（不算约定但常踩）：远程**必须** `ssh://git@ssh.github.com:443/...`；本机只有 PowerShell 5.1，所有 `.ps1` **必须 UTF-8 with BOM**；`_dev/`、`_shots/` 被 `_*/` 忽略，要进 CI 的脚本放 `scripts/`。
