## 3. 真实运行位置（先找对，再动手）

| 组件 | 形态 | 宿主机路径 | 容器内路径 |
|---|---|---|---|
| Suricata 8.0.7 | 容器 `suricata`（`jasonish/suricata:latest`，`network_mode: host`，抓 `eth0`） | `/opt/suricata/etc/suricata.yaml`、`/opt/suricata/rules/`、`/opt/suricata/logs/` | `/etc/suricata/suricata.yaml`、`/var/lib/suricata/rules`（`default-rule-path`）、`/var/log/suricata` |
| Wazuh manager 4.9.2 | 容器 `wazuh.manager` | `/opt/wazuh/config/wazuh_cluster/rules/`（**只读** bind） | `/var/ossec/etc/rules` |

要点：
- 宿主机上**没有** `/etc/suricata`，也没有 `suricata` 二进制 —— `ps` 里看到的 `/usr/bin/suricata -c /etc/suricata/suricata.yaml` 是容器内进程，别在宿主机上找配置文件。
- `rule-files` 原来只有 `suricata.rules` 一项，**没有 include 机制**，所以新文件必须登记进 yaml。
- `HOME_NET: [10.0.0.10]`、`EXTERNAL_NET: !$HOME_NET`（公网 → 内网 NAT 后在 eth0 上看到的是 `dest_ip=10.0.0.10`）。

## 4. 部署与加载（实际执行的命令）

```bash
# 4.1 放文件
sudo cp /tmp/xk-lab.rules /opt/suricata/rules/xk-lab.rules
sudo chown cfstatic:cfstatic /opt/suricata/rules/xk-lab.rules && sudo chmod 644 /opt/suricata/rules/xk-lab.rules
sudo cp /tmp/xk-lab_rules.xml /opt/wazuh/config/wazuh_cluster/rules/xk-lab_rules.xml
sudo chown root:root /opt/wazuh/config/wazuh_cluster/rules/xk-lab_rules.xml && sudo chmod 644 ...

# 4.2 登记进 rule-files（yaml 先备份）
sudo cp -a /opt/suricata/etc/suricata.yaml /opt/suricata/etc/suricata.yaml.bak-xklab-$(date +%Y%m%d-%H%M%S)
sudo sed -i 's|^  - suricata\.rules$|  - suricata.rules\n  - xk-lab.rules|' /opt/suricata/etc/suricata.yaml
# → 77: rule-files: / 78: - suricata.rules / 79: - xk-lab.rules

# 4.3 reload（只重启这两个服务容器，不重启机器、不碰 nginx/secagent）
sudo docker restart suricata
sudo docker restart wazuh.manager
```

- Suricata 无 `unix-command` socket（yaml 里没配 `unix-command`），因此 `suricatasc -c reload-rules` 不可用；
  又因为本次改的是 `rule-files` 列表本身（不是规则内容），所以走 `docker restart suricata`（被动抓包实例，中断约 10 s）。
- Wazuh 的规则目录是**只读 bind**，只加文件不改路径，`docker restart wazuh.manager` 后 analysisd 自动重新读 `etc/rules/*.xml`。

加载证据（`/opt/suricata/logs/suricata.log`）：

```

```
