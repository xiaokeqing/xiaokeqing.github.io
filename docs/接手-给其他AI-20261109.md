## 0. 三十秒认识这个项目

一个人（非程序员，安全运维岗）用 AI 辅助做的**公网安全观测站**：

- **展示层**：Hugo 静态站（`F:\7AAA\AI\blog`），一半是安全笔记，一半是实时数据看板。
- **数据层**：两台云服务器上的 Wazuh（告警）+ Suricata（流量）+ 两个蜜罐（Cowrie SSH / dionaea 文件）。数据每 30 分钟由 GitHub Action 抓成**静态 JSON 快照**塞进仓库，页面读同源快照，不直连后端。
- **后端**：Spring Boot（`F:\7AAA\AI\SecAgent\sec-agent`），提供 `/api/public/*` 只读端点和 AI 问答。
- **人设层**：一个 CRT 里的 E-mote 角色（牧瀬紅莉栖）跟着页面说话，仅桌面端、且只在网速足够时加载。

**口径高于一切**：站主最讨厌"编数字"。取不到就写「未取到 / 读不到 + 原因」，**绝不补 0、绝不外推**。任何页面上出现的数字都必须能追溯到一个真实端点和时间戳。

## 3. 构建 / 校验 / 发布（三条命令，背下来）

```powershell
cd F:\7AAA\AI\blog
$env:PATH = (($env:PATH -split ';') | ? { $_ -and $_ -notmatch 'WindowsApps' }) -join ';'   # Git Bash 里的 python3 会命中 WindowsApps 假壳
hugo --gc --minify --cleanDestinationDir          # 构建：期望 "Total in ~6 s"，354 个 HTML
bash scripts/assert-build.sh public               # 期望 "断言全部通过 → 允许发布"（94 项）
git add -A; git commit -m "..."; git -c rebase.autoStash=true pull --rebase -q origin main; git push origin main
```

- **push 后 12–60 秒 Vercel 自动部署**，线上即可见（`/css/* /js/*` 一年 immutable、`/images/*` 30 天，所以**换图必须换 URL**：`?v=YYYYMMDDx`）。
- **`git push` 被拒是常态**：仓库有定时快照 Action 每 30 分钟往 main 推提交 ⇒ 永远先 `pull --rebase`。
- **不要用 `hugo server` 验收**：它会把带 `livereload.js` 的产物写进 `public/`，污染断言口径。要看效果就 `hugo --gc --minify --cleanDestinationDir` 之后 `python -m http.server 8211 -d public`。
- 改动涉及页面时，验收口径固定四条：**构建成功 + 94 断言全过 + 1440 与 390 两档 `scrollWidth === innerWidth` + `pageerror 0`**。

## 5. 口径纪律（违反会被站主直接否掉）

1. **取不到就写"未取到"**，写清楚"哪一层没取到"，不许补 0、不许按比例外推。
2. **未映射的单独列一行**，不许摊派到已映射的类别里（例：ATT&CK 页把「无 mitre.id 的 904,950 条」单列）。
3. **两个不同窗口的数不许相加**（5 分钟窗口 vs 24 小时窗口）。
4. **时间戳要标窗口**：「过去 24 小时（Wazuh 窗口）」「索引窗口 5 天，快照为窗口内全量」。
5. **保留期例外**：服务端索引只保留 **5 天**（`wazuh-retention.service`），但 `/session/` 读的是 Cowrie 磁盘日志 ⇒ 仍是 **7 天**，页面上已注明，别"统一"掉。

## 6. 硬约束 / 高频翻车点（改动前先看这条）

| 陷阱 | 具体表现 | 正确做法 |
| --- | --- | --- |
| 两份同构代码 | `assets/js/xk-scene.js` 与 `layouts/index.html` 里的内联副本必须**同改**，只改一处会出现"首页不生效/行为不一致" | 改完两边一起搜关键字确认 |
| 两套外壳 | 文章页走 `baseof.html`，数据页走 `head-meta.html`；改 head 只改一处＝一半页面没变 | 先判断目标页走哪套（grep 该页 `</head>` 里的 marker） |
| 新 JS 放哪 | 放 `static/js/` 会被断言判死（无指纹、不可缓存） | 放 `assets/js/`，Hugo 里 `resources.Get | minify | fingerprint` |
| 样式真值位置 | 导航几何在 `xk-idcard.css`，正文栏宽在 `posts/single.html`，`tokens.css` 里的令牌**未必被引用** | 改前先 `grep` 真实类名，加 `getBoundingClientRect` 量 |
| `wb-api` 顺序 | `xk-boot.js` 必须在 `<meta name="wb-api">` **之后**、正文脚本之前执行，否则数据页会去连隧道 | 位置写死在 `head-meta.html` 第 29 行之后 |
| 图片缓存 | `/images/*` 30 天、`/js/*` 一年 immutable | 换图/换 JS 一定改 URL（`?v=` 或指纹） |
| PowerShell | 没有 heredoc；多行脚本一律写 `.py` 再跑；`Set-Content` 会加 BOM（远端 bash 会报 `#!/usr/bin/env: No such file`） | `[IO.File]::WriteAllText(p, s, UTF8Encoding($false))` |
| nginx（srv2） | `nginx -s reload` 会带走 master；`nginx -t` 报 pid 文件错不代表配置坏；`/etc/nginx/conf.d/` **未被 include** | 一律 `systemctl restart nginx`，server 块改 `nginx.conf` |
| 头像卡 | `assets/js/xk-idcard.js:64` 硬依赖 `#xkIdAv #xkIdAvCanvas #xkIdCap #xkIdPanel #xkSndBtn #xkLoginBtn` | 动顶栏结构前先确认这 6 个 id 还在 |
| 一次性脚本 | 我踩过：把 `_fix_after.py` 提交进仓库 | 临时脚本放 `E:\DeepSeek1\work\`，不要进仓库 |
