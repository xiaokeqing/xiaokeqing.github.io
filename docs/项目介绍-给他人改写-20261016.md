## ① 一句话定位 + 三段式简介

### 1.1 一句话定位（可直接当 title 用）

```
一个个人技术站点 xiaokeqing.cn：把「真实攻击数据」变成可由数字角色表达的问答与叙事，
贡献点在管线、评测、边界设计与工程化，不在基础模型与美术（《说明书》§8①）。
```

### 1.2 三段式（是什么 / 给谁用 / 解决什么问题，各 2~3 行）

**是什么**：一个**个人**技术博客站点（`xiaokeqing.cn`）+ 架在上面的**安全数字人**实验。
站点是 Hugo 静态站 + 原生 HTML/CSS/JS（**无前端框架**，《总览》§②末），
五类页面：主页 `/`、监测中心 `/alerts/`、笔记 `/posts/`、AI 问答 `/ai/`、测试模块页 `/test/`，
另有文章页 / 分类页 / 404（走 Hugo 常规模板）。它同时有**两重身份**（见 ②）：
A = 两台云服务器上**真实在跑**的蜜罐与检测栈；B = 把 A 产生的真实数据 → RAG 问答 / LLM 决策 → 由数字角色表达（《总文档》§①）。

**给谁用**：**主观众是站主本人**（站主口径修正原话："主要观众就是站长本人"，《任务清单》「规划原则修正」）；
对外用途 = **个人博客 + 面试 / 简历展示**（《总文档》§2.2）。**明确非商业** ——
角色素材授权是"非商业技术学习 / 研究 / 演示"，**商用需另议**（《说明书》§3.3）。
因此站点上没有账户体系、没有广告、没有收费，也没有任何运营指标可讲 ✗。

**解决什么问题**：把"两台服务器上真实发生的攻击"变成**人能看懂、且能逐条核验**的东西 ——
真实只读接口 → 聚合与脱敏 → 上屏；再让数字角色用**日语语音 + 逐帧动画 + 口型**把结论"说"出来（《总文档》§①）。
它刻意解决的问题是**可信度**：数字只来自真实只读接口，**取不到就写"读不到"** ✗，
并把这条口径做成了**可自动判分的评测用例**（40 题里 19 条应拒答，《说明书》§4.2、§5-5）。

### 4.2 角色渲染②·透明 VP9+alpha 视频替换精灵图集（本项目的招牌工程结果）

- **做了什么**：把 40 段角色动作从"PNG 图集逐帧贴图"换成"**透明 WebM（VP9 + alpha）逐帧 seek**"。
- **技术选择**：`<video>` 离屏（**不进 DOM**）、`muted`、`playsinline`，逐帧 `seek` 后 `drawImage` 到 canvas；
  视频第 i 帧 == 图集第 i 帧（单帧时长取 `statemachine` 的 `frameIntervalMs`，**不是容器 duration**）。
- **为什么这样选**：图集是**全帧整幅**位图，动作越长体积越爆；视频有帧间压缩，且浏览器原生解码 ⇐ 不用 WebCodecs；
  AV1+alpha 被实测否掉（见下）；两枚 `<video>` 交替方案被否掉（同剪辑两枚各自 seek 会**帧序打架**，改用"poster 顶位 + 解好的帧搬进离屏 canvas"）。
- **量化结果**：
  - 体积：40 组 `webm 8,763,277 B + poster 779,892 B = 9,543,169 B`，替代图集 `71,061,412 B`
    ⇒ **名义 7.45×**（《总账》§2.3、`[本文实测]` 逐文件实算 = 9,543,169 B ✓）。
  - ⚠️ **公平口径 = 5.42×**（**改写方请用这个做主口径**）：分子 40 组含图外的 `sad`/`smile`，
    分母 71,061,412 B = medium（38 剪辑 50,492,702 B）+ hi（**只覆盖 6 个剪辑** 20,568,710 B），**集合与质量档都不同**。
    同集合同档重算：分子 `9,543,169 − 227,280 = 9,315,889 B` ÷ 分母 `50,492,702 B` = **5.42×**（`R1`§X2，227,280 B = sad/smile 的 webm+poster）。
  - 画质自检 **40/40**：alpha MAE 均值 0.1889（最大 0.2511）｜RGB PSNR 均值 37.09 dB（最低 35.85）｜边缘 NCC 均值 0.9965｜帧数 7672/7672（《总账》§2.3）。
  - 分辨率 268×360（原 medium 134×180 的 2 倍边长 / 4 倍像素），统一 `pad=764:1028:100:0:black` 回画幅（同上）。
  - **路线证伪**：AV1+alpha 在 Chromium 的透明解出率 **0.0%** ⇒ 只能 VP9；B3 双拼 mp4（yuv444/420）alpha MAE 0.69~1.05，比 VP9 路线差 3.7~5.6×（同上）。

### 4.3 角色渲染③·按需解码 / 显存与内存策略 / 低端设备自动降级

### 4.5 角色渲染⑤·说话口型包络

- **做了什么**：每句语音配一份 10ms 窗的响度序列，驱动嘴部开合。
- **技术选择**：`mouthValue = clamp(RMS(10 ms 窗) × 3.75, 0, 1)`；首窗保底 0.12；**停止时发 0**；包络**从最终编码文件解码重算**。
- **为什么这样选**：口型必须与**实际播出的音频**对齐，而不是与母带对齐；且这套公式是既有 12 句的既定口径，不许另起一套。
- **量化结果**：包络与线上 12 句**逐点 100% 一致**（阈值 0.08 不写进包络）（《总账》§2.4）；

  Python 3.13 移除该模块，届时需换实现并重对齐（《说明书》§5-9）。
  ⚠️ **证据强度**：口型同步**未被证明严格同步** —— 素材侧只有 `r ≈ 0.51 @ lag 70~100 ms` 与 MAE 64.591 两个数，

### 4.11 语音工程③·真峰闭环（**本项目最有技术含量的一处"自我纠错"**）

- **做了什么**：对**最终分发文件**（不是母带、不是 meta 栏位）实测真峰与响度，并把闭环写回脚本。
- **技术选择**：三步闭环全部对最终文件闭合 ——
  ② 先在**母带**归一到 −16 LUFS → ③ 首尾 40ms fade →
  **③b 只在真峰超（目标 −1.0 dB 余量）时限幅**（已贴满刻度的信号必须先有 headroom 才压得动）→
  **④b 编码后量最终 m4a 真峰**，超了回头补降增益重编码（≤4 轮）→ **④c 编码后量最终 m4a 响度**，按实测偏移补一次（不得抬高真峰）。
- **为什么这样选**：根因两条（都实测到了）—— `alimiter` 压的是**采样峰**，对已贴满 0 dBFS 的素材**是空操作**（阈值越紧真峰反而可能升高）；
  且旧口径的 `m4a.lufs` 是 **fade 之前**测的 ⇒ **"母带合规"≠"上线文件合规"**。这条认知是本轮真缺陷的根因。

## ⑥ 亮点（7 条；每条按「问题 → 做法 → 结果」）

1. **用透明视频替掉精灵图集**
   · 问题：40 段动作的 PNG 图集共 71,061,412 B，首屏与移动端都吃不消。
   · 做法：VP9 + alpha 的透明 WebM，逐帧 seek 后在 canvas 上合成；`<video>` 不进 DOM；失败自动回图集。
   · 结果：**9,543,169 B 替 71,061,412 B**（名义 7.45×，**公平口径 5.42×**），分辨率反而升到 268×360；40/40 自检通过（alpha MAE 0.1889 / PSNR 37.09 dB / NCC 0.9965）。

2. **"母带合规 ≠ 上线文件合规"的真峰闭环**
   · 问题：响度环只把 **采样峰** 当安全网、且响度在 **fade 之前** 测 ⇒ 最终分发的 m4a 真峰超标（最差 **−0.37 dBTP**）。
   · 做法：改成对**最终交付文件**闭合的四步（先归 −16 LUFS → fade → 只超限才限幅 → 编码后量真峰并回补 → 再量响度按偏移补一次）。
   · 结果：**原声 484/484、合成 150/150 全部 ≤ −1.5 dBTP**；`--selftest` 响度极差 0.06 LU；**线上 12 句一个字节没改** ✓。

3. **发布"假成功"防线**
   · 问题：接收脚本原先"只比 `index.html`"⇒ 纯资源发布被判无变化，`exit 0` 但线上一个字节没换 ✗。
   · 做法：幂等判据改成**整树内容哈希**；发布按精确 ref；`KEEP=4`；备三档回滚（秒级 / ~5 秒 / ~2 分钟）。
   · 结果：修掉了假成功（提交 `f47c678`）；但**发布脚本侧仍留旧 `index.html` 口径**（如实标为"只修了一半"，`R1`§N3）。

4. **把"零造假"做成可自动判分的用例**
   · 问题："不编数字"如果只是口号，评审无法验证。
   · 做法：40 条问答质量集里 **19 条应拒答**，`must_not_contain` 里放**真实快照数字**（编出来即判幻觉）；`state=input-insufficient` / `rule-based` 都算正确拒答态。
   · 结果：拒答正确率 **4/4**、幻觉命中 **0**、提示注入护栏 **1/1** —— 且**样本量（有效 4 / 40）与"受 30 次/日额度限制"一起写** ✓（《说明书》§4.2）。

5. **诚实降级：读不到就写"读不到"，未接线就写 `NOT_WIRED`**
   · 问题：演示类项目最常见的失真来源是"取不到数就兜底造一个"。
   · 做法：前端不许兜底造假；`/test/` 页 9 块里 8 块直接挂 `NOT_WIRED` 徽章并写清接上时的落点；`未接入（NOT_WIRED）` 与 `这一段确实没有数据` **分开措辞** ✗。
   · 结果：主页残留假数字 `1,284` 已改成占位 `—`（提交 `6b35e89`）；空态纪律进 `/test/` 与 `alerts` 的验收项。

6. **6GB 笔记本上跑通端侧 TTS（成本 ¥0）**
   · 问题：没有云 GPU 预算，且中文路线要 1.2 GB BERT（峰值 2647 MiB）跑不动。
   · 做法：走 `--lang 日文`（不需要 BERT）+ SDPA + CUDA Graph / static-KV。
   · 结果：RTF ≈ 0.98、峰值 2070.5 MiB、显存余约 1.8 GB；本地成本 **¥0**，云端兜底 ¥0.0065/句。

7. **给"会过期的数字"建了机制**
   · 问题：审查方实测"**同一个仓库在 25 分钟内被发布了 3 次**"，任何写死的"当前值"落笔即过期。
   · 做法：新增 `_dev/snapshot-facts.py`，一键产出带 UTC 时间戳的 `docs/facts/<UTC>.json` + `latest.json`（release / 页面字节 / 端点数 / health 关键字段）。
   · 结果：`latest.json` 有可复跑的时间戳与 `source` 字段；本文因此**不复述"当前 release/字节"**，只给取数命令（⑩）。

## ⑦ 难点与踩坑（6 条**真实事故**：根因 → 修法 → 验证数字）

> 全部是"已发生并有证据"的真事故，不是假想难点。这 6 条**很适合改写成"工程严谨性"的素材**，
> 但**必须保留"曾经错过"的部分** ✗（去掉就变成吹牛）。

### 7.1 发布"假成功"：幂等只比 `index.html`

- **现象**：一次纯资源发布（`static/js/kurisu-player.js` + 新增 `static/kurisu/eye/`）被判"无变化"⇒ 删掉暂存、**exit 0**，**线上一个字节没换**。
- **根因**：接收脚本的幂等判据只看 `index.html`；首页没变 ⇒ 整批资源被当成没变。
- **修法**：改成**整树内容哈希**（`srv2-site-receive.sh` L171 `tree_hash()` / L175 注释），提交 `f47c678`。
- **验证数字**：源码注释里留了这次事故的原话（`srv2-site-receive.sh` L168）；⚠️ 发布侧脚本仍算 `index.html` sha256 ⇒ **只修了一半**（`R1`§N3）。

### 7.2 最终分发文件真峰超标：只保采样峰 + 响度在 fade 前测

- **现象**：对**最终 m4a** 实测发现真峰 > −1.5 dBTP，**最差 −0.37 dBTP**（原声 18 条 + 合成 8 条）。
- **根因**（两条，都实测到）：① `alimiter` 压的是采样峰，对**已贴满 0 dBFS** 的素材是空操作 ⇒ 阈值越紧真峰反而可能升高；② meta 里的 `m4a.lufs` 是 **fade 之前** 测的，不能当验收数字。
- **修法**：v3 方案 —— **从 raw 母带一次重建**（先线性归一到 −16 LUFS → **在母带上限幅** → 64k AAC → **量最终 m4a，不足再降 0.8 dB**）；并把闭环写回 `postprocess.py`（提交 `4b5bb6c`）。
  ⚠️ 失败的两版也如实记：v1（对 dist 反复收紧 alimiter）20 条里只修好 15 条、1 条反而更差；v2（提 AAC 码率 + 增加轮次）仍剩 4 条不合规。
- **验证数字**：**484/484 与 150/150 全部 ≤ −1.5 dBTP**（max −1.50）；抽样复测 合成极差 0.53 LU / 真峰 −1.69，原声 0.32 LU / −1.81；`--selftest` 极差 0.06 LU、真峰 −1.85（《台词库》§5.5、`状态S`）。

### 7.3 宿主情绪名**静默演错表情**：清单里没有该键 ⇒ 兜底成笑脸且不报错

- **现象**：宿主传 `sided_surprised` 一类情绪名时，前端找不到键，**静默**落到兜底（默认笑脸），**不报错、不打日志**。
- **根因**：前端适配表与后端/清单的键不一致；决策白名单只认 manifest 的 8 类，`calm` / `shy` 属非法值。
- **修法**：后端 `mapEmotionToAction()`（`sided_surprised → surprise_trans`）+ 8 类白名单校验（非法即回退并记 `rejectReason`）+ **构建期断言**（`AnalystVerdictTest` 的非法情绪用例）；
  ⚠️ **前端侧适配表不在本批**（属站点批）⇒ **前端不补键就仍会静默落错剪辑**（《后端重建》§1 裁决③、§11-③）。
- **验证数字**：`mvn` 新增 17 条全绿（605 run / 0 fail）；`decision=whitelist{actions=38,hostEntries=9,emotions=8,lines=12,md5=99850845}` 自检可读（《后端重建》§4/§5.2）。

### 7.4 眼皮补丁文件名不符契约 ⇒ **数字全绿但屏幕上不可见**

- **现象**：眨眼功能的各项指标全部通过，但屏幕上**看不到眨眼**。
- **根因**：补丁 json 文件名不符契约 —— 播放器唯一调用点是 `loadEye('idle1')`（请求 `/kurisu/eye/idle1.json`），而落地的文件名不是它 ⇒ **404 静默失败**。
- **修法**：改名对齐契约（`static/kurisu/eye/idle1.json`）。
- **验证数字**：**同帧像素 A/B 强差异 0 → 2575**（这就是"之前根本没生效"的硬证据）（`通宵`§二4；`动画第二批实施件` L36-38 记了契约本身）。

### 7.5 状态机 4 条新边被**静默丢弃**：守卫比错键

- **现象**：动画二批新增 4 条边，重跑生成器后边数**退回 88**，且没有报错。
- **根因**：生成器补丁里的守卫**比错了键** —— 拿"边端点名"去比"节点 id"（本项目 `节点 id ≠ 剪辑名`，缺 `from_id/to_id` 无法跳转）。
- **修法**：改比 `clip`，并对非法端点直接 `raise SystemExit`（把静默变成硬失败）。
- **验证数字**：**92 边、幂等**（重跑生成器不再回退）（`通宵`§二2；`[本文实测]` 复核 `edge_count=92`、`len(edges)=92` ✓）。

### 7.6 手机端 `/ai/` 导航跑到屏外：布局视口被撑到 620px

- **现象**：手机上底部导航"看不到也点不到"；375/390/414 三视口都复现。
- **根因**：`.ai-grid` 是 `grid-template-columns:1fr 292px`，`1fr` 列受子内容 min-content 约束**不能收缩** ⇒ 网格最小宽 ≈608px ⇒ 窄屏下**布局视口被撑到 620px**；
  而 `#dock{position:fixed;bottom:10px}` 相对**布局视口**定位 ⇒ used top = 1343−47−10 = **1286**，落在 812 高的**视觉视口之外**。
- **修法**：`.ai-grid{grid-template-columns:1fr}` + `.ai-grid>*{min-width:0}`；窄屏另修面板遮挡（`holo` 限高 + 给正文 76px 顶带）与触控区 `min-height:44px`。
- **验证数字**：溢出 **245/230/206 → 0**；三视口×四页 `dockInView true` / `navMinTouch 45` / console 0；release `site-20261016-003417`（提交 `590e6cc`）（`通宵`§四①；旧口径见《总文档》§8.1 H1）。
