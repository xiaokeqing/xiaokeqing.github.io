## SecAgent · AI 安全运营助手

**一句话**：把「告警 → 研判 → 处置」这条安全运营链路，做成一个可编排、可审计、有护栏的 AI 助手。

### 解决什么问题

企业安全运营中心每天产生几千到几万条告警，其中九成以上是误报和重复，真正的攻击被淹没在噪声里。分析师要在告警系统、日志平台、知识库、资产表之间来回切换才能下判断；判断完还要手工封 IP、锁账号——慢、容易出错，而且**处置过程没有留痕，事后无法复盘**。

新人上手要几个月，老手的经验留在脑子里带不走。

### 我做了什么

| 能力 | 具体实现 |
|---|---|
| **降噪** | 同一源 IP + 时间窗 + 同类告警自动聚合成一条，带 ×N 徽标，可下钻原始明细 |
| **多 Agent 研判** | 编排层 + 调度员，派发给研判员（查知识库 RAG）、取证员（拉告警与日志）、处置员（执行动作）三个专职智能体，汇总输出「结论 + 证据 + 处置结果」 |
| **分级处置 + 护栏** | 自动封禁；高危动作强制人工审批；白名单拦截内网/环回地址；全部动作写审计 |
| **知识库问答** | 33 篇安全知识文档向量化，支持带出处引用与相似度阈值拒答 |
| **红队评测** | 19 例用例（攻击 11 + 正常流量 8），同时输出绕过率与**误报率**两个独立维度 |

### 一个关键的设计取舍

> **处置动作的护栏写在代码里，不写在提示词里。**

因为提示词可以被精心构造的输入绕过，而代码层的白名单绕不过去。这条取舍说明我清楚大模型的能力边界——**知道该在哪里踩刹车**。

### 技术栈

Spring Boot 3.2 · Spring AI / Spring AI Alibaba · RAG · 多 Agent 编排 · Tool Calling · SSE 流式输出 · 自研向量存储抽象（内存 / Milvus 可切换）· Docker

## 这个站点本身

**一句话**：用 Hugo + PaperMod 构建的纯静态技术站，托管在 GitHub Pages。

**它值得单列的原因**：这不是套个模板就完事——为了让它符合一个安全从业者该有的样子，做了这些取舍：

| 决策 | 原因 |
|---|---|
| 纯静态，不要 CMS 和数据库 | 没有数据库就没有 SQL 注入，没有后台就没有弱口令 |
| 零第三方脚本 | 每个外部脚本都是把访问者的浏览器控制权分一份给别人 |
| 页面内不加统计/字体/客服 | 同上，只留必要的评论组件 |
| 源码与构建产物分离 | `main` 放源码，`gh-pages` 放产物，发布可复现 |
