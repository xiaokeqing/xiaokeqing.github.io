## 为什么做这个

安全的东西光看文章记不住。**自己动手试一次，胜过读十篇原理。**

但公网上放真实漏洞应用（比如 DVWA）是不负责任的——会被人当跳板，会牵连服务器，而且**一个懂安全的人本来就不该这么干**。

所以这里的演示全部是**在浏览器里模拟原理**：你输入，立刻看到后台"实际发生了什么"，以及为什么这么防。

> **重要说明**：这些演示跑在你自己的浏览器里，**没有任何真实漏洞**。
> 输入的 payload 只被当作字符串分析，不会被执行、不会发到服务器（唯一例外是标了「调用后端」的那一项）。

## 计划中的演示

| 演示 | 你做什么 | 你会看到什么 | 状态 |
|---|---|---|---|
| **SQL 注入** | 输入 `admin' OR '1'='1` | 拼出的完整 SQL 语句 + 为什么条件恒真 + 参数化查询怎么防住 | 🚧 |
| **XSS** | 输入 `<script>alert(1)</script>` | 转义前后的字符串对比（**只显示，不执行**） | 🚧 |
| **路径穿越** | 输入 `../../etc/passwd` | 规范化后的路径 + 是否越出允许目录 | 🚧 |
| **命令注入** | 输入 `; whoami` | 拼接后的命令长什么样 | 🚧 |
| **DLP 敏感信息扫描** | 粘贴一段含假密钥的文本 | 命中哪条规则、为什么判定为敏感 | 🚧 |
| **试着攻击我** ⭐ | 对真实运行的防护组件发起尝试 | 拦截结果 + 命中规则（**这一项会调用后端**） | 🚧 |

## 每个演示都会讲清三件事

1. **漏洞长什么样** —— 用你最熟悉的场景（登录框、文件下载、ping 工具）
2. **后台实际发生了什么** —— 把拼接后的 SQL / 规范化后的路径 / 最终执行的命令**原样展示出来**，这是理解原理的关键
3. **怎么防** —— 一键切到「已修复版本」，看同一个 payload 为什么失效

## 和真实靶场的区别

| | 公网真实漏洞靶场 | 本站的模拟演示 |
|---|---|---|
| 法律风险 | 可能被当跳板，有责任 | **零** |
| 能否被扫描滥用 | 会 | **不会** |
| 打开门槛 | 要自己找漏洞 | **打开就能玩** |
| 能不能讲清原理 | 不一定 | **专门讲这个** |
| 维护成本 | 要一直盯着 | **不用管** |

想练真实的渗透，建议去 **HTB / VulnHub / 自建本地靶机**——那是另一套东西，不该放在公网上。
