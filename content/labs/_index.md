安全的东西光看文章记不住。**自己动手试一次，胜过读十篇原理。**

但公网上放真实漏洞应用（DVWA 那种）是不负责任的 —— 会被人当跳板，会牵连服务器。**一个懂安全的人本来就不该这么干。**

前面四个演示**全部跑在你自己的浏览器里**：你输入，它把"后台那一刻到底发生了什么"原样摆出来给你看。
第五个（试着攻击我）不一样 —— 它会真的发请求到后端，由系统里真实运行的防护组件来判定。

> **⚠️ 关于安全，说清楚四件事**
>
> 1. **前四个演示没有任何真实漏洞。** 逻辑是纯 JavaScript 字符串处理，不连数据库、不执行命令、不读文件。
> 2. **你输入的东西不会被执行。** 哪怕输入 `<script>alert(1)</script>`，也只会被当成文字显示出来 —— 页面全程用 `textContent` 输出，从不拼 HTML。
> 3. **前四个演示不发任何网络请求。** 输入不离开你的浏览器。
> 4. **第五个会发请求，但接口是只读的。** 它只对字符串做检测、返回命中哪条规则，**不写库、不改状态、不执行任何处置动作**。处置类接口仍然要求管理员角色 + 人工审批，是另一条完全分开的路。

## 每个演示都在讲同一件事

**漏洞的本质，是"数据和代码"的边界被打破了。**

| 演示 | 你输入的东西本来应该是 | 实际却变成了 |
|---|---|---|
| SQL 注入 | 一个普通的字符串值 | SQL 语法的一部分 |
| 路径穿越 | 一个文件名 | 一条可以回退目录的路径 |
| 命令注入 | 一个 IP 参数 | shell 命令的一部分 |
| 敏感信息扫描 | —— | 反过来：找出本该被藏起来的数据 |
| **试着攻击我** | —— | **反过来：看真实防护组件认不认得出这是攻击** |

前四个演示都按同一个套路展示：

```
① 有漏洞的写法  →  ② 系统实际收到的东西（高亮出问题的那段）
                    →  ③ 判定结论  →  ④ 修复后的写法为什么能挡住
```

**第 ② 步是最关键的一步。** 大多数教程只告诉你"这样写有漏洞"，但不把中间那个"系统到底看到了什么"摊开给你看 —— 而那恰恰是理解原理的钥匙。

## 想试真的？

前四个是**模拟**，目的是讲清原理。第五个页签 **「试着攻击我」** 不一样 —— 它把 payload 发到后端，由 SecAgent 里**真实运行的三个防护组件**来判定：

```
PromptInjectionGuard     提示词注入检测
SensitiveContentScanner  敏感信息扫描（DLP）
PathSecurityUtil         路径穿越检测（文件上传）
```

**而且它会告诉你「哪个组件适用于这次输入」。** 这一点比拦截结果本身更值得看：

- 拿一段普通文本去做**文件名**校验，必然因字符白名单被拒 —— 那是**假阳性**，不是防护能力
- 反过来，拿一个文件名去查**提示词注入**，也永远查不出东西 —— 那是**假阴性**

所以每一项都标了是否适用，判定只统计适用的项。**防护组件必须明确自己的输入边界** —— 拿错了对象，要么误报一片，要么形同虚设。

## 和真实靶场的区别

| | 公网真实漏洞靶场 | 这里的模拟演示 |
|---|---|---|
| 法律风险 | 可能被当跳板，有责任 | **零** |
| 能否被扫描滥用 | 会 | **不会** |
| 打开门槛 | 要自己找漏洞、配环境 | **打开就能玩** |
| 能不能讲清原理 | 不一定 | **专门讲这个** |
| 维护成本 | 要一直盯着打补丁 | **不用管** |

想练真实的渗透，去 **HTB / VulnHub / 自建本地靶机** —— 那是另一套东西，不该放在公网上。
