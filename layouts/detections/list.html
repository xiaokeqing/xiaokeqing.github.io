口径 · 规则怎么来的先数流量，再写规则
  • 先统计真实流量，再决定写什么：7 天 eve.json 共 1,471,376 行 （2026-10-11 09:23 ~ 10-18 12:00 UTC），其中 alert 293,482 / flow 612,516 / http 283,796 / ssh 142,926 / dns 132,086 / tls 6,801。
  • 每条规则钉住证据：规则文件里每条规则上方都写着「为什么写 / 依据的观测计数 / 预期误报」， 证据是原始日志里的行；本页只取其中可公开的元数据。
  • 没有证据就不写：132,086 条 DNS 事件里没有观测到可归因的 C2 域名， 所以这个仓库没有「DGA / 僵尸网络回连」规则 —— 不拿看起来像监控的规则凑数。
口径 · 怎么验证的语法验证 + 离线回放 + 改前改后
  • Suricata 语法验证：一次性容器跑 suricata -T -S（jasonish/suricata 8.0.7， --network none、--rm），输出 Configuration provided was successfully loaded，exit 0；另有 3 条 SYN-only 方向提示（W:）， 与预期一致。
  • Wazuh 语法验证：一次性容器跑 wazuh-analysisd -t（wazuh-manager:4.9.2）， exit 0；并与「删掉规则文件再跑一次」的对照结果一致。
  • 离线 pcap 回放：1000103 做过阈值边界回放（suricata -r）：120 次 SYN / 600 秒 → 恰好 1 条； 119 次 → 0 条；按旧阈值 10 次 / 300 秒 → 0 条。
  • 改前 / 改后实测：1000103 调阈值、100110 把聚合口径改成同源、threshold.conf 加 suppress，README 里都留了改前与改后的计数。
口径 · 没做的 / 未接入取不到就写「未接入」，不补 0
  • 未接入 CI：上面的 -T / -t 都是手工跑的一次性容器命令， 仓库的流水线（部署 / 每日留存 / 快照）没有把规则语法验证做成构建门禁。
  • 未做长期回归：README 记录的是单次验证与调参记录，不是持续跑分的命中率曲线。
  • 本页不读线上实例：数据是构建期从仓库文件算出来的快照（data/detections.json）， 页面不发任何请求，刷新不会变。
  • 未展示：匹配内容原文、真实来源地址、口令、主机名、内网地址一律不进页面；规则描述里的 $(src_ip) 一类是 Wazuh 字段占位符，不是真实值。
口径 · 计数与出处数字对不上时，以文件为准
  • Suricata {{ $sa }} 条 = 规则文件里 alert 动作行；另有 1 条抑制型 pass 规则 （sid 1000108）默认注释，不计入。
  • Wazuh {{ $wt }} 条 = <rule id= 元素数（cowrie 6 + xk-lab 3）， sid 区间 {{ int $ws.sid_min }}–{{ int $ws.sid_max }}。
