AI 安全 · 研判状态口径

AI 研判链路每一步都会落一个机读的 state 标记。页面上的措辞按下面这张表来， 不允许含糊、也不允许把"没生成"写成"研判为安全"。

数据源未接入。 当前公开只读端点（/api/public/overview、/api/public/alerts）不返回 state 字段 —— 所以本页只放权威措辞与映射逻辑，不放任何"示例研判结果"。 等端点带上该字段后，告警流每一行会自动多出一枚状态标记（前端映射代码已就位： static/js/workbench.js 里的 WB_STATE 与 stateOf()）。

状态取值 → 页面措辞（权威口径）

state 取值页面措辞说明
model 模型研判 —
input-insufficient 依据不足，不做定性 —
no-retrieval 未检索到依据，不给结论 —
retrieval-failed 检索不可用，未生成 —
model-failed 模型不可用，未生成 —
rule-based 规则解析 模型不参与处置拍板

六行措辞为权威口径，前端只做映射与配色，不改写、不美化；未在上表内的取值一律显示原始 state 字符串 + "未识别状态"，绝不猜它的含义。

这套措辞为什么重要

"模型不可用"和"研判为安全"是两件完全不同的事，但在很多看板上都会被渲染成一片安静。 上面每个降级态都写死成未生成 / 不给结论，就是为了让"没算出结果"永远不会被读成"没有攻击"。 rule-based 单独标出"模型不参与处置拍板"，是因为那条路径的封禁决定来自规则，不是模型。
