XK-LAB // 公开端点清单 PUBLIC-API ● 全部只读 · 除 ask / tts 两处外都是 GET

这张表是给想自己敲命令的人看的：每个端点做什么、返回什么、有什么已知缺陷。 基址是 https://demo.xiaokeqing.cn，下面第三块那三条 curl 复制就能跑。

端点一览 · 做什么 / 返回什么 / 坑在哪17 个 · 只读
端点方法用途关键字段已知坑（先看这列）
/api/health GET 进程活着 + 线上跑的是哪个版本 buildSha embeddedGitCommit vectorStore documentVectors uptimeMs status 唯一端出构建指纹的端点。它和 deploy.release 对不上，说明前端与进程不是同一次发布；不脱敏，但不含业务数据。
/api/public/home GET 首屏聚合：alerts + geo + honeypot 三合一 alerts.generatedAt alerts.cacheSeconds snapshotAt cacheAgeSeconds 响应头是 max-age=45, stale-while-revalidate=90。快 ≠ 新：真实年龄 = cacheAgeSeconds + 响应头 Age，命中边缘缓存时耗时会接近 0ms。
/api/public/overview GET 指标总览（stats24h / 六态 / 额度） stats24h dataSource.wazuhMode degraded 看 wazuhMode：只有 REAL 才是真的 Wazuh 在供数，降级会显式写出来 —— 别把降级数据当实时。
/api/public/alerts GET 告警聚合（窗口内告警 + 来源 + severity） 窗口计数、来源、severity、stats24h 返回的是聚合，不是逐条原始日志；geo.coverage.totalAlerts 是窗口内未去重总量。
/api/public/alerts/{aggId} GET 单条告警详情 该 aggId 那一条的完整结构 路径里是聚合 id，不是 IP；想「按 IP 查告警」这个端点做不到，不存在的 id 直接 404。
/api/public/geo GET 来源地理聚合（国家/省/ASN + 24h 趋势） coverage.totalAlerts withSourceIp geocoded countryCount 必须连 coverage 一起看：只有带源 IP 的才进地理统计，不许把子集画成「全量攻击」；离线库只到国家/省，不定位到人。
/api/public/latest GET 窗口聚合（只给一个窗口的量） windowSize windowAlertCount 窗口大小会变，别拿它和 geo.coverage.totalAlerts 直接比 —— 两个数可能不是同一个窗口。
/api/public/honeypot GET 蜜罐战报（连接 / 登录 / 来源 Top / 口令结构 / 时间线） connections logins total sampled total 恒为 10000，那是统计上限哨兵，不是真实累计 —— 真实计数看 connections（其次 logins）。口令只给结构，不给原文。
/api/public/audit GET 处置审计（护栏拦截 / 封禁留痕 / 理由） summary.blockedByGuard summary.blockTotal 两个数都是累计，不是本周/本日；blockTotal 是留痕条数去重后的地址数。
/api/public/stories GET 攻击故事线候选池 sources[] 四段计数 alerts decoyPorts honeypotLogins auditActions，首末时间、最高严重度、gaps auditActions 多轮实测全是 0 —— 不是「没有处置动作」，是这一段还没接上数据；/api/public/stories/1 是 404，它没有子资源。
/api/public/story?src= GET 单源事件时间线（点了才拉，页面不预取） events[]（升序、每段 ≤40 条、truncated 如实标注） 缺 src → 400 MISSING_SRC；src 要填候选池返回的真实来源，别拿 IP 段瞎猜。脱敏要连 events[].summary 里的内嵌 IP 一起盖。
/api/public/webstats GET Web 访问统计（访问量 / 来源） 访问量、来源分类 一个 IP 都不给，连打码都不给；也还没有 statusCode 与 7 天日桶字段 ⇒ 面板上那两块如实写「读不到」。
/api/public/deploy GET 构建与发布信息（可追溯） build{} runtime{} release{release, totalBytes, source} 嵌套结构，不是平铺的；没有 files / history 两个键 —— 别按它们写代码。当前线上常见 available:false + RELEASE_INFO_NOT_CONFIGURED。
/api/public/eval GET 评测报告（AI 质量那几格） sampleSize keyPointHitRate refusalRate strictRate citationRate personaCatchphraseRate tabooRate generatedAt + note/caveats 比率必须连 sampleSize 一起读：96 份和 4 份不是一个可信度。当前线上常见 available:false + EVAL_REPORT_NOT_CONFIGURED。
/api/public/kb?q= GET 知识库只读检索 results[]{title, snippet, sourceType, trustLevel, score, publicRule}、hitCount available note 20 次/分钟，且每次都有 embedding 成本 ⇒ 禁止轮询。白名单口径：根目录 security-docs / data/kb-approved、来源类型 community、黑名单含 internal、top-k=3、摘要 300 字 —— 检索不到是真没有，不是坏了。
/api/public/ask POST 公开问答（检索 + 引用 + 六态标注） state（六态机读值）、引用、ttsTextHash 限流压在 6 次/分钟/IP + 公开池 30 次/日 + 同 IP 并发 1；429 和「读不到」是两件事，别混着写。它只解释，不做任何处置动作。
/api/public/tts POST 在线语音合成代理（转发字节流） 关闭态：503 + TTS_DISABLED 默认关闭（等语音 Key）。就算开了也只收白名单 phraseId / textHash，塞自由文本 → 400 TEXT_NOT_ALLOWED。

「字段」一列只写已经在线下核对过的键，不是照抄设计稿；标了「当前 available:false」的字面意思是：端点通、数据那份文件还没配好， 这是如实报告，不是接口坏了。

同一份数据的 .js 别名边缘可缓存 · 不吃 20 次/分钟

上面每个 /api/public/* 都有同名的 .js 别名（/api/public/alerts.js 这样）。它存在的理由是缓存： 边缘节点按扩展名决定缓存，无扩展名的路径必然回源（实测 0.94~2.60s），.js 能命中边缘缓存，而命中缓存的请求不到源站，也就不吃公开面每 IP 20 次/分钟的限流。 所以静态页大量取数时一律走别名。

两条纪律：① 别给这些地址加随机 cache-buster（?cb= / ?t= / Date.now()）—— 那样每次都是新 URL，100% 回源； ② ?q= / ?src= 这类语义参数是允许的（它换来的是不同内容）。

至于响应体长什么样，两种记录并存：一份 2026-10-16 的缓存契约写「响应仍是 application/json，照常 JSON.parse，别当脚本执行」， 另一处写它是 window.X = … 的脚本形式、可直接 <script src> 引入。本页不替你赌这一条，一条命令就能看出来：

# 开头是 { 就当 JSON 用；开头是 window. 就当脚本用（以响应头的 content-type 为准）
curl -s https://demo.xiaokeqing.cn/api/public/home.js | head -c 60
怎么最快验证一个端点三条 curl · 只读 · 不写入
# ① 活着吗、线上跑的是哪个版本（表格第 1 行）
curl -s https://demo.xiaokeqing.cn/api/health | head -c 300

# ② 蜜罐：total 恒为 10000 是上限哨兵，真值看 connections（表格第 8 行）
curl -s https://demo.xiaokeqing.cn/api/public/honeypot.js | head -c 400

# ③ 限流长什么样：连打 3 次 kb（20 次/分钟按 IP 算，打满后就是 429）
for i in 1 2 3; do curl -s -o /dev/null -w '%{http_code} ' "https://demo.xiaokeqing.cn/api/public/kb?q=rate-limit"; done; echo

# Windows PowerShell 等价写法（本页就是在这台机器上写的）：
#  Invoke-WebRequest -UseBasicParsing https://demo.xiaokeqing.cn/api/health | % Content
#  curl.exe -s -o NUL -w "%{http_code} " "https://demo.xiaokeqing.cn/api/public/kb?q=probe"

三条都只读，不写库、不改状态、不触发任何处置动作。取不到的时候（断网、429、源站挂了）就是取不到 —— 这一页不打算替换成任何「样例值」，/status/ 那页才是「现在通不通」的实测表。

口径与边界公开面只读

① 只读。全站公开端点没有任何写操作；处置动作在受保护的自用面，要管理员令牌 + 人工审批。
② 地址打码。页面上看到的来源地址统一是 1.2.3.x；但 curl 拿到的可能是接口原文， 显示层掩码与接口原文不一致属于预期，原文只留在 srv1 日志里。
③ 失败说失败。取不到就写「未取到 / 读不到」并带原因（available:false + reason），不补 0、不补样例值。
④ 不常驻。没有 SSE / WebSocket，一次性返回；要新数据就再敲一次。
