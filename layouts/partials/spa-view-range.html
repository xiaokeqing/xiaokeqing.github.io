下面每一条都是一键样本：点一下，这段输入会被送进真实运行的检测链路 （提示词注入防护 + 敏感信息扫描 + 路径穿越净化），返回每个检测项的判定、依据与动作。 只做检测，不执行、不处置。

一键跑：

为什么公开面只检测、不取证

公开面（你现在用的这一面）

  • 只解释概念与防御：问"我们昨天被谁打了"这类需要内部事件数据的问题， 回答会明确写"公开面只基于公开知识库回答，不读取内部事件数据"，并且不检索、不调模型 （不花公开额度去猜）。
  • 编排层不派发取证任务：公开身份拿不到内部日志工具， 工具层还会二次拒绝（不靠模型自觉），返回 public-identity-no-internal-data。
  • 引用一律直出正文：没生成结论时也把命中的标题 / 片段 / 可信度 / 来源性质摆出来， 不让访客只看到一句"依据不足"。

为什么这样切（取舍）

  • "不执行处置"和"不泄露内部事件数据"是两件事：收紧前，匿名问一句"昨天被谁打了" 会走取证路径，把内部资产名、内部接口路径带回公开回答；处置确实没执行，但数据已经出去了。
  • 代价是公开面看起来"更笨"：一些本来能答的问题现在会明确拒答。 这是刻意的 —— 匿名身份能读取内部事件数据这件事，本身就不该存在。
  • 定级也一并收紧：公开面的模型结论一律不做事件定级（严重度强制 INFO， 建议栏是"防护建议"）—— 这是收紧，不是放宽。

这里故意没做什么

删掉的

  • 公网部署 dvwa / pikachu 一类真实漏洞应用 —— 会被当跳板，也会牵连服务器。

  • 真正打到 POST /api/playground/check 的互动，判定结果由服务端返回， 前端只负责展示。
  • 接口自带的"未命中不等于无害"说明会原样、常显展示（含 SQL 注入 / XSS / 命令注入 本来就不属于输入扫描职责的原因）。
